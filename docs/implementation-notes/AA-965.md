# AA-965 — CRM-33b AI: supplier confirmations, notes to options, voice profiles

S281 lane l10-crm-ai (Claude Code). Design: root `docs/audits/2026-10-21-S246-crm-design-v3/design-v3.md` §6.3 card
CRM-33b (R10, R40, R41), data-privacy-integrations §2.9 group H (`ai_draft`, `voice_profile`), ux-design A-03 / A-04 /
A-18. Linear scope updated S279 (root ADR 0019 b6). Builds on CRM-33a (AA-964, AA-1027 F3).

## Decisions

- **One gateway, three new uses.** Every call goes through `app.llm.gateway.LlmGateway.call` like the reply draft: the
  stage profile and kill switch, the CRM app profile, the per-agency rate cap, the agency budget (fail closed at 100 %:
  the CRM budget is always a hard stop, there is no soft mode to switch), `ai_enabled`, the F3 scrub with the trip's
  known values, the route, the `crm.llm_call` ledger row, the placeholder map. The lane brief speaks of the "CIS AI
  gateway with pii_class us": in this repo that is the CRM's own gateway (root ADR 0008a §5-6: CRM keeps its own
  control plane and ledger); the F3 scrub is what makes a call personal-data free before it leaves, so no `pii_class`
  field exists here.
- **New stages** `crm_supplier_confirm` (R10) and `crm_notes_options` (R40), role `writer`, seeded by crm-069 as a copy
  of the `crm_draft_reply` profile and route at apply time, so they follow the route control in force (today Amazon
  Nova Lite on acc2, crm-042) and their calls show in the CIS Calls tab like the draft's. R41 adds no stage: a voice changes the
  draft's fixed system block only.
- **Output token caps per stage are settings** read by the gateway (not the call site, lessons: "the token cap is held
  by the gateway"): `crm.ai.supplier_confirm_max_tokens`, `crm.ai.notes_options_max_tokens`; the draft keeps
  `crm.ai.draft_reply_max_tokens`.

- **R10 scope**: an own supplier of category flight / insurance / visa / transport (transfers) / other (fees) only,
  never the AA row (403) nor accommodation / activity / guide / restaurant / dmc (422): b6 says ground services are AA's.
  The source is the supplier's inbound e-mail **body** on the trip's supplier request thread (crm-053) or pasted text.
  The closed list is that supplier's planning / requested agency lines (codes L1..Ln); the model never sees a line id.
- **R10 apply**: a run writes only the draft. The agent's confirmed values (they may edit the reference) go through the
  existing `lines.confirm` / `requests.back_to_planning` in one transaction; then the draft is accepted. A plain
  "accept" of a supplier confirmation draft is refused (`draft_needs_apply`) so "accepted" always means "applied".
  Dates and times the model read are shown, not written (a line's dates are edited on the line itself).
- **R40 closed list**: the components of the products Booking sells **this agency** (`ProductCache.products`, the same
  cache the AA add form uses) whose tour is `served` in the catalogue cache and in the trip's countries
  (`crm.trip.destinations` -> ISO via `app.duty.service.DESTINATION_COUNTRY`; none known = every country). "The day's
  list" is built per run for the day asked; the AA tour's own day number is shown as a hint, not a filter (a proposal
  day and a tour day are different numbers). Codes A1..An; anything else, a repeat or a pick over the setting is dropped.
- **R40 is a preview**: no option is written; "Add" uses the builder's normal AA add (live Booking quote = the server
  re-check the design asks for).
- **R41**: voices are per member (design: "at most 4 per member") but every member of the agency may use any voice
  (the lane brief: "the agency's writing tone"). Descriptors are fixed codes; the draft adds our own sentences, so a
  voice cannot inject text. `ai_draft.voice_profile_id` has no foreign key (like `llm_call_id`): deleting a voice keeps
  the draft's history and avoids touching the crm-010 cascade test of `ai_draft`.
- **Migrations**: crm-069 (contract: new table, ALTERs of `crm.ai_draft`, stage config rows) is the migration-only PR;
  crm-070 (contract: eight settings rows) ships in the code PR, the same deviation as crm-068 (lane l5): the settings
  lint (an enforced key must be read by code), the guide lint and the seed-parity test bind the seed, the readers and
  `compiled_defaults.json`; the code runs before the apply on the compiled defaults.

## Changed

- Lane brief "through the CIS AI gateway with pii_class us": the CRM has its own gateway (root ADR 0008a); the F3 scrub
  plays the role of the PII class. The brief's "max pages" limit is `..._max_chars` instead: there is no PDF text
  reader in this repo (no parser dependency), so PDFs and images are not read at all; the agent pastes the text.
  Follow-up if wanted: a PDF text extractor (a new dependency) behind the same no-image rule.
- "Budget hard_stop default true": the CRM budget is always a hard stop at 100 % (CRM-33a); no soft mode was added
  (it would be a new policy that lets AA's spend run past the agency budget). Stated in the PR body.
- `crm.ai_draft.prompt_scrubbed` (design §2.9) is not added: the ledger keeps the prompt hash, the draft keeps the
  output; storing prompts would need the 30-day clear job first.

## Tradeoffs

- Copying the draft stage's route into the new stages at apply time follows today's route control, but a later route
  change of `crm_draft_reply` does not move the new stages: stage routes change by migration only (crm-042 did it for
  the draft), so the next route migration must name all three stages.
- The R40 closed list reads Booking's product list on each run (the 5-minute per-agency cache makes repeated runs
  cheap); Booking down = 503 before any model call.
- The model answers JSON; a malformed answer is "nothing kept" (`no_json`), paid but shown as no proposal rather than
  retried (a retry would double the cost on a bad model day).
