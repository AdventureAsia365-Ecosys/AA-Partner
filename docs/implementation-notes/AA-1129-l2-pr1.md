# AA-1129 lane l2, PR 1: CRM translation and formats (P3), client host (P5), Academy small fixes (A1)

Source: S283 UI audit, `AA-Ecosys/docs/audits/2026-11-17-S283-fe-audit/README.md`, section "Medium, agency app",
rows 5-7, 16, 17, 22, 25 and the low rows of the same pages (plurals, spelling, form language, privacy, quiz context,
lesson sources). Web only, no API change.

## Decisions

- **Kit language in the CRM**: the CRM layout reuses the studio's fixed-language provider (`StudioLang`, imported as
  `AppLang`) rather than a second copy. Same store contract (the httpOnly cookie is resolved per request on the
  server), so kit core text on CRM pages follows `aa_crm_locale` exactly like the CRM dictionary does.
- **Plurals**: the existing `<key>.one` mechanism (`lib/i18nPlurals.ts`, `plural()`); the departures traveller split
  became `{total} ({parts})` with one counted key per traveller type and zero counts left out (`paxSplitText`).
- **Spelling**: one form everywhere, `huỷ` / `xoá` (the catalogue already used it ~130 times); a test fails on the old
  form in any web message file or component (kit core excluded: CIS canonical).
- **Studio activity labels**: worded web-side per action id (`lib/studio/activityLabels.messages.ts`); an action the
  studio does not know keeps the CIS label, so a new CIS action never shows a blank.
- **Inquiry form language**: `?lang=en|vi` links on the form, for this visit only. The client host has no `/prefs`
  route and a cookie written there would need a new route on a public host; a query parameter needs nothing new and
  keeps the "English unless chosen" rule (owner rule S249).
- **Form 404**: `notFound()` with a segment `not-found.tsx` that keeps the old "This form is not available." card,
  so a dead link answers 404 and the visitor still reads the same sentence. An API fault stays a 200 error card.
- **Brand on the client host**: the form uses the agency's name; the client-host 404 and the error card show no mark
  (the agency is not known there). Other client-host pages (`/c/t`, `/c/p`, ...) still show the partner app's mark:
  not opened by the audit, follow-up.
- **Privacy fallback**: shown only when the agency set neither a privacy link nor a data-request contact. The sentence
  says only what the product does (the agency answers the inquiry; the person can ask the agency to see, correct or
  delete the details).
- **Academy**: planned prerequisites are plain text; `not_found` reads on module, lesson and quiz pages answer 404;
  the quiz page reads the module (rules, best score, passed) or the path list (title, certificate held) before Start;
  a source row is named by its section's first Markdown heading, the ref under it, the browser's open marker kept,
  the first source open.

## Changed

- Web only. `app/(crm)/layout.tsx`, `app/layout.tsx` (metadata by host kind), `app/not-found.tsx`,
  `app/c/f/[publicKey]/{page,not-found}.tsx`, `components/CenteredCard.tsx` (`brand={null}`),
  `components/intake/InquiryForm.tsx`, `app/trip/[tourId]/page.tsx` + `lib/tripPage.ts`, the academy pages, the studio
  Activity column, partners / suppliers / marketing / departures counts, `lib/i18n*.ts`.
- Not in this PR (API side or next wave): the proposal text renderer's "adult(s)" (API text), the structured refund
  reason (API), exact start/end dates on the form definition, P4 settings pages, S1 studio billing.

## Tradeoffs

- `?lang=` does not persist across the client host's other pages; a persistent choice needs a client-host prefs route.
- The root layout now computes metadata per request (it already read headers/cookies, so no rendering change).
