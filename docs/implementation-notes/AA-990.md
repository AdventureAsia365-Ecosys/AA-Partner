# AA-990 (D2) — angle requests whose atom was replaced: a clear state in the portal

S252: 14 angle-gate requests (4 tenants) point at atoms a later atomize run replaced. CIS answers the typed 409
`atom_replaced` on write / regenerate (CIS #1013), but the portal only found out after a click. Decision D2 (Nghiệp's
standing approval, S252): no new status and no migration; CIS exposes a computed flag on the tenant's reads and the
portal shows the state and turns Write off. Requests with a unique replacement are re-pointed once by a CIS script
(root runbook), so the flag stays only on requests with no unique replacement.

## Decisions

- **CIS contract (AA-CIS-App, same issue):** `GET /v1/angle-gate/requests/{id}` (and the choose / reopen re-reads),
  `GET /v1/content-writing/reviews` and `GET /v1/content-writing/requests/{id}/review` add
  `atom_replaced: boolean` and `atom_replacement: {atom_id, place, itinerary_day} | null` (the unique matching part
  of the rewritten tour, a hint only). Both optional here: a CIS build without them reads as "not replaced".
- **Writer (`AngleGateWizard.tsx`):** a replaced request shows one notice ("This part of the tour was updated", the
  sentence from `lib/myContent.atomReplacedNote`, a "Go to Social Posts" button) and every action is off: goal cards,
  "Generate 3 angles", "Write with this angle", "Change angle", the CTA form, "Retry", and the automatic write on
  arrival at the Write step (it would only meet the 409). A piece written before the rewrite is still shown.
- **My Content (`lib/myContent.regenerateBlock`):** "Write again" is disabled with the reason
  `ATOM_REPLACED_BLOCK`. Order of reasons: published → being written → closed tour → replaced (a closed tour or a live
  post is the more useful thing to say first).
- **The way out is a new post from Social Posts**, not "Change angle": reopen + choose keep the same atom (CIS #1013
  review, S251).

## Changed

- `portal/lib/myContent.ts`: `ContentRow.atom_replaced`, `AtomReplacement`, `ATOM_REPLACED_BLOCK`,
  `atomReplacedNote`, the `regenerateBlock` rule; tests in `portal/lib/myContent.test.ts` (18 pass, `npm test`).
- `portal/app/portal/_components/reviewListApi.ts`: `ReviewItem.atom_replaced` / `atom_replacement`.
- `portal/app/portal/_components/AngleGateWizard.tsx`: the request fields, `AtomReplacedNotice`, the disabled actions.

## Tradeoffs

- **Computed, not stored:** no status to keep in sync with re-atomize runs; costs one main-pool read per request
  read on the CIS side (the MAIN exception pattern of the job-status read).
- **The hint is informational:** the portal does not offer "use the replacement" — the tenant picks the new part of
  the tour on the Slate, which makes a new request with the right Subject.
