# AA-1131 — Kit accessibility fixes, agency app side (S283 UI audit batch K1)

The kit core fixes (DataTable named page-size select and keyboard rows, Drawer name / focus / trap / return,
PageHeader text basis, PageFrame containing block) are made in the canonical AA-CIS-App `frontend/app/_kit/core` and
reach `web/app/_kit/core` through `tools/kit/kit-sync.sh crm-web` (never edited here by hand). This note covers the
agency app code that goes with them.

## Decisions

- **Studio sidebar Collapse row pinned** (`web/app/_kit/local/studio/PortalSidebar.tsx`, app code): the `<aside>` no
  longer scrolls; the nav does (`flex: 1 1 auto`, `min-height: 0`, a thin dark-surface scrollbar) and the Collapse row
  is `flex: none`, as in the Booking and CIS shells. Below 900 px studio.css hides the Collapse row, so the drawer is
  unchanged there.
- **CRM sidebar unchanged** (`CrmShell.tsx` `CrmSidebar`): it has no footer controls to pin (no Collapse, no staff
  card). Its last item is the Settings nav group, pushed to the bottom with `margin-top: auto`; it is part of the nav
  and scrolls with it when the groups overflow, which is right for a nav group. The staff console and the Academy
  shells have a top nav, no sidebar.
- **PageHeader rules**: the AA-883 copy in `web/app/(studio)/studio.css` is removed; the kit core now ships the rules
  as its own stylesheet (`PAGE_HEADER_CSS`). The CRM's `globals.css` had no copy. Visible change in the studio: a header
  with a description AND actions gives its text a 420 px basis (the actions wrap under a long description instead of
  squeezing it), the same in every app.

## Changed

- `web/app/_kit/local/studio/PortalSidebar.tsx`, `web/app/(studio)/studio.css`, `web/tests/studio/shellA11y.test.ts`
  (source checks).
- Visual job (`e2e/visual/`): the role-name gate (`a11yNames.ts`, a copy of the CIS helper: a kit-rendered control
  with no accessible name fails on every page, any control on the kit gallery; a page's own unnamed controls are
  reported in `unnamed`) and the kit keyboard check (`a11y-keyboard.spec.ts`: the gallery's table rows and drawer from
  the keyboard at 1440 and 390, job `pr` only).
- The kit sync (`web/app/_kit/core/*`, `web/kit.lock.json`) is its own commit, the LAST on the branch. Locally it is
  synced at the CIS branch commit, so the tests and the visual run test the real kit; the lock's ref is that branch
  commit, which the provenance check rejects. Before the push the commit is redone at the merged CIS sha
  (`tools/kit/kit-sync.sh crm-web --dest-repo <worktree>`, default ref = CIS `origin/main`, then `git commit --amend`).
  If the Kit Sync bot's PR (`bot/kit-sync`) merges first, the amended commit carries the same bytes and lock.

## Tradeoffs

- The role-name gate fails only on kit-rendered controls (and every control on the gallery): page-level unnamed
  controls are the per-page audit batches' work, so they are listed, not failed, to keep this PR from turning red on
  pages it does not touch.
