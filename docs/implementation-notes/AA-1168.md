# AA-1168 — EU AI Act Art. 50: AI mark and disclosure on the My Content CSV / XLSX export (AA-Partner)

Lane l8-ai-act-marking, S286, review fix pass. The CIS side of the issue (WordPress, Facebook and text export
disclosure, WordPress post meta) and the root AI Use Register v1.15 ship in their own PRs; a reviewer found the
Content studio export of My Content (`my-catalog.csv` / `my-catalog.xlsx`, CatalogTab "CSV (n)" / "XLSX (n)") was
missed: it writes AI tour text to a file the tenant downloads with no disclosure and no machine-readable mark.

## Decisions

- **Four AI columns per row** from the version's `ai` object, which CIS already adds to every tenant version read
  since AA-1040 (`/v1/tours/my-versions`, `/v1/tours/versions/{id}`; CIS `_tenant_projection.project_version` ->
  `ai_marking.version_mark`): `AI generated`, `AI generator`, `AI generated at`, `AI human edited`, values
  `true` / `false` (empty when not known), the same names as the CIS meta tags in words. The model is not exported:
  `version_mark` sends `model: null` for T2 versions (the writer model stays on the CIS ledger, admin only).
- **`AI generated` is "true" even without a mark**: every exported text is AI-written (the T2 rewrite, else the
  A-series Master `aa_*` text). Without a mark, `AI human edited` falls back to the version's `edit_source`
  (`tenant_edit` = a person's edit), the same rule as CIS `version_mark`.
- **Disclosure** = CIS `ai_marking.DISCLOSURE_TEXT` word for word ("This content was created with the help of AI."),
  one wording on every channel. CSV: the last line of the file (a single cell after the table, like the trailer of the
  CIS text export). XLSX: the last row of sheet "My Tours", plus the document properties keyword `ai-generated` and
  the disclosure as the comment (the T2 DOCX download uses the same keyword in its core properties).
- The row logic moved to `web/lib/studio/catalogExport.ts` (pure, unit-tested). The eleven AA-662 text columns keep
  their order and sources; one small change: when the detail read of a version fails, the text columns fall back to
  the list row's `aa_*` fields too (before, only Name did), so a failed detail read no longer exports empty cells.

## Changed

- `web/lib/studio/catalogExport.ts` (new): headers, widths, `catalogExportRow(s)`, `catalogTsv`, `catalogWorkbook`,
  `flattenVal` (moved from CatalogTab), `AI_DISCLOSURE_TEXT`.
- `web/app/(studio)/portal/_components/CatalogTab.tsx`: `exportSelected` builds the file from the module.
- `web/app/(studio)/portal/_components/catalogApi.ts`: `Version.ai` typed.
- `.github/code-health-baseline.json`: the stale `CatalogInner.exportSelected.map()#2` entry removed (the callback is
  gone; the new functions are under the complexity limit).
- Tests: `web/tests/studio/catalogExport.test.ts`.

## Tradeoffs

- A trailing disclosure line under a table: a script that reads every line as a row sees one short last row. The
  per-row AI columns are the machine mark; the line is for the person who opens the file. Putting it first would break
  header detection in every spreadsheet tool.
- English only, as on the other channels (the export headers are English by design, AA-1036).

## Should know

- Not covered: the DataTable toolbar "CSV" button of My Content and of the Content studio review list (kit
  `DataTable` `enableCsv`, a byte copy of the CIS kit core). Those files list the visible columns only (tour or piece
  title, country / channel, status, dates), not the written text; the kit has no hook for an extra trailer line. The
  register names them as a coverage limit; a kit change in CIS (a `csvTrailer` prop, then kit sync) is the follow-up.
- No API, no migration, no new setting.
- Live check after deploy: on the Dev studio (E2E tenant), My Content, select one tour, CSV (1) and XLSX (1); the CSV
  ends with the disclosure line and has the four AI columns; the XLSX last row is the disclosure and File > Properties
  shows the keyword `ai-generated`.
