## Decisions

- **Key crm-012, Guard 0 needs crm-011.** crm-013 (AA-978), crm-014 (AA-944), crm-015 (AA-945) follow; crm-014 and
  crm-015 replace `crm.erase_subject` again and must start from the crm-012 text (appendix below).
- **The Stage 2 signed link reuses the design's `crm.client_link`** (purpose `stage2_form`) rather than a new table:
  it already has a DM-7 row (root `02-data-management.md` §7, trips row), so the Copy Guard's retention-row check
  passes, and later purposes (proposal, portal, pay) add rows to the CHECK, not tables. Columns follow design group E
  with Fix B11 (`revoked_at`, `reissued_from`; no `cookie_bound`), plus `status` (sent / opened / submitted / expired /
  revoked, transitions in `crm.status_transition`) and `dispatch_id`.
- **Token lookup = the crm-008 invitation pattern**: `client_link_token_lookup` FOR SELECT TO `crm_app` on
  `token_hash = decode(app.client_link_hash, 'hex')`, and only live rows (status sent / opened / submitted, not
  expired, not trashed). An expired or revoked token therefore finds nothing, exactly like an unknown one (404
  `link_not_found`, no probing difference). The token itself is never stored (SHA-256 only, 32 bytes, CHECK).
- **Gates in the database (defence in depth behind the API's 409).** qualifying -> proposal needs
  `intake_completeness.s2 >= 80` or `app.gate_override = 'stage2'`. proposal -> booked and booked -> pre_departure are
  reachable only with an override (`app.gate_override = 'booking'` / `'stage3'`) until CRM-18 / CRM-24a / CRM-25 make
  them computable; that later card replaces `crm.enforce_stage_transition()` again. Refusal = SQLSTATE `CRM19`
  (`stage2_incomplete`, `gate_unmet:<gate>`).
- **Undo is a database rule, not reverse edges** (plan note 5). While `app.stage_undo = <history id>` the only
  allowed change is the exact reverse of the trip's latest history row, <= 15 s old (the API offers 10 s; 5 s slack for
  the request), not itself an undo, not a move into `cancelled`, written by the same `app.actor`. Anything else =
  `CRM20` (`undo_not_allowed`). The edge table and the gates are not consulted for an undo (the trip was legitimately
  in the earlier stage seconds ago).
- **No undo of a cancel.** The cancel flow has a dry-run preview, a typed confirmation and side effects (dispatch rows
  cancelled, tasks skipped, slots cancelled; later Booking release, invoices); none of them is reversible by flipping
  the stage back, so the database refuses it.
- **`trip_stage_history` insert pin** (`crm.pin_stage_history_insert`): for every role except `crm_owner`, `at`,
  `created_at` = `now()` and `created_by` = `app.actor`, the crm-007 audit pattern. The undo rule reads `at` and
  `created_by`; without the pin a `crm_app` bug could backdate a row or write another actor. The same trigger checks
  that `undo_of` names a row of the same trip (`CRM20`); the composite `(tenant_id, undo_of)` key keeps it in the
  agency.
- **`override` stays, now tied to `override_reason_code`** (`override = (override_reason_code IS NOT NULL)`), so every
  override carries one of `client_in_hurry`, `repeat_client`, `info_by_phone`, `manual_booking`, `manual_stage3`,
  `other`.
- **Cancel reasons** (fixed list, set exactly when `stage = 'cancelled'`): `client_request`, `client_illness`,
  `travel_advisory`, `force_majeure`, `supplier_failure`, `aa_cancelled`, `payment_not_received`, `duplicate`, `other`.
- **Completeness as jsonb `{s1, s2, s3}`** with a CHECK function (`crm.completeness_ok`: exactly those keys, integers
  0..100). `traveler_profile.stage2_completeness` (crm-005) stays the profile-side number.
- **Call-slot rules as jsonb** checked by `crm.call_slot_rules_ok`: `{}` = none offered, else `windows` (1-21 of
  `{dow 1-7 ISO, start HH:MM, end HH:MM}`), `duration_min` 10-240, `horizon_days` 1-60, <= 4 KiB. Times are local to
  `tenant_settings.timezone`. Both CHECK functions are IMMUTABLE, pinned `search_path`, EXECUTE for `crm_app` only
  (a CHECK runs with the writer's rights).
- **`timezone`**: default `Asia/Ho_Chi_Minh`; the database checks the shape only (a CHECK cannot read
  `pg_timezone_names`), the API checks the name.
- **`meeting_slot`**: one live slot per agency start time (partial UNIQUE on `(tenant_id, starts_at)` while requested /
  confirmed), so two inquiries racing for one slot give one slot and, in the job, a `call_slot_taken` task. `source
  form` needs its `form_submission_id`; trip and / or traveller (at least one).
- **Stage 2 submissions reuse `crm.form_submission`** (not in the plan's S1 list, but S3 needs it): `intake_form_id`
  is required for `s1` only; `client_link_id` with one composite key `(tenant_id, client_link_id, trip_id,
  traveler_id)` -> the link's own trip and traveller (a CHECK makes trip and traveller non-null whenever a link is set,
  so the MATCH SIMPLE key always fires); outcome adds `applied`.
- **`dispatch_id` and `reissued_from` are `ON DELETE SET NULL (col)`** (PostgreSQL 15 column list): erasing a dispatch
  row or an older link never blocks an erase; neither column is guarded by the hold rule.
- **crm_app never deletes a link or a slot** (status moves only), like `legal_hold` / `erasure_request`.
- **`crm.lifecycle_purge_expired` is not replaced**: it touches `llm_call` and `placeholder_map` only.

## The `waiting_on` hook (contract for AA-944 / AA-946; implemented in S2 `app/stages.py`)

`trip.waiting_on` (crm-005 CHECK `agency | client | aa | supplier | none`) is derived by one function on every stage
move, and re-derived by any card that changes what the trip waits on. Cards never write the column with their own rule.

```python
# app/stages.py
WaitingOn = Literal["agency", "client", "aa", "supplier", "none"]

@dataclass(frozen=True)
class TripFacts:          # read once per derivation, in the caller's open context
    trip_id: uuid.UUID
    stage: str
    stage2_link_open: bool  # a live client_link purpose stage2_form exists (sent / opened)

WaitingOnHook = Callable[[AnyContext, TripFacts], Awaitable[WaitingOn | None]]
WAITING_ON_HOOKS: list[tuple[int, str, WaitingOnHook]]  # (priority, name, hook); register_waiting_on_hook() adds one

async def derive_waiting_on(ctx: AnyContext, trip_id: uuid.UUID) -> WaitingOn: ...
async def refresh_waiting_on(ctx: AnyContext, trip_id: uuid.UUID) -> WaitingOn:  # derive + UPDATE when it changed
```

Rules of the base derivation (CRM-15): `inquiry` -> `agency`; `qualifying` -> `client` while a Stage 2 link is open,
else `agency`; `proposal` -> `client`; `booked` / `pre_departure` -> `aa` while the trip has an AA line not yet
`confirmed` (`trip_commitment` kind `aa_line` requested / held), else `none`; `travelling` / `completed` / `lost` /
`cancelled` -> `none`. Hooks run in ascending priority **only for stages booked and pre_departure**; the first hook
that returns a value wins over the base value, `None` = no opinion. AA-944 registers `("supplier_lines", 50)`: returns
`supplier` while the trip has an agency (non-AA) line that is not `confirmed`, else `None`. A member may still set
`waiting_on` by hand (`PATCH /crm/v1/trips/{id}`); the next move or `refresh_waiting_on` derives it again.

## Changed (vs the plan)

- `api/app/pipeline.py` `move_stage` refuses a move outside `ALLOWED_MOVES` before the UPDATE (409
  `transition_not_allowed`). With crm-012 applied the database opens qualifying -> proposal behind a gate the Slice 1
  code does not map (CRM19 would be a 500); the check keeps the deployed Slice 1 behaviour identical between the apply
  and the S2 deploy. Safe before the apply too (same moves as the crm-005 edges).
- `form_submission` changes (Stage 2 storage) are in crm-012 although the plan lists them only implicitly under S3.
- Gates for booking / Stage 3 are in the database too (the plan's item b named the Stage 2 gate only).
- History insert pin and the undo actor rule (not in the plan) answer the review question "is the undo / override
  setting abusable from crm_app sessions".

## Tradeoffs

- **The DB checks are defence in depth against code bugs, not against a compromised `crm_app`** (same threat model as
  crm-006 §4.3): `crm_app` can still set `app.gate_override` itself. A deferred constraint trigger "every gated move has
  a history row with an override reason in the same transaction" would close more, but makes every stage write order
  dependent; not worth it before real agencies.
- **15 s window vs 10 s offer**: the extra 5 s absorbs request latency; the API enforces 10 s (409 `undo_expired`).
- Existing trips get `intake_completeness = {0,0,0}` and `last_activity_at = apply time` (FORCE RLS hides every row
  from the migration, as in crm-011). On Dev that is synthetic data only; S3 recomputes completeness on the next change.
- One live call per agency start time (not per agent): agencies are small; per-agent calendars arrive with AA-961.

## Appendix: the final `crm.erase_subject` (crm-012)

crm-014 (AA-944) and crm-015 (AA-945) copy this text and add their tables; `crm.erase_held` (crm-012 section 11a) is
replaced the same way. Changes vs crm-010: trip scope unlinks `form_submission` (`trip_id`, `client_link_id`) first,
then deletes `client_link` and `meeting_slot`; traveller scope deletes `meeting_slot` (own, or booked by their
submissions) first and `client_link` after `form_submission`; the agency erase adds `meeting_slot` before and
`client_link` after `form_submission`.

```sql
CREATE OR REPLACE FUNCTION crm.erase_subject(p_scope text, p_subject uuid, p_profile_token uuid DEFAULT NULL,
                                             p_dry_run boolean DEFAULT true) RETURNS jsonb
    LANGUAGE plpgsql
    SECURITY DEFINER
    SET search_path = pg_catalog, pg_temp
AS $$
DECLARE
    v_tenant uuid := NULLIF(current_setting('app.tenant_id', true), '')::uuid;
    v_actor text := COALESCE(current_setting('app.actor', true), '');
    v_counts jsonb := '{}'::jsonb;
    v_blockers text[];
    v_status text;
    v_has_token boolean;
    v_step text[];
    v_left text[] := '{}';
    r record;
    -- Tables an agency erase keeps: the agency row (status offboarded), the destroyed key rows, the audit and its
    -- export registry and chain (crm-007: they leave with the partition drops / the archive), the erasure receipts,
    -- the lifecycle counts and the holds (ids and codes only).
    c_keep CONSTANT text[] := ARRAY['tenant', 'tenant_key', 'audit_event', 'audit_export_tenant',
                                    'audit_export_manifest', 'erasure_request', 'lifecycle_run', 'legal_hold'];
BEGIN
    IF v_tenant IS NULL THEN
        RAISE EXCEPTION 'crm: erase_subject needs app.tenant_id' USING ERRCODE = 'invalid_parameter_value';
    END IF;
    IF p_dry_run IS NULL OR p_subject IS NULL THEN
        RAISE EXCEPTION 'crm: erase_subject needs a subject and dry_run true or false'
            USING ERRCODE = 'invalid_parameter_value';
    END IF;
    IF p_scope NOT IN ('trip', 'traveler', 'task', 'note', 'document', 'relation', 'tenant') THEN
        RAISE EXCEPTION 'crm: erase_subject scope % is unknown', p_scope USING ERRCODE = 'invalid_parameter_value';
    END IF;

    -- Hold rule 4g: serialise with hold placement. SHARE conflicts with the ROW EXCLUSIVE of an INSERT / UPDATE on
    -- crm.legal_hold: a hold placed now waits until this transaction ends; a hold being placed makes this wait, then
    -- the check below (a new snapshot: this function is VOLATILE) sees it.
    LOCK TABLE crm.legal_hold IN SHARE MODE;

    -- The subject must exist in this agency (FORCE RLS: crm_owner sees app.tenant_id's rows only).
    IF p_scope = 'trip' THEN
        -- FOR UPDATE: a row that would reference the subject (FOR KEY SHARE of its foreign key) waits until this erase
        -- ends, so nothing is attached to it between the hold check and the deletes (the hold guard triggers catch
        -- any other change).
        PERFORM 1 FROM crm.trip WHERE trip_id = p_subject FOR UPDATE;
    ELSIF p_scope = 'traveler' THEN
        SELECT profile_token_enc IS NOT NULL INTO v_has_token FROM crm.traveler WHERE traveler_id = p_subject
           FOR UPDATE;
    ELSIF p_scope = 'task' THEN
        PERFORM 1 FROM crm.task WHERE task_id = p_subject;
    ELSIF p_scope = 'note' THEN
        PERFORM 1 FROM crm.note WHERE note_id = p_subject;
    ELSIF p_scope = 'document' THEN
        PERFORM 1 FROM crm.document WHERE document_id = p_subject;
    ELSIF p_scope = 'relation' THEN
        PERFORM 1 FROM crm.traveler_relation WHERE relation_id = p_subject;
    ELSE
        IF p_subject <> v_tenant THEN
            RAISE EXCEPTION 'crm: subject_not_found (a tenant erase names the agency of app.tenant_id)'
                USING ERRCODE = 'CRM13';
        END IF;
        SELECT status INTO v_status FROM crm.tenant WHERE tenant_id = v_tenant;
    END IF;
    IF NOT FOUND THEN
        RAISE EXCEPTION 'crm: subject_not_found (% %)', p_scope, p_subject USING ERRCODE = 'CRM13';
    END IF;

    -- Hold rule 4e: any held row among those this erase would delete or update refuses it, dry run included.
    IF crm.erase_held(p_scope, p_subject, p_profile_token) THEN
        RAISE EXCEPTION 'crm: legal_hold (an active legal hold reaches a row the erase of % % would change)',
            p_scope, p_subject USING ERRCODE = 'CRM10';
    END IF;

    IF p_scope = 'trip' THEN
        v_blockers := crm.trip_delete_blockers(p_subject);
        IF cardinality(v_blockers) > 0 THEN
            RAISE EXCEPTION 'crm: delete_blocked %', array_to_string(v_blockers, ',') USING ERRCODE = 'CRM11';
        END IF;
    ELSIF p_scope = 'traveler' THEN
        IF EXISTS (SELECT 1 FROM crm.trip_traveler tt JOIN crm.trip t ON t.trip_id = tt.trip_id
                    WHERE tt.traveler_id = p_subject AND t.deleted_at IS NULL) THEN
            RAISE EXCEPTION 'crm: traveler_on_trip (delete or erase the client''s live trips first)'
                USING ERRCODE = 'CRM12';
        END IF;
        IF v_has_token AND p_profile_token IS NULL THEN
            RAISE EXCEPTION 'crm: profile_token_required' USING ERRCODE = 'CRM15';
        END IF;
        -- Consistency guard (the database cannot open the encrypted pointer; the caller decrypted it from this row,
        -- bound by its AAD): every party row of the token is the F2 twin of one of the traveller's own party rows
        -- (same trip, same role).
        IF p_profile_token IS NOT NULL AND EXISTS (
            SELECT 1 FROM crm.trip_party p
             WHERE p.traveler_token = p_profile_token
               AND NOT EXISTS (SELECT 1 FROM crm.trip_traveler tt
                                WHERE tt.trip_id = p.trip_id AND tt.traveler_id = p_subject AND tt.role = p.role)) THEN
            RAISE EXCEPTION 'crm: profile_token_mismatch' USING ERRCODE = 'CRM15';
        END IF;
    ELSIF p_scope = 'tenant' AND NOT p_dry_run AND v_status <> 'offboarding' THEN
        -- A dry run (the counts the owner sees before confirming) works on an active agency.
        RAISE EXCEPTION 'crm: tenant_not_offboarding (status %)', v_status USING ERRCODE = 'CRM14';
    END IF;

    IF NOT p_dry_run THEN
        PERFORM set_config('app.erasing', 'on', true);
    END IF;

    IF p_scope = 'trip' THEN
        -- crm-012: the trip's submissions let go of the trip and of its links first, then the links and slots go.
        FOREACH v_step SLICE 1 IN ARRAY ARRAY[
            ['form_submission', 'trip_id = $1', 'trip_id = NULL, client_link_id = NULL'],
            ['client_link', 'trip_id = $1', ''],
            ['meeting_slot', 'trip_id = $1', ''],
            ['dispatch_queue', 'trip_id = $1', ''],
            ['trip_commitment', 'trip_id = $1', ''],
            ['document', 'trip_id = $1', ''],
            ['note', 'trip_id = $1', ''],
            ['task', 'trip_id = $1', ''],
            ['trip_stage_history', 'trip_id = $1', ''],
            ['trip_party', 'trip_id = $1', ''],
            ['trip_traveler', 'trip_id = $1', ''],
            ['trip', 'trip_id = $1', '']
        ] LOOP
            v_counts := v_counts || jsonb_build_object(
                v_step[1] || CASE WHEN v_step[3] <> '' THEN '_unlinked' ELSE '' END,
                crm.erase_rows(v_step[1], v_step[2], p_subject, NULL, p_dry_run, NULLIF(v_step[3], '')));
        END LOOP;
    ELSIF p_scope = 'traveler' THEN
        -- crm-012: their call slots (also those their submissions booked) before the submissions, their links after.
        FOREACH v_step SLICE 1 IN ARRAY ARRAY[
            ['meeting_slot', 'traveler_id = $1 OR form_submission_id IN (SELECT s.submission_id '
                             'FROM crm.form_submission s WHERE s.traveler_id = $1)', ''],
            ['dispatch_queue', 'traveler_id = $1', ''],
            ['traveler_health', 'traveler_id = $1', ''],
            ['document', 'traveler_id = $1', ''],
            ['note', 'traveler_id = $1', ''],
            ['traveler_relation', 'from_traveler_id = $1 OR to_traveler_id = $1', ''],
            ['trip_traveler', 'traveler_id = $1', ''],
            ['trip_party', 'traveler_token = $2', ''],
            ['profile_history', 'traveler_token = $2', ''],
            ['traveler_profile', 'traveler_token = $2', ''],
            ['consent', 'traveler_id = $1', ''],
            ['form_submission', 'traveler_id = $1', ''],
            ['client_link', 'traveler_id = $1', ''],
            ['traveler', 'referrer_traveler_id = $1', 'referrer_traveler_id = NULL'],
            ['traveler', 'traveler_id = $1', '']
        ] LOOP
            v_counts := v_counts || jsonb_build_object(
                v_step[1] || CASE WHEN v_step[3] <> '' THEN '_referrer_unlinked' ELSE '' END,
                crm.erase_rows(v_step[1], v_step[2], p_subject, p_profile_token, p_dry_run, NULLIF(v_step[3], '')));
        END LOOP;
    ELSIF p_scope IN ('task', 'note', 'document') THEN
        v_counts := jsonb_build_object(p_scope,
            crm.erase_rows(p_scope, p_scope || '_id = $1', p_subject, NULL, p_dry_run));
    ELSIF p_scope = 'relation' THEN
        v_counts := jsonb_build_object('traveler_relation',
            crm.erase_rows('traveler_relation', 'relation_id = $1', p_subject, NULL, p_dry_run));
    ELSE
        -- The whole agency. Memberships are deleted as a platform action (crm-008 guard_member_write lets only an
        -- unscoped or platform context delete a member); the caller's actor is restored afterwards.
        PERFORM set_config('app.actor', 'platform:crm_offboarding', true);
        FOREACH v_step SLICE 1 IN ARRAY ARRAY[
            ['dispatch_queue', ''], ['trip_commitment', ''], ['document', ''], ['traveler_health', ''],
            ['note', ''], ['task', ''], ['trip_stage_history', ''], ['trip_party', ''], ['trip_traveler', ''],
            ['traveler_relation', ''], ['consent', ''], ['meeting_slot', ''], ['form_submission', ''],
            ['client_link', ''], ['profile_history', ''],
            ['traveler_profile', ''], ['placeholder_map', 'optional'], ['llm_call', ''], ['trip', ''],
            ['traveler', 'unlink'], ['traveler', ''], ['intake_form', ''], ['form_definition', ''],
            ['integration_credential', ''], ['tenant_settings', ''], ['member_invitation', 'optional'],
            ['owner_recovery_request', 'optional'], ['tenant_entitlement', 'optional'], ['member', '']
        ] LOOP
            CONTINUE WHEN v_step[2] = 'optional' AND to_regclass('crm.' || v_step[1]) IS NULL;
            IF v_step[2] = 'unlink' THEN
                v_counts := v_counts || jsonb_build_object('traveler_referrer_unlinked',
                    crm.erase_rows('traveler', 'referrer_traveler_id IS NOT NULL', p_subject, NULL, p_dry_run,
                                   'referrer_traveler_id = NULL'));
            ELSE
                v_counts := v_counts || jsonb_build_object(v_step[1],
                    crm.erase_rows(v_step[1], 'true', p_subject, NULL, p_dry_run));
            END IF;
        END LOOP;
        PERFORM set_config('app.actor', v_actor, true);
        -- Nothing of the agency may be left in a tenant table outside the keep list: a table added later that this
        -- function does not know fails the erase (rolled back) instead of keeping personal data silently.
        IF NOT p_dry_run THEN
            FOR r IN SELECT c.relname::text AS name
                       FROM pg_catalog.pg_class c
                       JOIN pg_catalog.pg_attribute a ON a.attrelid = c.oid AND a.attname = 'tenant_id' AND NOT a.attisdropped
                      WHERE c.relnamespace = 'crm'::regnamespace AND c.relkind IN ('r', 'p') AND NOT c.relispartition
                        AND c.relname <> ALL (c_keep) AND c.relname NOT LIKE 'audit_event%'
                      ORDER BY 1 LOOP
                IF NOT (SELECT relforcerowsecurity FROM pg_catalog.pg_class WHERE oid = ('crm.' || quote_ident(r.name))::regclass) THEN
                    v_left := v_left || r.name;  -- without FORCE RLS the owner would see every agency: refuse
                ELSE
                    EXECUTE format('SELECT EXISTS (SELECT 1 FROM crm.%I)', r.name) INTO v_has_token;
                    IF v_has_token THEN
                        v_left := v_left || r.name;
                    END IF;
                END IF;
            END LOOP;
            IF cardinality(v_left) > 0 THEN
                RAISE EXCEPTION 'crm: erase_incomplete (rows left in %)', array_to_string(v_left, ', ')
                    USING ERRCODE = 'CRM16';
            END IF;
        END IF;
    END IF;

    IF NOT p_dry_run THEN
        PERFORM set_config('app.erasing', '', true);
    END IF;
    RETURN jsonb_build_object('scope', p_scope, 'dry_run', p_dry_run, 'counts', v_counts);
END;
$$;
REVOKE ALL ON FUNCTION crm.erase_subject(text, uuid, uuid, boolean) FROM PUBLIC;
GRANT EXECUTE ON FUNCTION crm.erase_subject(text, uuid, uuid, boolean) TO crm_eraser;
```
