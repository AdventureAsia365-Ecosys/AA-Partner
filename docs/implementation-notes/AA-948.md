# AA-948 (card CRM-20): the proposal builder map on the shared map engine

Tech lead decision S294 D8: one shared map engine, extracted from the TripPlanner planner map, instead of a CRM fork of
TripPlanner; the Mapbox cost of CRM map loads is accepted (about 0 USD on Dev: free tier, synthetic agencies only,
a token restricted to the agency host).

## What it does

- The builder (`/pipeline/<trip>/proposal/<version>`, A-04) shows a **Map** panel above the days: each trip day that
  has a place is a numbered stop, joined in day order in the agency's accent colour. A click on a stop selects that day
  in the builder and names its places ("Day 2: Mosswater (approximate area)"). The days without a place are listed
  under the map ("Days without a place on the map: 4"), never pinned at a guess (design edge case: "a day without a
  location renders without a pin"). The "Before you go" day is never on the map.
- Where the points come from (API, `app/proposals/day_map.py`): the builder view's `days[].map_points`, the places of
  the version's whole AA tours (`trip_plan` options) that AA still serves (`crm.aa_catalog_tour.served_state =
  'served'`: the agency's live AA tours only), from the catalog cache body (`Tour.days[].places[]`: name, lat, lng,
  precision). A proposal day takes the tour day it falls on only while the tour runs that day.
- Empty states, never an error: no token configured -> "Map not set up yet"; a token but no placed day -> "Nothing to
  show on the map yet". In both cases no map is created, so an empty builder costs no Mapbox map load.

## Decisions

- **Shared engine, root ADR 0016 pattern** (the UI kit's guarded byte copies): canonical in AA-TripPlanner-Web
  `frontend/lib/map-engine/` (the engine came from its MapView), byte copy here in `web/lib/map-engine/`, pinned by
  `web/map-engine.lock.json` (canonical repo/path, ref, sha256 of the copied `MANIFEST.json`). Written only by the
  canonical folder's `check-map-engine.mjs --sync`; never edited here.
- **Framework-free core** (`geo.ts`, `motion.ts`, `layers.ts`, `engine.ts`; mapbox-gl passed in, a type import only)
  and a thin React binding (`react.ts`, `useMapEngine`). No Next import anywhere in the core.
- **Import guard** (`check-map-engine.mjs --imports . --engine lib/map-engine`): no source file imports the TripPlanner
  app (package `aa-tripplanner-frontend`, a path naming `AA-TripPlanner-Web`, or a relative path that leaves this
  repository), and `mapbox-gl` is imported only inside the engine copy (its stylesheet may be imported anywhere).
  Runs in Web Build ("Map engine copy"), in the vitest suite (`tests/builderMap.test.ts`) and in the pre-push kit step.
- **Provenance** (`api/scripts/check_map_engine_provenance.py`, Web Build): the copied manifest is AA-TripPlanner-Web's
  at a ref on its `main`, **or** its `main` manifest today. The second form lets an engine change and its first
  consumer ship in one wave: the copy is synced from the TripPlanner branch, whose commit is not on `main` after the
  squash merge; the copy is still exactly what TripPlanner merged. A later sync refreshes `ref`.
- **Token = runtime config, not a setting**: `MAPBOX_PUBLIC_TOKEN` of the web task, read per request on the server
  (`web/lib/mapConfig.ts`) and passed to the client map as a prop. Not a build arg (one image for every environment),
  not in the settings registry (it is an integration credential, not a policy value). Only a public `pk.` token is
  accepted; a secret `sk.` token or anything else gives the "not set up" state, so a wrong value never reaches a
  browser. AA-CIS-Infra maps it from the key `mapbox_public_token` of `crm/dev/web` while `crm_web_mapbox_enabled`.
- **No new feature key**: the map is part of the builder page, so it follows the builder's own access (the CRM add-on
  and the member's role). No entitlement code exists for the builder or its map (`app/entitlements.py` FEATURES).
- **CSP**: `connect-src` gains the Mapbox hosts (API, tiles CDN, telemetry; the list the TripPlanner planner uses);
  `worker-src blob:` and `img-src data: blob:` were already there.

## Changed

- API: `app/proposals/day_map.py` (new), `app/proposals/builder.py` (`days[].map_points` via `with_points`; the module
  docstring reflowed by one line so the file stays at its code-health baseline).
- Web: `lib/map-engine/` (copy), `map-engine.lock.json`, `components/proposals/BuilderMap.tsx`, `lib/builderMap.ts`,
  `lib/mapConfig.ts`, `lib/i18nBuilderMap.ts` (EN/VI), `BuilderPage.tsx` (the panel), the builder route page (token),
  `lib/securityHeaders.ts` (CSP), `mapbox-gl` 3.7.0 + `@types/mapbox-gl` 3.4.1 (the TripPlanner pins).
- CI: Web Build steps "Map engine copy (integrity + import guard)" and "Map engine provenance"; the scope area `web`
  includes the provenance script. Pre-push: the same two offline checks in the web kit step.

## Tradeoffs

- One stop per place visit: two days at the same place share the first day's numbered stop (the planner's rule);
  selecting the later day from the map is done from the day list.
- The map is drawn with Mapbox layers (circles + labels), not DOM markers: lighter, but a stop is reached by mouse
  or touch only; the same days are in the day list next to it for keyboard and screen reader users.
- The provenance check's "main today" form trades a strict ref check for one-wave shipping; integrity and the
  manifest match still make any edit of the copy fail.

## Hand step: the Mapbox token (tech lead)

1. Sign in at https://account.mapbox.com/ (the account that already holds the TripPlanner token; the free tier covers
   Dev map loads, about 0 USD).
2. **Tokens -> Create a token**. Name `aa-crm-builder-dev`. Public scopes: the defaults only (`styles:read`,
   `fonts:read`, `datasets:read`, `vision:read`); no secret scope.
3. **URL restrictions**: add the two agency hosts of the CRM web, `https://portal.lumiguides.it.com` (the public
   origin agencies sign in on) and `https://partner-dev.lumiguides.it.com` (the partner host). Nothing else: no
   localhost, no wildcard. Save, copy the `pk.` token.
4. Write it into the web secret (MFA profile, token on stdin, never in the shell history), from an AA-CIS-Infra
   checkout: `printf '%s\n' '<pk token>' | python3 tools/identity/crm_dev_identity.py web-mapbox-token --mapbox-token - --apply`
   (the output says `"map": "on"`, `"action": "written"`; the value is never printed).
5. Then the orchestrator: tfvars PR `crm_web_mapbox_enabled = true` (AA-CIS-Infra `accounts/aa365/terraform.tfvars`)
   -> Terraform Apply -> Deploy Web Dev of AA-Partner. Check: the builder of a proposal with an AA tour shows the map;
   `curl -s -H "Referer: https://example.invalid/" "https://api.mapbox.com/v4/mapbox.mapbox-streets-v8/1/0/0.mvt?access_token=<pk>" -o /dev/null -w "%{http_code}"`
   answers 403 (the URL restriction holds; a style request would still answer 200, so test a tile).
