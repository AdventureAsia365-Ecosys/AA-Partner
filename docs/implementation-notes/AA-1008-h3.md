# AA-1008 H3 — the Visual check ready to be a required check (AA-Partner)

Lane `aa1008-h3-visual-merge-group` (S270). Companion PRs: AA-CIS-App (`visual.yml` + `kit-consumers.yml`) and
AA-Booking (`visual.yml` + the post-deploy not-found fix). The branch-protection step itself is the tech lead's
(ADR 0011); this PR only makes the check safe to require.

## Decisions

- **Step-level skip, not a scope job.** `visual.yml` job `pr` gets a `Scope` step right after the checkout. It diffs
  the PR (`origin/<base_ref>...HEAD`) or the queue group (`merge_group.base_sha...HEAD`) and matches the old
  pull_request `paths:` list, including the negation `!web/tests/**` (a web/tests-only change still skips; GitHub
  evaluates the patterns in order and nothing after the negation matches web/tests/). No match: `run=false`, "no
  frontend change" in the step summary, every later step skipped by `if: steps.scope.outputs.run == 'true'`, the job
  green. A separate scope job with a job-level `if`/`needs` would report "skipped", which GitHub counts as passed even
  when the scope job failed.
- **The required name stays**: `Visual (built in the runner, public pages + kit gallery)` (pinned by the TL script,
  verify-h3.sh and the new test).
- **Scope fails toward running**: an empty base or a failing `git diff` runs the full check with a warning, never a
  silent skip. `--no-renames` so a file moved out of `web/` still counts by its old name.
- **merge_group**: `Changed pages` diffs `$MERGE_BASE_SHA...HEAD` (`github.base_ref` is empty there); the PR comment
  stays pull_request-only. The `deployed` job's condition names workflow_run and workflow_dispatch only, so it never
  runs on pull_request or merge_group (unchanged; a test pins it).
- **Concurrency**: the old fallback `github.event_name` gave every queue group the group `visual-merge_group` with
  `cancel-in-progress: true`, so each new group would cancel the last; merge_group now keys on `github.run_id`.
  workflow_run runs keep their shared group (a newer deploy's visual run replaces an older one, as before).

## Changed

- `.github/workflows/visual.yml` (header: now a required check).
- `api/tests/unit/test_aa1008_h3_visual_required.py` (new, text-based like `test_visual_workflow_hosts.py`):
  triggers, name, step guards, concurrency, the deployed job's condition; the Scope step run with bash in a scratch
  git repo for each path of the old filter, the negation and near misses, on pull_request and merge_group.

## Tradeoffs

- Every PR now starts the job (checkout with full history + one diff, ~30 s) even without a web change.
- A web PR's queue group runs the full visual again (~3–6 min) on the combined commit.
