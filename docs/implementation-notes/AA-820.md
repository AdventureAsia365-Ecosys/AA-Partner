# AA-820 — portal AI provider list follows the AI Use Register (S262)

Design: root ADR 0009 (AI platform and provider gateway, accepted parts 31/10/2026) and its AI Use Register v0
(`docs/architecture/ai-use-register.md` in the root repo, S262 item TL-15). The Usage Policy clause itself was already
on `/terms` §3 since the v0.2 portal change (root `docs/legal/tenant-terms-ai-clause-draft.md`); this slice only makes
the provider list match the register.

## Decisions

- **Two writers, one checker family, two capped fallbacks.** `/terms` §3 and `/privacy` §5 now say: Claude through
  Amazon Bedrock writes; OpenAI models through Amazon Bedrock review, score and check; the Anthropic API or the OpenAI
  API, used directly with a spending cap, "may be used as a fallback". This is what the routes allow today: the judge
  routes (`s1_judge`, `t2_judge`, `t7_debate_judge`, `t10_judge`, `t10_adjudicate`) end at `gpt-6-luna-openai`, so
  tenant text can reach the OpenAI API when both Bedrock judge models fail; the Anthropic API path is approved
  (ADR 0009 decision 14) but no route names it yet, so "may" is the honest word.
- **Jev on `/privacy` only.** Jev answers yes/no checks for allowlisted tenants; the privacy notice names it as a
  recipient. The terms do not, because the tenant's duty is to follow the model providers' usage policies, and Jev
  is not a model provider in that sense.
- **OpenAI Usage Policies linked in the terms.** OpenAI models check tenant content, so their policy belongs next to
  the Anthropic and AWS ones.
- **Cohere left out.** Embeddings cover catalog content and traveller search text, never tenant data (register).
- **Version bump.** `LEGAL_VERSION` Draft v0.2 → v0.3, `LEGAL_UPDATED` 31 October 2026. The draft banner stays: counsel
  has not reviewed either page.

## Changed

- `portal/app/terms/page.tsx` §3: the provider bullet split in two (who writes and checks; whose policies apply).
- `portal/app/privacy/page.tsx` §5 and §6: the "[to be confirmed]" provider list is replaced by the register list.
- `api/tests/unit/test_portal_guards.py`: two guards (`test_terms_ai_section_names_the_register_providers`,
  `test_privacy_ai_section_lists_every_provider`).

## Tradeoffs

- Naming the fallback paths makes the pages longer, but omitting them would be untrue for the judge routes.
- The guards check phrases, not the register file (it lives in another repo); the register's "who updates it" rule and
  this note carry the link.
