## Decisions

- **The submission is stored first, processed by a job.** The public route encrypts the answers into
  `crm.form_submission` and queues `crm_intake_process` (ids only) in the same transaction; the job creates the
  traveller and the trip. The card names the job, the public request stays short, and a vault or DB hiccup in the
  heavy part is retried by the runner instead of losing the inquiry. "Card on the board within ~1 min" = the worker
  poll plus one job.
- **R test shape.** Honeypot filled -> **202 as if stored** (a bot learns nothing), nothing written, not even the job;
  no contact consent -> **422 `consent_required`** (a person needs to know why), nothing written. Both leave one
  count-only log line `intake_dropped reason=<honeypot|no_consent|invalid|origin> form_id=<id> count=<n>` and bump an
  in-process counter; never the payload, the address or the e-mail.
- **Public route prefix `/crm/public/v1`, not a route class.** It takes no token; the agency is decided by the form's
  URL key inside the new `intake_tx()`, which reads the form through a SELECT-only policy keyed on `app.intake_key`
  (the crm-004 caller-lookup pattern). `CONTEXT.md` route table updated.
- **The browser posts to the API on the client host itself.** The web reaches the API through CloudFront from its
  NAT address, so a web-side relay would make every visitor one address for the API's limits. The client host's ALB
  rule sends `/crm/public/*` to the API and everything else to the web (Infra branch `feat/aa-936-client-host`);
  same origin, no CORS, and the limits key on `CloudFront-Viewer-Address`.
- **Limits**: 5 submissions per address per minute and 200 per form per hour (in-process fixed windows, like the
  health limit; `FixedWindowLimiter` got a `window_s`). Review S249: the per-address limit runs before anything is
  read; the **per-form quota is charged only by a submission that passed the origin, honeypot, consent and answer
  checks** (`submit(form_quota=...)`, 429 `form_rate_limited` + `Retry-After`, nothing written), so forged-origin,
  honeypot or junk requests cannot lock a form for an hour. A bot sending well-formed answers with a forged Origin can
  still use it up from many addresses (it would also be writing rows, which the quota exists to cap); the WAF rule
  at Go-real is the answer to that.
- **Body cap holds for chunked bodies** (review S249, blocking): the route streams `request.stream()` and stops with
  413 as soon as the buffer passes 32 KiB (`read_capped`), so a chunked body without Content-Length, or one whose
  Content-Length lies, is never buffered whole; a declared Content-Length over the cap is refused before reading. Origin check: the client host (`INTAKE_PAGE_ORIGINS`) or the
  form's own `allowed_origins`; with no page origin configured outside test/local every submission answers 503
  `intake_not_configured` (fail closed).
- **Embedding = iframe of the hosted page.** `allowed_origins` drives the page's CSP `frame-ancestors` (the proxy
  reads the form definition through a 60 s memo shared with the page). No script embed in Slice 1.
- **One AA-prebuilt Stage 1 definition (`stage1.v1`)** in code (`app/intake/stage1.py`): the server validates every
  answer; `crm.form_definition.schema` stores a snapshot per agency. Conditional branches (R31) are CRM-15.
- **Budget bands are USD per person excluding flights** (spec §5 rule 2: bands, not numbers). The agency base
  currency (`tenant_settings.base_currency`) arrives with the money cards.
- **"Open Inquiry" = the lead's trip at `inquiry` or `qualifying`.** Both are pre-proposal leads; a second form from
  someone being qualified must not open a second trip. Once lost (or later stages), a new inquiry opens a new trip for
  the same traveller (repeat client, `repeat_count` + 1 on the F2 profile).
- **Dedupe keys: e-mail blind index first, then phone.** Names are never a dedupe key (lossy 8-byte index).
- **Dedupe is serialised by advisory locks** (review S249): `crm.traveler` has no unique index on the blind indexes
  (a traveller may have none), so `crm_intake_process` takes `pg_advisory_xact_lock(hashtextextended(...))` on
  (agency, e-mail index) and then (agency, phone index) before the lookup. Two jobs for the same new person (two
  workers overlapping in a rolling deploy) no longer create twin travellers / trips; the integration test runs two
  handlers with `asyncio.gather` and fails when the locks are removed. Lock order is fixed (e-mail, then phone; the
  key prefixes differ), so no deadlock.
- **Consent from a form, and the F2 flag** (review S249): every processed submission appends its `contact` and
  `marketing` rows (latest row per purpose wins) and `traveler_profile.marketing_ok` now **follows that latest
  marketing row on every path** (no more `marketing_ok OR true` on a repeat, and the attach path sets it too), so the
  ledger and the flag cannot disagree. A submission is unverified (anyone can type someone's e-mail), so neither is
  enough to send marketing: **CRM-17 / CRM-29 must confirm marketing by double opt-in before any marketing mail.**
- **Past dates are refused** (review S249): a start date before yesterday (UTC; a visitor ahead of UTC choosing
  "today" passes) or a month before the current one is `invalid_submission` on that field. Stored answers whose keys
  no longer match (`Stage1Answers.from_json` TypeError) are a permanent `Stage1Invalid` `stored_answers`, not five
  retries.
- **The web's form lookup has its own guard** (review S249): the page and the proxy fetch the definition from the
  web's NAT address, which the API's public limit counts as one caller. `loadForm` now (a) memoises missing keys apart
  from found forms (random keys cannot evict real forms), (b) allows each viewer (`CloudFront-Viewer-Address`, IPv4
  or IPv6 /64) at most 20 memo misses per minute before the API is asked (over that: 429 page, no API call), and
  (c) keeps serving the last good definition when a refresh fails or the API answers 429 / 5xx, so the CSP never
  falls back to `frame-ancestors 'self'` for a known form while the API is busy.
- **LLM budget check is serialised per agency** (review S249): `pg_advisory_xact_lock` on the agency id before the
  month's spend is read, held until the call is logged, so two calls at 99 % cannot both pass once CRM-33a turns real
  calls on. Calls of one agency run one at a time; fine for the CRM's volumes, revisit if CRM-33a needs parallel
  calls (then reserve the estimated cost in a row instead).
- **Trip stage CHECK holds every stage now; Slice 1 opens only its moves.** Design Fix B5 wants every stage defined
  early; adding transition rows later is cheaper than rewriting a CHECK. The stage trigger is a twin of the crm-002
  status trigger (`crm.enforce_stage_transition()`), reading the same `crm.status_transition` table.
- **Lost needs one of the fixed R23 reasons** (CHECK: `lost` iff a reason); reopening clears it.
- **Contact reveal is in Slice 1** (`POST /travelers/{id}/reveal`, e-mail or phone, one `reveal` audit per click):
  without it the "reply within 2 h" task cannot be done. CRM-09 adds the sensitive fields and `reason`.
- **One `list_view` event per board load** with `object_kind = pipeline` and `fields = [display_name]` (the audit
  row has one object id; the id list per event is CRM-12's audit format).
- **Member names are not shown**: `crm.member` holds no name (identity stays in Cognito); the assign menu says "Me" or
  "Agent · 3f2a". Names come with the team page (CRM-11 / AA-978 feed).
- **Assignment rule (R8 / §4.6)**: owner assigns anyone or nobody; agent / assistant may only take an unassigned trip.
  The reply task follows the new owner when it was unassigned or the old owner's.
- **LLM gateway stub**: own gateway and log (D12), order scrub receipt -> budget -> `ai_enabled` -> call -> log; every
  refusal is a `crm.llm_call` row too (cost 0), so the CIS cost page sees attempts. A stub scrubber is accepted only
  with the stub provider (no real model ever gets unscrubbed text). Budget = this month's `cost_usd_est` sum vs
  `tenant_settings.ai_budget_usd` (default 2); the 75/90 % alerts and `spend_budget` are CRM-33a.
- **CIS cost row uses a platform rollup.** `crm.llm_call` is tenant-scoped (FORCE RLS); a cross-agency read would
  need a widening policy. `crm.llm_usage_daily` (no tenant column, no PII) is upserted in the call's transaction and
  read by `/crm/ops/v1/llm/usage`.
- **`system_tx()` / `intake_tx()`** are new contexts with the same audit queue as `tenant_tx()` (`SystemContext`,
  `actor_kind = system`); the DB lint restricts each to its modules and now also accepts `<param>.conn` on a
  context-typed parameter, so helpers take the open context instead of opening one.
- **Seeder writes travellers through the intake path** (`--apply --travellers`), so synthetic people reach the vault
  exactly like real inquiries; fake phones the validator refuses are dropped.
- **E2E lives in `e2e/` with exact versions and no lockfile**, outside `web/` (never in an image, no effect on the web
  build or `npm audit`); env names without underscores (CIS `E2ECOGNITO` convention).

## Changed

- **No confirmation mail and no agent e-mail in Slice 1.** The card's F1 flow ends with "the confirmation email", but
  errata S247 makes every traveller mail leave the agency's own mailbox (CRM-17, AA-945); AA's SES sends system mail
  only. The "Reply within 2 h" task and the board card are the agent's signal until then.
  The **agent "new inquiry" e-mail** is different: it is AA system mail (errata S247 §3 item 3, "operational alerts
  to agency people: ... new inquiry"), so it is allowed, but it is **deferred to CRM-17 (AA-945)** here because two
  things it needs do not exist yet: (1) a CRM sender on AA's SES (the CRM task role has no `ses:SendEmail` grant and
  there is no CRM system-mail configuration set; AA-931 granted only the receipt rule), and (2) the member's e-mail
  address (`crm.member` holds none by design; it comes from the partner pool, AA-939). **Needs Nghiệp's explicit
  record of this deferral** (review S249); the delivery-plan checklist item stays open until then.
- **No system tags (R29)**: they derive from the CIS catalog (`catalog.http.v1`, CRM-B4); not built here.
- **No `traveler_relation` for companions (R7)**: companions are names-only travellers on the trip (Fix E5);
  relationships are CRM-09.
- **`inquiry.submitted`** is the TripPlanner -> Booking contract; the CRM card does not use it (nothing aligned).
- **`form_submission.redact_after`** instead of the lane's `purge_after = +90 d`: `purge_after` is a trash column of
  the base template (set only together with `deleted_at`). The redaction job comes with CRM-14.

## Tradeoffs

- In-process rate limits are per task (Dev runs one); a WAF rule replaces them at Go-real (ADR 0010 decision 2).
- E2E workflow (review S249): every step that runs third-party code before the tests (npm install with
  `--ignore-scripts`, the browser download, `tsc`) now runs **without AWS credentials**; the mailbox role (it reads
  every e2e inbound mail, sign-in codes included) is configured just before `playwright test`. Actions pinned by SHA
  (checkout v7.0.1, setup-node v7.1.0, configure-aws-credentials v6.3.0, upload-artifact v7.0.2; each release older
  than two weeks), checkout without persisted credentials.
- The honeypot is a single hidden field with a per-form random name; no time trap or CAPTCHA (no third party, no
  personal data to a vendor). Revisit with real traffic.
- The proxy's form lookup adds one API call per form per minute per web task (memo), not per view.
- The board shows at most 50 cards per stage (count shows the total); paging and the List view are CRM-15.

## S249 follow-up: English by default + E2E Dev run 40060691620 (branch `fix/crm-web-english-default`)

### Decisions

- **English unless the person picks another language** (owner rule, Nghiệp S249). `resolveLocale` takes only the
  cookie and an `explicit` value from the page's own record; the agency's `default_locale` and Accept-Language are no
  longer inputs (removed from the signature, so no caller can pass them by mistake). en-AU is the default date locale
  ("3 Apr 2026", design v3 §2.3); vi-VN reads "3 thg 4, 2026". Dropping Accept-Language was deliberate: a Vietnamese
  browser is not an explicit choice, and the spelled month keeps en-AU dates unambiguous for US readers too.
- **Agency `default_locale` keeps its data role.** The API still writes trip titles in the agency's language
  (`stage1.trip_title`, "Việt Nam, 9 đêm"); the board shows that stored title as data inside an English UI. Changing
  the stored title language is an API/data decision, not part of this fix.
- **Public form `/c/f/<key>`: English unless the form sets `locale`.** The design (lanes/data-privacy-integrations
  `form_definition … locale`; design v3 C-01 R32) puts the language on the form definition, not on the agency. The
  API already spreads the definition's `schema` into the public payload, so a `locale` key there (`en`, `vi` or a date
  locale) is honoured by the web (`PublicForm.locale`); no seeded form sets one, so Dev forms are English. No UI to set
  it yet (Forms admin, CRM-15). The visitor's cookie would win, but the client host does not serve `/prefs`, so in
  practice the form's own setting decides. The form block carries `lang` (the root `<html lang>` follows the cookie).

### E2E root cause (run 40060691620)

- Failure: `getByTestId('revealed-email')` not found after clicking "Xem e-mail". Screenshots 01–03 passed (form
  refused without consent, thanks, card on the board — UI in Vietnamese, which the spec's bilingual regexes accepted,
  so language was not the cause).
- Evidence (CRM API log `/ecs/aa-crm-dev`, git_sha 2c21001): the intake job succeeded at 04:02:2x
  (`crm_intake_process … status created`), the trip page loaded (`GET /crm/v1/trips/<id>` 04:02:26.205,
  `GET /crm/v1/members` 04:02:26.271), and then **no `POST /crm/v1/travelers/<id>/reveal`** and no further request
  until the test timed out at 04:02:31. The BFF guard was ruled out (same-origin POST without a session answers 401
  `session_expired`, not 403; a 401 in the browser would have reloaded through `/auth/refresh`, which would show
  `/me` calls — none).
- Cause: the board card is a plain `<a href>`, so the trip page is a full server render. Playwright saw the SSR text
  (`trip-party` contains the name) and clicked the "Show email" button before React hydrated it; a pre-hydration
  click runs no handler. Same latent race on the inquiry form (destination chip click lost; the submit would post the
  form natively with the answers in the URL).
