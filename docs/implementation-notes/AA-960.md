# AA-960 — CRM-29b tags, system tags, coverage, ready to travel again

Design v3 §6.3 card CRM-29b (R3 tags + tag workflows, R29 system-tag workflows, R30 missing-workflow badge, R36 ready
to travel again). Card rules: **R** a workflow on an archived contact is suppressed; **E** bulk apply previews the
count, the R36 list explains its reasons. Builds on CRM-29a (AA-959, `crm-038`). Migration `crm-061` (expand).

## Decisions

- **Schema (crm-061, expand only).** `crm.tag` (kind agency | system, applies_to trip | client, fixed `code`, name,
  tone, archived_at) and `crm.tag_link` (one tag on one trip or one client, source member | system, `reasons` JSON on
  a system link). No ALTER of an existing table, so the file stays expand (root ADR 0017) and ships in the wave's
  migration-only PR (batch crm 059-061). The design's polymorphic `object_kind/object_id` became two nullable foreign
  keys (`trip_id`, `traveler_id`, exactly one) so every link cascades from the row the erase deletes: no replaced
  `crm.erase_subject` (contract) was needed.
- **Codes, not ids, in workflow conditions.** A tag has a fixed `code` (made once from its first name, ASCII
  `a-z0-9_`; renaming keeps it). `conditions.tags_any` names codes, like the other condition lists, so a rule reads in
  words and survives a rename. System codes start with `sys_`; an agency code never does (CHECK + `code_for`).
- **System tags are the app's only** (guard CRM55 `system_tag_app_only`): a member can neither add nor remove one. They
  are refreshed by the hourly workflow tick (`app.tags.system`, actor `job:crm_workflow_tick`), not by a new job kind:
  no job registry / capacity change. Trip tags (R29) every hour; ready to travel (R36) once a day at the special-date
  hours (the client history is read once or twice a day, like birthdays).
- **R29 sources AA catalogue data only** (rescope note S265, root ADR 0015 live tour): the AA tours a trip holds (live
  AA booking lines and AA options of live proposals) joined with `crm.aa_catalog_tour` `served_state = 'served'`;
  facets = duration (day tour / multi-day), the CIS activity vocabulary (8 codes) and intensity (easy, challenging).
  Agency data (children, budget) is not turned into system tags: those are already workflow conditions.
- **R36 rule** (`app.tags.model.ready_to_travel`): a completed trip with an end date, no open trip, home at least 9
  months. Reasons (codes and numbers): months since return, repeat traveller, anniversary of the last trip within 60
  days, new live AA tours in a country they travelled to (not booked before). The list is the agency's marketing (it is
  the controller); AA never reads it; the list shows the marketing consent state and sending stays consent-gated by the
  engine and the dispatcher.
- **Tag workflows** = trigger `event` with value `trip_tag.added` or `client_tag.added` and the condition `tags_any`
  (required for those two). No CHECK change on `crm.workflow_rule` (its trigger kinds are unchanged). A
  `client_tag.added` rule is about the client (like a special date): its steps are tasks, e-mails, texts and waits.
  Runs are keyed `tag:<tag link id>`, so a tag removed and put back starts the rule again, a refresh that re-writes the
  same link starts nothing.
- **Card R** (archived contact): putting a tag on an archived client starts no client workflow; the start is audited
  `workflow_start` denied `client_archived` and the bulk preview counts it as "workflows suppressed". The engine
  already stops a client run when the client is archived (AA-959).
- **Coverage (R30) is computed on read**, not stored (`workflow_run.coverage_gap` of the design would be an ALTER =
  contract): `GET /workflows/coverage` lists, per active stage or trip-tag rule, the live trips in that state that
  match its conditions and never had a run of it. [Run] = the existing apply (dry run first) on those trips.
- **Permissions** (no tag row in design §4.6; added to the matrix): `tag_apply` every role (tag one trip / client and
  make a new tag from the picker, like editing a client); `tag_bulk_apply` owner + agent (like `workflow_apply`);
  `tag_manage` owner (rename, recolour, archive, delete: it changes every record); `marketing_view` owner + agent (the
  A-15 Marketing nav is owner / agent).
- **Bulk apply** takes a selector (trip stage / owner / tag, or client archived / owner / tag) or explicit ids, always
  previews first (count, already tagged, archived = suppressed, held = skipped), and the apply must send the previewed
  count back (`expected`): a different count is 409 `count_changed` (the set moved since the preview).

## Tradeoffs

- Hourly refresh instead of a refresh inside every line / option write: system tags lag up to an hour after an AA line
  appears. Writing them inline would touch the hot Booking feed and builder paths; the tick already walks every agency.
- Coverage on read costs one facts query over the live trips (capped at 2000, the preview's cap) per call; the board
  calls it once per load.
