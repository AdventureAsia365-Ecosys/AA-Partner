## Decisions

- **The BYO errata wins over the card text.** The Linear checklist still says "`allow_platform_sender` opt-in,
  owner-only, logged" and "send-as Gmail + Outlook". Errata S247 §1 removes `allow_platform_sender` (no
  `tenant_settings` column is added, and none exists), sender kinds are `agency_mailbox | system` only (CHECK
  `message_sender_kind_chk`), and send-as is **Gmail + Microsoft 365 + SMTP** (send only, no IMAP).
- **Key crm-015, Guard 0 needs crm-014.** `crm.erase_held` and `crm.erase_subject` are the crm-014 text plus the mail
  steps (a scripted, exact-match patch of the crm-014 text, so nothing of crm-012/013/014 is dropped); Guard 1 checks
  that every table an earlier key taught `erase_subject` is still named. SQLSTATEs **CRM28–CRM30** are this file's:
  CRM28 `message_not_deletable`, CRM29 `message_sealed`, CRM30 `mailbox_credential_mismatch`. The next key starts at
  CRM31.
- **Credentials per member.** Design §4.6 gives every role `OWN_MAILBOX_CONNECT`, but crm-003 had
  `UNIQUE (tenant_id, provider)`. crm-015 adds `integration_credential.member_id` (NULL = agency-level) and replaces the
  key with `UNIQUE NULLS NOT DISTINCT (tenant_id, provider, member_id)`: the agency still has at most one agency-level
  credential per provider (the crm-003 test that a second `stripe_key` is refused still holds).
- **One sending mailbox per member** (`channel_account_member_uq`, NULLS NOT DISTINCT: one agency-level one too). A
  reconnect updates the row (kind may change, e.g. Gmail -> SMTP). The DB checks the credential is the same member's
  and of the right provider (CRM30), and a `connected` mailbox has a credential. Disconnect = status `disconnected`
  first, then the credential row is deleted (`credential_id` ON DELETE SET NULL); the mailbox row stays as history.
- **`dispatch_queue.message_id`, not an FK on `message_ref`.** The plan asked for `dispatch_queue.message_ref ->
  crm.message`. AA-943 (crm-012, `app/intake/stage2.py`) already writes the Stage 2 `client_link` id into
  `message_ref`, so that FK would fail VALIDATE on Dev and every later Stage 2 send. crm-015 adds a separate
  `message_id` (same-agency key, ON DELETE SET NULL, NOT VALID + VALIDATE) and keeps `message_ref` as the generic
  reference. Gate codes added: `held_reconnect` (card R), `send_failed`, `no_message` (a row with nothing to send, e.g.
  rows queued before CRM-17).
- **Unmatched = both `traveler_id` and `trip_id` NULL.** A mail matched by the trip token from an unknown sender (a
  spouse) is on the trip, not Unmatched.
- **Drafts are rows** (`draft_autosaved`); crm_app may hard-delete a draft only (CRM28). Anything that is not a draft
  keeps its content (CRM29); Undo / "edit a held message" moves it back to `draft_autosaved` first.
- **`trip.mail_token`**: 12 hex characters from `gen_random_uuid()` (48 random bits, built in, no pgcrypto), a column
  default, so every existing and new trip has one; unique per agency. It is a reference, not a secret (the client sees
  it in the subject).
- **Erasure.** Trip and traveller scopes delete the messages of their conversations, then the conversations; a new
  scope `conversation` (the trash purge of an Unmatched thread); the agency erase deletes every mail table. Hold rule:
  `erase_held` reaches the travellers / trips a conversation names; `guard_held_change('trip_id', 'traveler_id')` on
  `conversation`; `crm.guard_message` checks a message through its conversation (no denormalised trip / traveller on
  `message`, so linking an Unmatched thread later does not need to rewrite its messages).
- **Attachments** are `crm.document` rows (docs DEK) with `uploaded_by_kind = 'mail'` (CHECK widened). `crm.document`
  needs a trip or traveller, so an Unmatched mail's attachments are not kept (`attachment_notes` code `no_subject`),
  nor oversized / unsupported ones (`too_large`, `type_not_allowed`); the UI shows the note.

### Code (S3–S6)

- **No poll job kind.** The plan had `crm_mail_ingest_poll` queuing one `crm_mail_ingest` per object key. An S3 key is
  not an id, so it cannot enter `crm.job` (payload guard, DM-6.3). Instead a maintenance hook (`MailIngestScan`) lists
  `raw/` once a minute (one key) and queues **one** `crm_mail_ingest` per UTC minute only while something waits; the job
  lists and processes up to 50 objects itself. Nothing is queued ahead (deploy gate / DB Migrate idle check).
- **No `httpx`.** Gmail and Graph are two JSON calls each; `app/mail/providers/http.py` uses stdlib `urllib` in a
  thread, like `app/fx/fetch.py`. No new dependency to pin and audit; tests inject a transport.
- **OAuth state without a server-side store.** The state is the (provider, scope, member, nonce, expiry, PKCE
  verifier) JSON sealed with the agency's `mail` DEK, AAD bound to (agency, `oauth_state`, `state`, member). Another
  member or agency cannot complete it (decrypt denied, on record); it expires after 10 minutes; a replayed code is
  refused by the provider. The plan's "stored server-side 10 min" would have needed a table (and a DM-7 row).
- **ID token for the mailbox address** (`openid email` scopes): `gmail.send` alone cannot read the profile. The claim is
  read without a signature check because it comes straight from the token endpoint over TLS (OIDC Core §3.1.3.7).
- **Graph send uses the MIME endpoint** (`me/sendMail`, base64 MIME): one message builder for all three providers.
  Graph returns no id and may replace our Message-ID; References carries ours (S252 fix below), the subject trip tag
  is the second net.
- **Sender outcome codes.** The crm-010 `Sender` returned `None`; it now returns `sent | held_reconnect | no_message |
  send_failed` and the dispatcher maps them (held / held / dropped). A dropped row's message becomes `failed` with the
  gate code. Transient provider errors raise, so the job retries (5 attempts).
- **Owner alert once per disconnect**: only when the mailbox newly moves to `disconnected` (an UPDATE ... RETURNING),
  through the existing `mail_owners` helper (partner pool owners, best effort).
- **Permissions reuse existing actions** (no new matrix rows): own mailbox `OWN_MAILBOX_CONNECT`, agency mailbox
  `INTEGRATIONS_MANAGE`, read threads `TRIP_VIEW`, drafts `TRIP_EDIT`, send / undo `MESSAGE_SEND` (assistant: ASSIGNED =
  trip owner), link `CLIENT_EDIT`, agency-wide saved replies `WORKFLOW_EDIT` (the agency's templates), import
  `OWN_MAILBOX_CONNECT`. On OAuth complete the scope sealed in the state is re-checked.
- **Attachments are written with the row.** A stored message is sealed (CRM29), so attachments are kept before the
  INSERT; a Message-ID already stored is detected first (no conversation or document is made for a duplicate).
- **`MailIngestDropped`** is published by the existing job-metrics sampler into `AA/Jobs/Crm` (the only namespace the
  task role may write) from a per-process counter: no IAM change.
- **Web callback has no side effect.** `/connect/mail/callback` only redirects to Settings > Mailbox with code + state;
  the page completes through the BFF (same-origin write guard). A GET with a side effect could be triggered by a
  sibling host (it.com is a public suffix, AA-911).
- **SSRF guard on SMTP**: the agency names the SMTP host, so `require_public` refuses a host that resolves to a
  private, loopback, link-local (instance metadata), reserved or multicast address (422 `smtp_invalid_host`).
- **SES scan verdicts**: `X-SES-Spam-Verdict` / `X-SES-Virus-Verdict` = FAIL -> dropped like an unknown address. SPF /
  DKIM verdicts are ignored (forwarding breaks them).
- **Stage 2 link mail**: AA-943's planning-form dispatch rows carry a `client_link` id in `message_ref` and no message,
  so the sender answers `no_message` (held). Making the Stage 2 send compose a real `crm.message` (with the link in the
  body) is a follow-up.

### Review round (S250, independent review of the four PRs)

- **Blocker, `PUT /mailbox/smtp`**: the SMTP check ran before `tenant_tx` checked membership and the scope's
  permission, so any signed-in partner user could make the API dial any host and port (a port / SMTP-login oracle
  through AA's IP). The route now opens a `tenant_tx` that only authorises, then checks the login outside any
  transaction, then opens a second `tenant_tx` to store. Route test: an agent with `scope=agency` and a non-member get
  403 and the fake provider's `check` is never called.
- **SMTP DNS rebinding**: `require_public()` returns the vetted address and `connect()` opens the socket to it
  (`_PinnedSMTP` / `_PinnedSMTPSSL` override `_get_socket`); `self._host` stays the name, so STARTTLS / implicit TLS
  still send SNI and check the certificate against the name. Ports are limited to 25 / 465 / 587 / 2525
  (`smtp_invalid_port`). Tests: a resolver that answers public then private is called once and the socket goes to
  the public address; implicit TLS wraps with `server_hostname` = the name.
- **Refresh-token rotation**: `OAuthMailProvider.access_token()` returns the rotated credential;
  `SendResult.rotated_secret` and `check()`'s return carry it; `app.mail.sender.store_rotated()` seals it again
  (`encrypt_secret`) on send, on the nightly check and on the Test button (which now sends with the credential that is
  current after its check).
- **Poison raw objects**: any exception from `parse()` deletes the object (`unparsable`); a read or store failure keeps
  it until it is older than `POISON_AGE` (1 hour, from S3 `LastModified`), then drops it (`failed_permanent` +
  `MailIngestDropped`). The job pages with `StartAfter` past objects that failed in this run (at most `MAX_PAGES` = 5
  listings, `BATCH` = 50 handled), so 50 bad objects never block new mail. New `IngestStore.list_objects()`.
- **Spoofed own-mailbox From**: the forward-in local part has 64 random bits (`token_hex(8)`; fits the crm-015 CHECK,
  no migration change). A mail From one of the agency's mailboxes is stored as the agency's sent copy only when
  `ParsedMail.sender_authenticated` (SES spam + virus PASS, and SES's own topmost `Authentication-Results:
  amazonses.com` has `dkim=pass` for the From domain or a subdomain, or `dmarc=pass header.from=<From domain>`), or for
  a history import (the member's own export). Otherwise it is inbound and the own-mailbox lookup is not made.
- **History import**: one job per `SLICE` (500) messages; payload `batch` (a payload-guard control key) = the slice;
  each slice skips the earlier messages (mbox keys are skipped without parsing) and queues the next slice
  (idempotency key `crm_mail_history_import:<id>:<n>`; slice 0 keeps the old key). Counts are added
  (`total_count = total_count + $2`), so slices never overwrite each other. The last failed attempt marks the import
  `failed` / `import_failed` and deletes the object. `EXPECTED_SECONDS` for the kind: 900 -> 120.
- **Nits applied**: the recipient comes only from the topmost `Received` header when SES wrote it
  (`by inbound-smtp.<region>.amazonaws.com`), else the forwarding headers then To / Cc; attachments and the threading
  run in a savepoint with the message insert and the S3 puts happen only after the row is in (a duplicate race leaves
  no document row, no conversation and no file); the dispatcher runs the sender in a savepoint and, on the job's last
  attempt, drops the row `send_failed` and fails the message `retries_exhausted` instead of leaving both `queued`.

- **Web (review round)**: `htmlFrame` puts a CSP `<meta>` (`default-src 'none'; img-src data: cid:; style-src
  'unsafe-inline'; font-src data:`) ahead of the mail's markup, so "show formatted" loads nothing remote (no read
  receipt, no agent IP); the SMTP error keys match the API (`smtp_unreachable`, not `smtp_smtp_unreachable`, plus
  `smtp_temporary`, `smtp_provider_rejected`, `smtp_invalid_port`, `smtp_missing_*`, EN and VI); the SMTP port is a
  select of the four ports the API dials.

### S252 fix: Gmail replaces the Message-ID (branch `fix/aa-945-provider-message-id`)

- **Live finding (S252 Dev evidence run)**: mail A sent through the connected Gmail mailbox reached the client with
  `Message-ID: <CAKnvzAQx-...@mail.gmail.com>`, not the `<...@gmail.com>` id `compose.build` generated, hashed and
  stored (`sender.py` `SENT_SQL`: `rfc_message_id_hash = id_hash(built.message_id)`). Probe R2 (In-Reply-To /
  References = the id the client received, no trip tag) found no stored hash in `threads.BY_HEADER_SQL` and went to
  Unmatched; R1 (trip tag) threaded. So `users.messages.send` replaces a client-supplied Message-ID; the code and
  docstrings had assumed "Google keeps our Message-ID". Graph `sendMail` may do the same and returns no id.
- **Decision: References ends with our own Message-ID** (`compose.build`: `References: [<client's latest>] <ours>`).
  Providers keep References as written, and a reply's References = the parent's References + the parent's
  Message-ID (RFC 5322 §3.6.4), so the client's reply carries the id the CRM stored and rule 1 (`reply_header`)
  matches. No schema change (the stored hash stays the generated id, so SMTP / In-Reply-To-only replies match as
  before), no new scope, no threading or ingest code change.
- **Rejected**: (a) reading Gmail's id back with `users.messages.get format=metadata` after the send needs
  `gmail.metadata` / `gmail.readonly` (restricted scopes, re-consent of every mailbox, Google verification); Graph has
  no id to read at all. (b) a separate marker id in References would need a second stored hash (column + migration) and
  would drop the In-Reply-To-only match SMTP has today. (c) the subject trip tag already exists (card E); it cannot
  help a mail program that drops or rewrites the subject.
- **Order**: our id is last, not first. JWZ-style threading links References in order and makes the last one the
  parent; a self-reference is a loop it skips, so the client's mail stays A's parent in the client's mail app. First
  would make A the parent of the client's mail.

## Tradeoffs

- Sender authentication trusts the **topmost** `Authentication-Results` only when its authserv-id is `amazonses.com`.
  If SES ever left that header out, a sender's own header would be topmost; the 64-bit address is the remaining
  guard. The SES verdict headers are required too.
- A retried import slice re-reads its messages: the stored ones count as duplicates, so `total_count` can count a
  retried slice twice. Imports are idempotent (no double rows); only the counter may be high after a retry.
- When SES leaves out `for` (several recipients) only one agency gets the mail (the first crm-in address in the
  forwarding headers / To / Cc). Rare on Dev; an SNS action with the true envelope is the follow-up if it matters.

- `message_external_id_uq` is per agency + channel, not per mailbox: provider ids are globally unique in practice
  (Gmail / Graph ids), and a per-mailbox key would break when a mailbox row is reconnected with another kind.
- The ingest-address lookup policy is SELECT only, like `intake_form_public_lookup`: the job writes the forwarding
  code only after `ingest_tx` has set `app.tenant_id`.

- S252 References fix: a self-reference in References is unusual (RFC 5322 lists ancestors); JWZ threading skips it
  as a loop. Some mail programs trim a long References to the first and last few ids; ours is the second-to-last in
  the client's reply, so it survives the usual trimming. A mail program that keeps only In-Reply-To still misses when
  the provider replaced the id; the trip tag covers that. The agency's own Gmail copy (history import / BCC) carries
  Gmail's id, so it is not deduplicated against the sent row (same as before the fix); it now threads to A by header.

## History import UI (S252, 26/10/2026)

Branch `feat/aa-945-history-import-ui`. Closes follow-up (b) of "Should know" above: the mbox / CSV upload is no
longer API-only. Agent: Claude Code (subagent).

### Decisions

- **Where**: a fourth panel "Import mail history" on Settings > Mailbox (`web/components/mail/MailImport.tsx`, pure
  helpers in `web/lib/mailImport.ts`), shown to every role (the API's `OWN_MAILBOX_CONNECT`).
- **Through the BFF, raw bytes.** New allow-list line `POST mail/imports` with `raw: true` (`lib/bff.ts`): the route
  reads the body as bytes (`lib/bffBody.ts readCapped`, stops reading past 25 MiB -> 413 `body_too_large`), refuses a
  declared Content-Length over the cap before reading, refuses a body shorter than its Content-Length (400
  `body_incomplete`), sends it as `application/octet-stream` with the session's token and agency, and forwards the
  `?source_kind=` query. Upstream timeout 120 s for this route (the API writes the object to S3 inside the request).
  A JSON route still reads `request.text()` (a binary mbox through `text()` would have been re-encoded).
- **`/bff/mail/imports*` is outside the proxy matcher** (`web/proxy.ts`). Next clones the body of every request the
  proxy runs on and, past `proxyClientMaxBodySize` (10 MiB), **silently cuts it** (a console warning, no error; the
  route sees a short body). Raising the limit to 26 MiB for every path was the other option (rejected below). Because
  the proxy's host check no longer runs for these paths, the BFF route repeats it (non-partner host -> 404). The
  matcher is a literal Next reads statically; `tests/mailImport.test.ts` checks it against `UNPROXIED_BFF_PREFIX`.
- **No list endpoint, no backend change.** The panel remembers the imports this tab started (ids and kinds only, no
  file name: sessionStorage `crm.mailImports`, at most 5) and re-polls them after a reload. Adding
  `GET /mail/imports` was not needed for the flow.
- **Upload with XMLHttpRequest** (`uploadImport`), not fetch: only XHR reports upload progress (a 25 MB file over a
  slow link takes a while). A 401 reloads through `/auth/refresh` like `bffSend`.
- **Kind from the name**: `.csv` -> csv, `.mbox` / `.mbx` -> mbox; anything else (Thunderbird folder files have no
  extension) defaults to mbox with a "check the type" hint; the select overrides it.
- **Polling**: every 3 s, one call at a time; stops on `done` / `failed`, on any 4xx (e.g. 404
  `mail_import_not_found` when the agency was switched), or after 5 failures in a row (network / 5xx), then says so.
- **Errors**: any 413 (BFF `body_too_large` or API `import_too_large`) -> the size text; known codes
  (`empty_upload`, `invalid_source_kind`, `mail_ingest_not_configured`, `mail_import_not_found`, `role_forbidden`,
  `api_timeout`, `api_unreachable`, `body_incomplete`) -> their EN / VI text; an unknown 4xx -> the API's own
  `message` as is; else the generic text. A failed import's `error_code` (`csv_columns`, `bad_payload`,
  `import_failed`) has its own explanation.

### Changed

- `lib/bff.ts`: `BffRoute.raw` / `timeoutMs`, `MAIL_IMPORT_BODY_BYTES`, `UNPROXIED_BFF_PREFIX`, `upstreamHeaders(...,
  raw)`. `tests/mail.test.ts` now expects `POST mail/imports` on the list (19 AA-945 lines);

- `CONTEXT.md` (mail section): the upload is no longer "API only in v1".

### Tradeoffs

- **Matcher exclusion vs `proxyClientMaxBodySize: "26mb"`**: the global limit would make every path of the partner
  host buffer up to 26 MiB per request before the session gate (the web task has 512 MB) and buffer the upload twice
  (proxy clone + route). The exclusion keeps the 10 MiB default elsewhere and holds the file once; the price is the
  host check written twice (proxy and BFF route) and a matcher literal to keep in step (tested).
- The route still holds the whole file (<= 25 MiB) in memory before forwarding it, instead of streaming it on: simpler,
  lets the BFF refuse a short body, and the API reads it whole anyway.
- Imports started in another tab or browser are not listed (no list endpoint); the API keeps the rows, and a later
  `GET /mail/imports` would let the panel show them all.

### Review round (S252, PR #88, independent review: changes requested)

- **Memory per upload**: `readCapped` returns `new Blob(chunks)` (no concatenated copy) and the Blob is the upstream
  fetch body (undici streams it with its Content-Length); the short-body check uses `blob.size`. About one copy of the
  file per upload instead of three (~75 MB peak per 25 MiB file before).
- **At most 2 raw uploads in flight per web process** (`MAX_RAW_IN_FLIGHT`, `lib/bff.ts`): a third gets 503
  `upload_busy` + `Retry-After: 10` before its body is read; the slot is held through the upstream call and freed in
