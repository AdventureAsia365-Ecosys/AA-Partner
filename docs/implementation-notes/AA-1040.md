# AA-1040 — AI-assisted label in Content studio, AI mark on CRM drafts (AA-Partner)

Lane l6-ai-marking, S266. Kit part (the `form="badge"` of the kit `AiNotice`, the `narration` variant) and the CIS
marking of pieces: AA-CIS-App `docs/implementation-notes/AA-1040.md` and `AA-1040-marking.md`.

## Decisions

- **Content studio label:** the kit badge, never a local pill (ADR 0016). Placed under the channel badge of each My
  Content row and each Published row (stacked, so the column grows to the badge width only, ~90 px, not by its
  width plus the channel's), in the piece drawer title next to the channel, and on each publish card under the title.
  The line notice (`publisher` variant) at review, publish and export from AA-1033 stays: the badge labels each piece,
  the line says what it means.
- Every piece is AI output, so the badge needs no API field; it always shows.
- **CRM draft mark:** `POST /crm/v1/trips/{id}/ai/draft` answers `ai: {ai_generated: true, generator, generated_at}`
  when there is model text (else null). The model is not repeated: the gateway result does not carry it and the
  ledger row (`llm_call_id`) already does; adding it to `GatewayResult` would touch the gateway for no reader. The
  web's draft text element carries `data-ai-generated`, `data-ai-generator`, `data-ai-generated-at` (DOM mark beside
  the staff notice).
- Messages sent after copying a draft are the member's own text (a person reviewed and sent it: "AI drafts, humans
  send", R39); `crm.message` gets no mark and no migration.

## Tradeoffs

- Per-row badge vs only the page-level line: Art. 50 asks that AI content be identifiable as such; a per-row label
  travels with the piece in screenshots and exports of the list, at the cost of one small pill per row.
