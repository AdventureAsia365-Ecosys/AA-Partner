# AA-1030 — Agency price tiers (CRM side: suggested retail price)

Lane l9 of S269. The Booking half (tiers, discounts, contract rate cards on the B2B price) is in AA-Booking
`docs/implementation-notes/AA-1030.md`; this file covers the CRM. Root ADR 0019 b15: RRP = net + 25 %, agency tiers
0 / 3 / 6 %. S265 re-scope on Linear: "the CRM's suggested retail price defaults to the RRP from AA-1029; the agency's
own markup override and the below-'from' warning stay."

## Decisions

- **Where the markup lives.** `crm.tenant_settings.retail_markup_pct` (JSONB `{kind: percent}`, crm-046), not a new
  table: a per-agency setting next to the other agency settings, erased with the agency (no `crm.erase_subject`
  change, no tenant-table template, no new DM-7.1 row). The shape is a DB rule (`crm.retail_markup_ok`, like
  `crm.call_slot_rules_ok`) plus the API's own 422.
- **Product types** = Booking's component kinds (`trip_plan`, `hotel_room`, `transfer`, `guide`, `activity`,
  `entrance`, `meal`), the `component_kind` an AA option already stores.
- **Suggestion rule** (`app/proposals/retail.py`): the agency markup on the B2B price (`option.net_amount`, already
  with the agency's tier / rate card from Booking), rounded up to the cent; else AA's RRP x party for a tour; else no
  suggestion. Computed at read time in the builder view, so it follows each re-quote with no stored column.
- **Prefill.** An owner or agent adding an AA option without a sell gets the suggestion as its sell (the "suggested
  on new AA options" ask). An assistant's add keeps the old rule (sell 0, Publish waits for an owner / agent): the
  assistant cannot see B2B prices, and a markup-based price would reveal one.
- **Visibility.** The markup and a markup-based suggestion are margin data: Settings > Payments is owner only (API
  `PAYMENT_SETTINGS`), and the view hides an `agency_markup` suggestion from the assistant. An `aa_rrp` suggestion is
  AA's public price and is shown to every role.
- **Below-"from" warning** unchanged: it is computed on whatever sell the option has, the suggested one included.
- **No markup default in code.** Without an agency markup a tour suggests AA's RRP (Booking's 25 % policy data); other
  product types suggest nothing (question 5 in the Booking notes asks the business owner).

## Tradeoffs

- A JSONB column instead of a typed table: one row per agency already exists, seven numbers do not need their own
  table, and the erase / template / retention rules stay untouched. The cost is a DB function for the shape.
- Read-time suggestion instead of a stored `suggested_sell` column: no ALTER of `crm.option` and always current; the
  builder view does one extra read of `tenant_settings` when the draft has AA options.
