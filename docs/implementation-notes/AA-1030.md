# AA-1030 — Agency price tiers (CRM side: suggested retail price)

Lane l9 of S269. The Booking half (tiers, discounts, contract rate cards on the B2B price) is in AA-Booking
`docs/implementation-notes/AA-1030.md`; this file covers the CRM. Root ADR 0019 b15: RRP = net + 25 %, agency tiers
0 / 3 / 6 %. S265 re-scope on Linear: "the CRM's suggested retail price defaults to the RRP from AA-1029; the agency's
own markup override and the below-'from' warning stay."

## Decisions

- **Where the markup lives.** `crm.tenant_settings.retail_markup_pct` (JSONB `{kind: percent}`, crm-046), not a new
  table: a per-agency setting next to the other agency settings, erased with the agency (no `crm.erase_subject`
  change, no tenant-table template, no new DM-7.1 row). The shape is a DB rule (`crm.retail_markup_ok`, like
  `crm.call_slot_rules_ok`) plus the API's own 422.
- **Product types** = Booking's component kinds (`trip_plan`, `hotel_room`, `transfer`, `guide`, `activity`,
  `entrance`, `meal`), the `component_kind` an AA option already stores.
- **Suggestion rule** (`app/proposals/retail.py`): the agency markup on the B2B price (`option.net_amount`, already
  with the agency's tier / rate card from Booking), rounded up to the cent; else AA's RRP x party for a tour; else no
  suggestion. Computed at read time in the builder view, so it follows each re-quote with no stored column.
- **Prefill.** An owner or agent adding an AA option without a sell gets the suggestion as its sell (the "suggested
  on new AA options" ask). An assistant's add keeps the old rule (sell 0, Publish waits for an owner / agent): the
  assistant cannot see B2B prices, and a markup-based price would reveal one.
- **Visibility.** The markup and a markup-based suggestion are margin data: Settings > Payments is owner only (API
  `PAYMENT_SETTINGS`), and the view hides an `agency_markup` suggestion from the assistant. An `aa_rrp` suggestion is
  AA's public price and is shown to every role.
- **Below-"from" warning** unchanged: it is computed on whatever sell the option has, the suggested one included.
- **No markup default in code.** Without an agency markup a tour suggests AA's RRP (Booking's 25 % policy data); other
  product types suggest nothing (question 5 in the Booking notes asks the business owner).

## Tradeoffs

- A JSONB column instead of a typed table: one row per agency already exists, seven numbers do not need their own
  table, and the erase / template / retention rules stay untouched. The cost is a DB function for the shape.
- Read-time suggestion instead of a stored `suggested_sell` column: no ALTER of `crm.option` and always current; the
  builder view does one extra read of `tenant_settings` when the draft has AA options.

## Tariff download (S270, lane aa1030-crm-tariff)

The CRM half of G3: the agency reads and downloads its own AA tariff (booking.b2b.v1 1.4 `GET /tariff`, Booking #192).
No migration, no Booking change.

### Decisions

- **Role.** New matrix row `Action.AA_TARIFF_VIEW` = (allow, allow, deny): owner and agent, the assistant 403
  `role_forbidden`, the same cells as `VIEW_MARGIN` (S270 default; the tech lead may make it owner only by changing the
  agent cell of this one row). A separate action rather than reusing `VIEW_MARGIN` so that switch never touches margin.
  `tests/unit/test_permissions.py` pins the row and asserts the tariff is never wider than `view_margin`.
- **Why the action is the guard.** `app.margin.MARGIN_KEY` (`(^|_)(net|b2b|cost|margin|commission)(_|$)`) does not
  match Booking's key names `price` / `price_per_person` / `agency_discount_pct` / `rrp_per_person`, and the CSV bytes
  never pass the JSON serializer. So the route is closed by `tenant_tx(action=AA_TARIFF_VIEW)` before Booking is called.
- **Key rename (defence in depth).** The CRM JSON names the B2B amounts `b2b_price` / `b2b_price_per_person`, which
  `MARGIN_KEY` matches: if the action were ever widened by mistake, the serializer would still strip them for a role
  without `view_margin` (unit test). `agency_discount_pct` and AA's public `rrp_per_person` keep their names.
- **One CSV shape.** `format=csv` asks Booking for its file (`Accept: text/csv`, `format=csv`) and passes the bytes on
  unchanged (Booking's `tariff.CSV_COLUMNS`), with Booking's file name when it is a plain `[A-Za-z0-9._-]+.csv` name,
  else `aa-tariff-<currency>-<date>.csv`. The CRM never builds the file again.
- **Client.** `BookingClient._call` was split into `_send` (token, agency header, 401 drops the cached token, 5xx /
  408 / 429 -> `BookingUnavailable`, other non-2xx -> `BookingRefusal`) and the JSON `_call`; `tariff_csv` uses `_send`
  with `accept="text/csv"`, so both calls share every failure rule. A 2xx that is not `text/csv` is `booking_contract`.
- **Parser.** `contract.tariff(data, currency)` in the tolerant-reader style; a row that breaks the contract fails the
  whole read (503), never a half-shown tariff; an answer in another currency than asked is a contract break.
- **Audit.** One `aa_tariff_view` event per read: object = the currency, reason = `format_json|csv`, the tour asked for
  as object id (only when it is a safe id); never an amount.
- **Web visibility.** `/me` answers `permissions.aa_tariff_view` (the API's own matrix), and the web hides the page's
  links (Settings, the builder's AA drawer) and shows the forbidden state without calling the API when it is false.
  An older API without `permissions` falls back to owner / agent.

### Error mapping

| Booking | CRM |
|---|---|
| refusal `unknown_partner` / `forbidden` (no B2B partner row, or suspended) | 409 `aa_partner_not_active` ("not linked to AA B2B, or suspended") |
| refusal `invalid` (not a quote currency) | 422 `aa_tariff_invalid` |
| any other refusal | 422 `aa_tariff_refused` (`aa_code` = Booking's code) |
| down, 5xx, 408, 429, token failure, contract break, CSV that is not one | 503 `booking_unavailable` + `Retry-After: 60` |
| no Booking client configured | 503 `booking_not_configured` |

Every answer (JSON and CSV) carries `Cache-Control: no-store`; the BFF sets it too.

- The Print button uses the browser's print with print CSS (shell, toolbar hidden; the table unpaginated) instead of
  a PDF route: no new dependency, and the CSV is the file to keep.
