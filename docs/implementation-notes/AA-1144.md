# AA-1144 — Agency lines limited to flight, visa, insurance and fee; catalogue supply stays AA-only

Lane l12 of session S285 (19/11/2026). Business rule of 19/11/2026 (S285 decisions B5, B6, B9, B10, B11, T19): every
product is Adventure Asia's and its suppliers'; agencies only use the apps. Root ADR 0019 b6 is amended in the root
repo in the same wave. Advisories: root `docs/audits/2026-11-19-S285-session/advisory-crm-agency-extras.md`,
`advisory-r2-b2b-crm.md` (B10, T18, T19), `advisory-r2-plan.md` (slice L1).

## Decisions

- **Item codes stay `insurance` and `fee`.** The lane brief names the list "flight, visa, travel_insurance,
  agency_fee"; the database, the catalogue and the AI supplier confirmation already say `insurance` and `fee`, so the
  codes stay and the UI words say "Travel insurance" and "Agency service fee". Renaming the codes would touch three
  CHECKs, the catalogue rows and the AI stage for no behaviour change.
- **`category` on `crm.option` and `crm.booking_line`, NULL allowed.** CHECK: NULL, or an agency row of the closed list.
  NULL stays legal for AA rows and for the agency rows made before crm-080 (they stay readable and editable; a working
  copy of an older version copies them as they are). The API requires a category on every NEW agency option and line;
  the database does not (an INSERT-only trigger would break the working copy of an older version).
- **Agency items sit on an Other block only.** No new block type: `other` already exists, and a new `extras` type would
  widen another CHECK and touch every block label. A lodging / activity / transport / meal / guide block takes AA items
  only; a block holding agency items cannot be re-typed (the same 422). An older agency option on a lodging block stays
  and can still be edited (price, title): only adding a new one is refused.
- **"other" is a supplier category, never an item type.** It covers the agency's own fee and a consolidator. An agency
  line or option typed `other` (or `transfer`) is 422 `invalid_category`.
- **T19 data step**: counts first (two NOTICE lines: before and after), never DELETE. Own suppliers of a blocked category
  (accommodation, transport, activity, guide, restaurant, dmc) become `other`; the ones nothing references (options,
  booking lines of any state, supplier bills, departure costs, AA invoice rows, catalogue services, supplier request
  threads) go to the trash with `deleted_by = 'migration:crm-080'` and the agency's own `trash_days` (else the platform
  default of `crm.agency_defaults.trash_days`), so they are restorable from Trash until `crm_lifecycle` purges them. A
  row that anything names stays live as `other` (old proposals, bills and costs read as before; a purge would cascade
  bills and costs). Live `transfer` catalogue services go to the trash too; the CHECK keeps a trashed transfer row legal
  (the catalogue has no restore path, so they stay hidden).
- **Per agency under FORCE row security**: the owner sees one agency at a time, so the file loops over
  `crm.audit_export_tenant` (RLS not forced) and sets `app.tenant_id`. An agency under an active legal hold with rows to
  change stops the file with the count (the hold guard would refuse the UPDATE). The narrowed CHECKs validate every
  row whatever the row security, so a missed agency fails loudly.
- **B11 "Ask AA for extra nights"**: no existing request mechanism fits (the AA request queue is Booking's outage queue
  tied to a line; the CIS add-on request is for products). A small table `crm.aa_extra_night_request` (place, before /
  after, check-in, nights, rooms, adults, children; open -> closed quoted / not_needed), the ops check
  `aa_extra_nights_requested` (one AA ops e-mail per request, like `ops_release_withdrawn`), and a read-only list on the
  staff console's Ops page (group `crm-ops`, `ops_tx`, no personal data). The staff class stays read-only (AA-971): AA
  answers the agency and makes the hotel bookable in Booking; the agent closes the request.
- **Bounds are the CHECK bounds** (nights 1..60 like `option.aa_nights`, rooms 1..30 like the room list, place 1..80):
  technical limits of the row shape, not business thresholds, so they are not settings.
- **B6 Facts Entries** live in the CIS facts API (AA-814): this lane restricts the Partner studio UI (new facts and "Use
  my own" only for `price` and `booking_terms`) and, after review, the tenant proxy
  (`web/app/api/tenant/[...path]/route.ts` -> `lib/studio/facts.ts` `factWriteRefusal`): `POST v1/facts` of another
  kind (or none: CIS would store `other`) and a `PATCH v1/facts/{id}` that sets another kind (or null) get 422 with a
  plain message before CIS; a body the proxy cannot read as a JSON object gets 400, so what passes is what the check
  saw. An edit that leaves the kind alone and a delete still pass (older facts stay editable and deletable).
- **CIS follow-up (to file, AA-CIS-App, not in this lane):** (1) the CIS facts API refuses a tenant fact whose kind
  is not `price` / `booking_terms` (create, and a patch that sets the kind); (2) the agency's existing own facts of
  tour kinds are retired or the writer stops letting them override Adventure Asia facts. The orchestrator files it
  with the tech lead's yes (Linear rule: ask before a new issue); its id goes here when it exists.

## Changed

- crm-080 (contract): two category columns + CHECKs, `crm.aa_extra_night_request` (base template, status transition,
  hold guard, crm_app SELECT / INSERT / UPDATE), the T19 data step, the narrowed `agency_supplier_category_chk` and
  `agency_service_category_chk`. Readiness `crm-080` in the code PR.
- API: `app/ledger/agency_items.py` (the list and the refusals), builder (`add_agency_option`, `update_block`, copy and
  view carry `category`), lines (create needs `category`, patch takes it, view shows it; `update_line` validators moved
  to a table, complexity 19 -> 14), suppliers, catalogue (`plan_option` carries the service category), AI supplier
  confirmation (no `transport`), `app/booking/extra_nights.py` + routes in `app/routers/ledger.py` and
  `app/routers/staff_ops.py`, the ops check.
- Web: the drawer offers the agency / catalogue tabs on an Other block only, with an item type select;
  `AgencyBlockNote` (the note on AA-only blocks, "Ask AA for extra nights" on a lodging block); the Bookings tab's add
  form asks the item type; the supplier form defaults to Flight; the catalogue lists four types; the staff Ops page
  lists the open extra-night requests; the studio's Facts form offers price and booking terms only, and the tenant
  proxy refuses a facts write of another kind (review fix).
- Tests: fixtures that typed hotel / transport / activity suppliers now type flight / other; the shared builder helper
  `_option` turns the block into an Other block and types the item a fee; the rule-5 tier test uses AA hotel rooms.

## Tradeoffs

- Keeping NULL legal means old Dev drafts still show agency hotels until they are re-made; refusing them in the
  database would break the working copy of every older version. The UI no longer offers the path.
- The agency fee needs a supplier on a booking line until the next slice makes the supplier optional ("Agency does
  it itself"); an `other` supplier stands in.
- The staff side cannot answer inside the CRM yet: an answer path (a staff write) would change the read-only staff
  class; the e-mail and the list are enough until AA ops ask for more.
