# AA-1008 — agency app on the kit ShellFrame, visual job, empty kit suppressions (AA-Partner part)

Lane l3 of S269 (Claude Code). The ShellFrame, the Tabs roles, the Modal `pinFooter` layout and the DataTable
`rowTestId` are built in AA-CIS-App (the canonical kit; its `docs/implementation-notes/AA-1008.md`). This file covers
the AA-Partner web (the CRM and, since AA-1036, the Content studio). H3 (required checks in branch protection) is not in
this lane: it needs the tech lead's GitHub sign-in.

## Decisions

- **Shells.** `CrmShell` and the studio's `PortalShell` are configurations of the kit `ShellFrame` (drawer below 900 px,
  the CRM on the document scroll model). Their markup hooks (`data-crm`, `data-pshell`) stay, so the studio smoke
  specs keep working.
- **Suppressions to `{}` by fixing, not deleting.**
  - The studio legacy layer `app/(studio)/portal/_components/ui.tsx` is deleted. What the kit has went to the kit
    (EmptyState, Field + Input / Textarea on the brand form, `K` in place of the `T` alias object); what it has no twin
    for (the card and its head, the progress bar, the sticky card header, the in-card link, the primary-look CTA link)
    moved to the local kit layer `app/_kit/local/studio/StudioCard.tsx`, on `K` tokens. The legacy module path stays in
    `eslint.config.mjs` so it cannot come back.
  - Raw tables: the CRM bookings list, the trip ledger (desktop), suppliers, the data rules and the two team lists are
    the kit `DataTable`; the ledger rows keep `line-<id>`, suppliers `supplier-<kind>` (new kit prop `rowTestId`). The
    health page and the mailbox senders were key / value lists: a `<dl>` and a `<ul>`.
  - The stage-engine `Dialog` is the kit `Modal` with `pinFooter` (the S262 frame moved into the kit, the CSS
    `[data-crm-dialog]` block left globals.css). The builder's "+ Add" panel is inline, not a dialog: `role="group"`
    with `aria-pressed` source buttons.
  - Hard-coded colours: the board menu's shadow is `K.shadowMd`, the dialog scrim is the kit's.
  - `react-hooks/set-state-in-effect` / `refs`: state reset on a new prop during render (BoardView, UndoToast), set
    where the cause happens (PlanningForm index clamp, the bulk dialog's preview on a reason change), a lazy initial
    state (MailImport list, MailboxSettings OAuth error), fetch-then-set with a liveness flag (MessagesPanel thread,
    the bulk dialog's first preview), `latest` written in a layout effect and the autosave created after mount.
- **Visual run.** Per PR: `next build` + the standalone server in the runner with the Web Build smoke's fake
  configuration and `KIT_GALLERY=1`; public pages + the gated `/kit-gallery` (public path in `lib/hosts.ts`, 404 on a
  deployed build). After a green Deploy Web Dev on main: `workflow_run` (not a job inside `deploy-web-dev.yml`, whose job
  list a guard test pins, and so the sign-in happens after the studio smoke's), the changed pages on the agency host,
  CRM and studio pages signed in as the e2e studio user. A signed-in page the session is sent away from is reported
  "skipped (sent to …)", never passed. The deployed job checks out main, never a ref taken from the triggering run.
- **Overflow probe uses the configured viewport width**, not `window.innerWidth`: on a 390 px mobile emulation a page
  that overflows widens its layout viewport, so the old probe saw `doc == innerWidth` and passed. Found by this run on
  `/signed-out` (12 px, the language select); fixed in all three repos' specs and in `LocaleSwitch` (wraps, shrinks).
- Review fix (S269): the `deployed` visual job's first step refuses any host but the agency host
  (`https://portal.lumiguides.it.com` or `vars.CRM_WEB_BASE_URL`, trailing slash allowed) before the signed-in step
  can send the e2e studio password and a live TOTP code anywhere, like the CIS and Booking visual runs. Guard:
  `api/tests/unit/test_visual_workflow_hosts.py` runs the step's script with bash.

## Changed (vs the issue)

- "the portal and CRM web" are one app since AA-1036; "PR previews" became the in-runner build (ADR 0019 d23).
- One new message key pair (`suppliers.col.lines`, EN + VI): the suppliers table needs a header for the count column.
- `aa760-empty-states.spec.ts`: the Slate's empty state is the kit EmptyState now (`kit-empty-state`).
- `api/tests/unit/test_studio_guards.py`: the accent-colour allow-list names `K.sideBg` (the dark panel) instead of
  the retired `T.darkPanel`.

## Tradeoffs

- The kit `Modal` header differs from the old stage dialog (serif title, a close button); the S262 behaviour (title
  and footer in view, the body scrolls, the short-window mode, the more-below cue) is unchanged.
- The deployed run captures CRM pages only if the e2e studio user's session opens them; without a CRM membership they
  are skipped (named), not covered. A CRM E2E user for the visual run is a follow-up.

  --project=visual-390` (self-test: `VISUAL_SELFTEST=1`, then `node visual/summary.mjs --selftest`).
- Local result S269: 24 public + gallery captures, 0 findings; self-test 8 of 8 planted captures caught; vitest 895 pass.

  to the CIS branch core (review fix: the drawer slot height rule included).
