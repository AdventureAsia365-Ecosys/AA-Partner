# AA-970 — CRM-37b What's new, preview switch, help topics, public data pages

Design v3 card CRM-37b (R42, R43), scope after the S279 review: (1) a What's new feed (EN/VI) with a per-agency preview
toggle and a lint that fails if privacy or price logic sits behind a preview flag; (2) a public data page and a
sub-processor page rendered from the root DPA Annex 3, refreshed first; (3) more help topics beyond getting started.

## Decisions

- **The preview toggle is a settings-registry key, not a new table or a plan field.** `crm.release.preview` (crm-072,
  bool, `platform+tenant`, default off, maker-checker) is the design's `release_channel`: an AA administrator sets one
  agency's own value on CIS Platform > Settings (CRM tab), with the registry's audit, versions and reason. No plan name
  decides it (task rule), and the existing feature keys (`crm.tenant_entitlement.allowed_features`) are CIS
  projections of paid add-ons, not a release channel.
- **Who switches it:** AA, not the agency owner. A preview is something AA offers an agency that agreed to try
  features early; an owner self-service switch can come later if the business owner wants it.
- **What's new entries live in the web (`web/lib/whatsNew.ts`), not in a `release_note` table.** A note only changes
  with a release, so the release is its source and its pull request its review; a table would need an editor, a
  migration with RLS, a retention row and an API for no gain today. The API serves only the switch (`/me.preview`).
- **The one preview feature today is the Help page's Preview panel** (and the What's new entry that announces the
  channel). It proves the E test (an agency on preview sees it, others do not) without putting a half-built product
  feature behind the flag. New preview features join the registry `web/lib/preview.ts`.
- **The lint is a script plus a unit test** (`api/scripts/preview_flag_lint.py`, `tests/unit/test_aa970_preview_lint.py`):
  the Unit Tests job is required, so a finding turns CI red without a new workflow step. It is a word-list lint on
  paths and imports (privacy: consent, erasure, retention, lifecycle, portability, vault, reveal, access, audit, PII;
  money: price, tariff, payment, invoice, refund, margin, commission, finance, markup, discount, cancellation,
  deposit, currency, FX, ledger, bill, booking) plus the registry areas, on both sides (web gate calls, API reads of the
  switch). "legal" is a path word only, so a page may import the public page paths.
- **Public pages render the annex block, not a hand copy.** Root annex §5 holds a public summary between two markers;
  `api/scripts/gen_legal_annex.py` copies it (with the annex version and review date) into
  `web/lib/legal/annex3.generated.json`, and the existing "Vendored CIS copies" job now also reads the root file on
  `master` and fails on drift (the root repo is public; same fetcher, `repo=AA-Ecosys`, `branch=master`). The script
  refuses a block with a 12-digit number, an ARN, an issue id or an account label.
- **A table becomes cards** (`RowCard` block in `legalDoc.ts`): the kit lint forbids raw tables in page code, and a
  five-column table does not fit a phone.
- **Help topics chosen:** pipeline, clients, proposals, inbox, tasks (the sections every role uses daily); every
  sentence restates a label or subtitle the app already shows.
- **Migration number crm-072** (first lane draft: crm-077, renumbered in the fix pass): main holds crm-071, so
  crm-072 is the only key the migration preflight accepts now; the campaigns lane holds crm-073 and crm-074 right
  after it, so the wave's crm keys stay consecutive. If the campaigns PRs merge first, renumber to crm-075
  (`git grep '072_' 'crm-072'`, then re-run `scripts/gen_settings_defaults.py`).

## Changed

- Root (separate PR): annex 3 v0.6 adds §5 "Public summary"; the AI facts were re-read against ADR 0001a Note S278 and
  were already current in v0.5, so the refresh is the public block only. Annex 2 v0.6 adds M-18b and gap 10, the honest
  F2 wording the card's checklist asks for (design v3 §4.3 Fix A1).
- `GET /crm/v1/me` gains `preview` (bool).
- `scripts/check_vendored_copies.py` gains the root annex check; `github_fetch` takes `repo` / `branch`.
- `LegalPage` takes an optional version line and renders untitled sections and row cards; its footer links the two new
  pages.

## Tradeoffs

- The word-list lint can refuse a harmless file (for example a component that imports a finance helper only to show a
  number): the fix is to keep the preview part in its own file. A false negative would need a privacy or money module
  with a plain name; the registry type `PreviewArea` also leaves those areas out.
- The public pages show the annex's English body under an EN/VI frame: one text that applies, no translation drift.
- Entries in code mean a typo fix needs a release; acceptable for a release feed.

## Should know

- Ship order: the root PR first (the "Vendored CIS copies" job compares with root `master`; it is non-required, but it
  stays red until the root PR merges).
- crm-072 is contract (an INSERT of a config row) and ships in the code PR like crm-070 / crm-071: the settings lint,
  the guide test and the seed-parity test bind the seed, the reader and `compiled_defaults.json`. The code works before
  the apply (compiled default: off). `compiled_defaults.json`, `guides.json` and `CONTEXT.md` also change in the search
  (crm-071) and campaigns (crm-073/074) lanes: after a merge, re-run `python3 scripts/gen_settings_defaults.py`.
- To put an agency on preview on Dev: CIS admin Platform > Settings > CRM > `crm.release.preview` > the agency's value
  on, with a reason; `/crm/v1/me` answers `preview: true` within the 30 s cache window.
