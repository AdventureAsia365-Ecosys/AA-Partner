# AA-968 — CRM-36 campaigns (R14)

Card: design v3 §6.3 CRM-36 as updated by the S279 review (Linear AA-968): BYO mailbox, d21 content gate, the CRM
fan-out of a retired tour pulls scheduled campaigns, consent and suppression rules, the daily spread, feature key
default off until the independent review (AA-969).

## Decisions

- **Three tables, one expand file (crm-073)**: `crm.campaign`, `crm.campaign_recipient`, `crm.campaign_suppression`.
  `state` columns (not `status`), so no `crm.status_transition` rows and the file stays expand (the crm-063 pattern);
  the app moves states with conditional UPDATEs. Every subject key cascades (campaign <- `tenant_settings`, recipient <-
  campaign and traveller, suppression <- `tenant_settings`): no `crm.erase_subject` replacement.
- **The design's `unsubscribe_token` table is not created**: the token hash lives on the recipient row (one token per
  mail), with a SELECT-only lookup policy keyed on `app.campaign_unsubscribe_hash` (the `client_link_token_lookup`
  pattern). The DM-7.1 registry row of `crm.unsubscribe_token` is replaced by the three real tables (root PR).
- **Suppression by e-mail blind index, not by client**: card R "an unsubscribed contact re-imported stays suppressed"
  needs a record that outlives the client (an erased client imported again is a new row). The traveller e-mail blind
  index (HMAC under the agency's index key) is kept after a client erase to honour the opt-out; only the client's own
  "Subscribe again" on the preferences page lifts it. The agency erase deletes it.
- **Three places check consent and suppression**: the plan (left out and counted), the send day (skipped with a code),
  and the dispatcher's gate (`no_consent` for a suppressed address on any marketing e-mail, workflows included).
- **The import** records no marketing yes for a new client whose address is suppressed (warning `marketing_suppressed`).
  A matched client was already untouched by a re-import (AA-962).
- **Daily spread**: the plan assigns `send_on` days at the mailbox's daily limit minus what other campaigns of the agency
  planned or queued on that mailbox; the hourly send pass also caps a day at the limit minus the campaign mails queued
  that day, so a slipped day rolls on by itself. Days are the agency's timezone.
- **Limits are settings (tech lead S279)**: `crm.campaign.mailbox_daily_limit` (400, platform+tenant: the platform value
  with an administrator's per-agency value, 1..10000) and `crm.campaign.max_recipients` (2000, platform+tenant). crm-074
  ships in the code PR like crm-068 / crm-070 (the settings lint binds seed, readers and compiled defaults).
- **Feature key**: the existing entitlement code `campaigns` (projected from the CIS `crm.campaigns` key) gates every
  write and every send day (a withdrawn feature holds the campaign `feature_off`); reads answer `feature_allowed`.
- **d21 gate** without an LLM (`app.campaigns.model.content_gate`): AA subject required (served tour, listed AA campaign
  block, or brand content); links only to the client host's AA tour pages (`/trip/<key>` of a tour the campaign names)
  or the TripPlanner site; brand content has no such link. `mailto:` / `tel:` are contact links and pass.
- **Retired tour**: the fan-out (`crm_tour_retired_fanout`, `retired`) holds every scheduled / sending campaign naming
  the tour; the send pass also holds one whose tour is no longer `served` (paused, or the fan-out not run yet).
- **Send path**: one `crm.message` per client in the client's conversation (no trip), from the campaign's mailbox, and
  one `crm_dispatch` row with purpose `marketing`, origin `system` (no new origin value: that would be a contract CHECK
  change). Mails end with the unsubscribe lines and carry RFC 8058 `List-Unsubscribe` / `List-Unsubscribe-Post`.
- **New job kind** `crm_campaign_tick` (hourly, due now) rather than a step of `crm_workflow_tick`: its own result
  counts and failure isolation.

## Changed

- Root `docs/architecture/data-standards/02-data-management.md`: `crm.unsubscribe_token` (design name) replaced by the
  real rows of `crm.campaign`, `crm.campaign_recipient` (trip-scoped row) and `crm.campaign_suppression` (agency row).
- `TRIPPLANNER_SITE_ORIGIN` (new optional env, an endpoint, not a threshold): Terraform must set it before planner links
  pass the gate; until then only AA tour page links are allowed.
- The Marketing page's "campaigns arrive later" text is replaced by the campaigns panel; `tag.marketing.campaignsSoon`
  removed.

## Tradeoffs

- **Form consent counts as a yes**, as for workflows and the dispatcher today; the "double opt-in before marketing"
  note of Slice 1 is not built here. Raised for the independent review.
- **The one-click POST is not under the per-address public limit**: mail providers post from shared addresses and a 429
  would lose an opt-out; an unknown token is a 404 before any write (one indexed read).
- **The tenant's own TripPlanner host** (custom domain, CIS 428) is not known to the CRM: only the platform TripPlanner
  origin is allowed. A CIS contract field would close it (follow-up).
- **No bounce / complaint feed**: sends go through the agency's own mailbox (no SES events); the `bounced` /
  `complained` reasons are ready for a later feed.
