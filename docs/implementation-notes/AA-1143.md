# AA-1143 — The CRM's copy of its connection budget shares (lane l11, S285)

Tech lead decision G3: one budget per LLM connection as rows in CIS (the total, one share per app, CIS takes the
remainder), edited on CIS AI gateway › Budgets. This repo's part: receive and enforce the CRM's own share without
reading any CIS object (root ADR 0008a §6). The CIS side and the full design: AA-CIS-App
`docs/implementation-notes/AA-1143.md`.

## Decisions

- **A pushed copy, like the app profile** (crm-041 / crm.ops.v1 1.10): no CIS view is granted to `crm_app`, and the CIS
  settings relay is CIS → CRM, so CIS sends the CRM its part over crm.ops.v1 1.16 `PUT /llm/connection-shares` into
  `crm.llm_connection_share` (crm-079, a contract file: the REVOKE of the default privileges, as crm-041). The copy is
  whole: every CIS connection with a total, the CRM's share or 0.
- **Dual-read for one release**: `connection_share.share_for` reads the copy's row; a connection the copy does not name
  (or a database without crm-079) falls back to `crm.ai.connection_monthly_cap_usd`. Not min(copy, setting): the copy
  is what the tech lead set on Budgets, and CIS lowers its own remainder before it sends a higher CRM share, so the
  connection total holds either way.
- The response keys are a list of `{connection_key, share_usd}` (two keys added to the L1 allow-list), never a map
  keyed by connection (a map's keys would be data the allow-list cannot check).
- No readiness raise: the code checks `to_regclass('crm.llm_connection_share')` and keeps the setting before crm-079.

## Changed

- `connection_cap.read_state` takes the cap from `share_for` (one line); the rest of the AA-1138 route check is as
  that lane left it.
- Three "reads nothing" assertions of `test_aa1113_connection_cap.py` now check that no spend is read (the copy lookup
  is one indexed read).

## Tradeoffs

- One more read per capped call (a savepoint with `to_regclass` and one primary-key row): cheap, and only for a
  provider that maps to a CIS connection.
- A failed send from CIS leaves the copy behind; CIS only lets that happen on the safe side (a rise not yet sent), and
  its Budgets page shows "CRM copy not in step" with a Send to CRM button.

## Should know

- crm-079 ships in the migration-only PR with crm-078 (AA-1138, batch crm 078-079); this code PR after it is applied.
- The old setting stays editable on CIS Platform › Settings during the dual-read release; it only matters for a
  connection the copy does not name.
