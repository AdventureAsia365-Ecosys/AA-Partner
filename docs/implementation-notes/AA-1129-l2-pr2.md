# AA-1129 lane l2, PR 2: CRM home and routing (P1), people and labels (P2)

Source: S283 UI audit, `AA-Ecosys/docs/audits/2026-11-17-S283-fe-audit/README.md`, section "Medium, agency app",
rows 1-5, 8, 15 and the low "Next group departures" row. Web + API, no migration.

## Decisions

- **Member names without a schema change.** `crm.member` holds only the token's `(iss, sub)` ("members carry no
  name", AA-939). The only name the CRM has is the address a member was invited with (encrypted on
  `crm.member_invitation`). `GET /members` now returns `display_name` = that address before the "@" ("lan.nguyen"),
  never the full address (the owner's Team page keeps that), opened by the vault with one `list_view` audit event naming
  the members opened. A member with no invitation (seeder, L1 console, CIS account feed founder) gets `seq`, its place in
  its role, and the web says "Agent 2". A stored, editable display name would need a crm migration (contract, MIG-4
  chain) and a guard change (crm-008: only an owner writes `crm.member`); proposed as a follow-up, not done here.
- **"Needs you" is the caller's.** The agenda API adds `needs_you`: open tasks past due and due today in the `/tasks`
  "mine" scope (assigned to the caller, or unassigned on their trip), and live trips waiting on the agency that the
  caller owns or nobody owns. Late payments stay the agency's count (`overdue_instalments`). The panel lists only lines
  with something in them, most urgent first, each a link (`/tasks`, `/payments`, `/pipeline?waiting_on=agency`).
- **Departure date from the AA line.** `DEPARTURES_SQL` takes `min(service_from)` and the tour title of the departure's
  live AA lines (same rule as `/departures`), the trip's start date only for a group code without an AA line.
- **Home reads the agenda once** and hands it to the tiles and the panel (was one call inside the tiles).
- **CRM-only owner on "/"**: "/" keeps opening the Content studio (root ADR 0019 d7). The "No Content studio access"
  page now checks the CRM's own `GET memberships` and, for a person in an active CRM agency, says the CRM is ready and
  links `/home`. A person without a CRM agency sees the page as before (the CRM would send them back here).
- **Unmatched inbox preview**: the design rule "no contact data in lists" gets one documented exception: the Unmatched
  list carries the latest inbound sender, subject and a 140-character preview (a thread with no client is triaged by
  exactly these). Opened only for `unmatched=true`, one extra `list_view` audit event naming the messages.
- **Calendar task labels** use `taskTitle()` (the `/tasks` words, EN / VI), no new strings.
- **Home subtitle** says what Home is today (it said the pipeline and messages were still to come).

## Changed

- API: `app/pipeline.py` (`MEMBERS_SQL`, `members(ctx, vault)`, `display_name()`), `app/routers/pipeline.py` (vault
  for members), `app/finance/agenda.py` (`DEPARTURES_SQL`, `NEEDS_SQL`, `needs_you`, `title`),
  `app/mail/conversations.py` + `app/routers/mail.py` (Unmatched previews).
- Web: `lib/pipeline.ts` / `lib/team.ts` `memberLabel`, `roleSeq`; Team page and forms owner picker; calendar detail;
  `components/home/NeedsYou.tsx`, `AgendaTiles` (title, shared read); Unmatched inbox rows; the no-access page;
  `lib/i18nAgencyUi.ts` (new strings kept out of `lib/i18n.ts` so this PR and the lane's PR 1 do not touch the same
  lines).

## Tradeoffs

- Every `GET /members` now opens the invitation addresses (one audit event per call when any is opened). The list is
  small (agency members) and the vault caches its data key; the audit rows are the price of naming people.
- "Needs you" counts trips waiting on the agency that nobody owns, while the link opens the whole waiting list
  (`owner=me` would hide the unowned ones).
