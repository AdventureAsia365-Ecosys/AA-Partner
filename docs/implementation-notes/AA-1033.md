# AA-1033 — AI-output notice (AA-Partner: CRM web + portal)

Lane ai-notice, S263. The kit component and its wording are in AA-CIS-App (`frontend/app/_kit/core/AiNotice.tsx`,
`aiNotice.messages.ts`; notes in AA-CIS-App `docs/implementation-notes/AA-1033.md`). This repo gets them through the
kit sync (bot PR `chore: sync UI kit core to AA-CIS-App <sha>`), which must merge before this PR.

## Decisions

- **CRM web has no AI draft UI yet.** The API has `POST /crm/v1/trips/{id}/ai/draft` and the BFF allows it, but the
  draft panel is the next CRM-33a slice (CONTEXT.md "Draft"). Instead of an empty placement, a guard
  (`web/tests/aiNotice.test.ts`): any file under `app/` or `components/` that asks for `ai/draft` must render
  `<AiNotice`. The draft slice cannot ship without the notice.
- **Settings > AI**: the rule "AI can make mistakes: check facts before sending." is first in "How AI drafts work";
  below the rules the page shows the staff notice exactly as a draft will carry it (`ai-notice-example`, the CRM UI
  language through the `lang` prop — CRM web has its own i18n, not the kit I18nProvider) and links `/terms#ai`.
- **Terms**: CRM web had no terms page; the shared-responsibility acknowledgement on onboarding is a versioned text the
  owner accepts (`ACK_VERSION`), so changing it would need a new version and re-acceptance. Chose a new signed-in
  `/terms` page (draft) holding only the "AI-generated content" section, modelled on the portal terms §3, linked from a
  new one-line shell footer and from Settings > AI. EN + VI (`lib/i18nTerms.ts`), as everything in CRM web.
- **Wording** states only what the CRM does (CONTEXT.md: drafts are suggestions, nothing is sent without a person,
  the F3 scrubber replaces personal details before text reaches the model, client text is data). It does not name the model
  provider (routes change; "AI models of third-party providers, called through Adventure Asia's AI gateway"). It says
  "can contain mistakes", "for information only", and that the confirmed quote and booking terms bind. No liability
  waiver (test pins it).
- **Public trip page** (`/trip/[tourId]`, client host): it shows CIS AI-written tour text to travellers, so it carries
  the traveller notice before the call to action (English, like the rest of that page).
- **Portal**: `AiContentNotice` deleted; its placements (My Content header, review drawer, publish list and
  confirm dialog, catalog tab and drawer, tour rewrite panel, writer panel) render the kit `AiNotice variant="publisher"`
  — the same sentence, so portal terms §3 (which quotes it) and `test_portal_guards.py` are unchanged. The test id
  changes from `ai-content-notice` to `ai-notice` (no test used the old one).

## Changed

- The issue asked for the notice "under an AI draft (screenshot)": not possible yet (no draft UI). The screenshot target
  is Settings > AI (`ai-notice-example`) until the draft slice lands.

## Tradeoffs

- A terms page with one section vs editing the onboarding acknowledgement: the acknowledgement is versioned consent;
  a separate draft page avoids silently changing accepted text.

## Review fix pass (privacy wording)

- The first draft of `terms.ai.models` (and the older Settings > AI help `ai.enableHelp`, AA-937) promised that names,
  e-mail addresses, phone numbers and passport numbers "are replaced with placeholders before any text reaches the
  model". The F3 scrubber is best effort: pass 1 replaces the values it knows for the trip (`app/privacy/known.py`:
  the party, related travellers, emergency contacts), pass 2 / 3 replace what the detectors and name lists find, and
  a name it does not know (an agency member, a person mentioned only in free text) can pass. An absolute promise in
  legal text adds liability. Both strings (EN + VI) now say what the system does: the details it knows for the trip
  and the ones it can detect, that it may not catch every detail, and (terms) not to add personal data a draft does
  not need. `tests/aiNotice.test.ts` pins the wording and forbids the absolute sentence.
