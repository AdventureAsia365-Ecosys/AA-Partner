# AA-1191 — USD only (Partner part: CRM and Content studio)

Lane l4-usd of S297. The setting and the contract live in AA-CIS-App (`docs/implementation-notes/AA-1191.md`).

## Decisions

- **Read path**: CIS `catalog.http.v1` 1.5 `GET /catalog/v1/currencies` with the existing M2M client and scope
  (`cis.catalog/read`). The CRM holds no grant on any CIS schema (root ADR 0010 decision 4), so a catalog view is not an
  option, and a CRM-side copy of the value would be a second source of truth.
- **Cache**: one process cache (`app.state.enabled_currencies`, `app/catalog/currencies.py`), kept for the `cache_s`
  CIS sends (the setting's own cache window), so the CRM has no cache literal of its own. A failed read keeps the
  last answer and is retried after `RETRY_S` (a technical constant, the CIS reader's default window). Before any
  answer, and without `CIS_API_URL`, the CRM serves USD only: an outage never opens a currency the platform closed.
- **Scope of "a write in a currency"** in the CRM: what an agency sells and is billed in: the proposal currency (builder
  working copy and text proposal), the agency's base currency, the planner price rounding steps, the AA prices
  currency. Supplier cost currencies (agency line cost, supplier bills, commissions, FX overrides, services) stay open,
  like the supplier currencies the issue scopes out for Booking.
- **Stored values stay**: a text proposal or a base currency saved in VND is accepted when sent back unchanged, and the
  forms keep it as a hidden value, so nothing is silently relabelled from VND to USD. The DRY RUN counts them.
- **New versions (review fix)**: one rule for both proposal kinds: a new version is written in an enabled currency
  only, and nothing is carried over or converted from the old currency. Text: "New version" of a sent, superseded or
  withdrawn proposal in a currency that is not enabled starts in USD with empty total and deposit and a note
  (`lib/currencies.ts` `proposalFormCurrency`); the hidden stored value is kept only for a PATCH of the same draft.
  Builder: a working copy of a version in a currency that is not enabled is refused (422 `currency_not_enabled`,
  `currencies.refuse_copy_unless_enabled` in the route's transaction; the first cut skipped the check for copies, so
  a VND copy was written while VND was disabled), and the trip page offers "Start the builder" in USD when the latest
  builder version cannot be copied (`lib/currencies.ts` `builderStart`, `BuilderStartRow`). The check sits in the
  route, not in `builder._copy`: the code-health baseline forbids `builder.py` and `_copy` from growing.
  Re-pricing a copy in USD was rejected: it needs FX on agency sell prices, which is a pricing decision, not this
  lane's. The AA re-quote copy (`rebook_copy`, a booked trip re-quoted after an AA cancellation) keeps the booked
  currency unchecked: it continues a booking already made (follow-up if the tech lead wants it refused too).
- **Message keys**: `currency_not_enabled` is worded in `proposal.error.*`, `builder.err.*` and `ledger.error.*`
  (EN + VI), so no refusal shows the generic "something went wrong".
- **Content studio Billing / Dashboard**: CIS now serves the effective billing currency (USD while VND is disabled),
  so `billingMoney.ts` needs no change.

## Changed

- `app/catalog/client.py` (`get_currencies`), `app/catalog/currencies.py` (new), `app/main.py` (app state), the
  builder, proposals, ledger (payment settings, planner prices) and AA routers, `app/proposals/service.py`,
  `app/ledger/fx.py`.
- Web: `lib/currencies.ts` (new), `ProposalPanel` (pickers from the enabled list, hidden with one choice),
  `PaymentsView` (base currency picker, FX override quote without a VND default), `lib/aaTariff.ts` (USD only when
  the currencies cannot be read), the pipeline page reads `GET /currencies`.
- Tests: `web/tests/aa1191CurrencyDom.test.ts` (new version of a VND proposal, VND draft edit, VND builder start),
  `tests/unit/test_aa1191_enabled_currencies.py`, `FakeCis` answers `/currencies`, the tariff tests enable every
  currency (they test the tariff), `web/tests/aa1191Currencies.test.ts`, `web/tests/aaTariff.test.ts`.
- Integration tests about another currency enable it for their own app with `tests.aa_fakes.platform_enables(app,
  ...)`: the real `EnabledCurrencies` reader over `catalog.http.v1` answered by a `FakeCis`, no product check weakened.
  Service-level tests pass `allowed=` instead. Each changed file also asserts the default (USD only) refusal.

## Tradeoffs

- `GET /aa/tariff?currency=VND` answers 422 instead of a USD fallback: the page already offers only enabled currencies
  and falls back to USD for an unknown `?currency=`, so only a hand-made URL reaches the refusal.
- The FX override form lost its "VND" default (now empty with an "EUR" placeholder): FX overrides are supplier
  conversions and stay open, but the page no longer suggests VND.

## Should know

  gets 404 and keeps USD only.
