# AA-1080 — Brand Identity: brief fills the brand pack, market note with the reason (Partner web part)

The API side (brief parser, signature-word storage, unmapped-market records, T2 market) is in AA-CIS-App
(`docs/implementation-notes/AA-1080.md` there).

## Decisions

- The brief import (`POST /api/tenant/admin/brand-identity/parse`) now also fills **Brand context**, the **Default
  Call to Action** and the new **Signature Words** field. Fields the import drafted (no section in the brief) are
  named in the "Check before saving" box; sections of the brief it could not map come as a warning from the API.
- **Signature Words** is a comma-separated field like Tone of Voice; saved as `signature_words` (the API stores it in
  the brand's AA-800 signature vocabulary). Older saved versions without it show an empty field.
- **Market note** under Target Markets (`MarketNoteBox`), from the saved record (`markets` on GET) or the last save:
  the market tour-page keywords use (the first listed market with search data), and one line per declared market
  without search data with the reason and the market used instead. Shown on load, not only after a save.
- Copy and logic split: `lib/studio/brandMarkets.ts` (pure, unit-tested in `tests/studio/brandMarkets.test.ts`),
  copy in `brand.messages.ts` (EN + VI). English UI by default; no issue ids in UI text.

## Changed

- The brief review note for unsupported markets now uses the same reason line as the market note (it named only the
  fallback before).

## Tradeoffs

- The market note reflects the SAVED markets; while the agency edits Target Markets it keeps showing the saved state
  until the save (the save answer refreshes it). A live preview would need a client copy of the market mapping.

## Should know

- Needs the CIS API from the same lane deployed (GET `markets` / `signature_words`, parse `drafted`). Against an older
  API the form still works: the note falls back to `unsupported` codes, the extra field is simply empty.
