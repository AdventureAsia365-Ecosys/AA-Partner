# AA-1129 lane l18 — agency app leftovers (access log wording, studio monthly bill, seed names)

Scope: the "Left (small, next slice)" list of the S285 follow-up comment on AA-1129: access log lines that still show
ids or raw codes, "1 items shown", raw list labels; S1 "Studio money" (Content studio billing view); D1 data hygiene
per the tech lead's decision A7 (19/11/2026: data on Dev stays, only new data is guarded). One PR, web and API tests.

## Decisions

- **Fix the class, not the three lines.** The access log printed a raw code whenever the web had no message for it
  (`codeLabel` falls back to the code with spaces): "ops read the agency bab16039", "sales partner list sales partner".
  The API writes about 300 action codes, 94 object kinds, 73 detail (field) codes and 190 reason codes, most without
  words. All of them now have English and Vietnamese words in `web/lib/i18nAuditLog.ts` (English and the rules) and
  `web/lib/i18nAuditLogVi.ts` (split so each file stays under the code-health line limit).
- **One catalogue of the codes, read from the API code.** `api/scripts/audit_codes.py` walks `app/` with `ast` and
  collects the literal codes of every `ctx.audit(...)`, bare `audit(...)` and `AuditEvent(...)` (literals, module
  constants, `StrEnum` members, `a if c else b`, f-strings and `+` of those; every `app.permissions.Action` value,
  since a refusal can name any). It writes `web/lib/auditCodes.json` (merge, sorted). Two guards close the loop:
  the API unit test `test_aa1129_audit_codes_catalogue.py` fails when the code writes a code the catalogue lacks; the
  web unit test `tests/accessLogSentences.test.ts` fails when a catalogue code has no words in either language.
  Dynamic codes the reader cannot resolve (`f"ai_draft_{action}"`, `"tag_bulk_" + action`, commission and support
  session actions, `purpose_{purpose}` reasons) were added to the catalogue by hand from their call sites.
- **Sentence shape.** `log.say.<action>` is a whole sentence ("created a campaign"); it may name the object with
  `{obj}` ("removed {obj}" -> "removed team member Agent 2"). Otherwise `log.act.<action>` is a verb the object
  follows. Codes only a refusal writes (permission actions) read "tried to …" (the line also shows "Refused").
- **Objects never show an id.** One object is "a trip" / "an invoice" (English article from the noun: "an" before
  a vowel or an acronym read with a vowel sound: "an AI draft", "an SMS …"); the one of its kind is "the agency", "the
  access log"; Vietnamese has no article. The line still links a client or trip to its page (the id stays in the
  link only). A trip's title is not shown: `crm.trip.title` is `pii:travel` and the page promises "never client
  details". The key version of `tenant_key` ("vault:v1") stays: it is a version name, not a random id.
- **A list view or a view of no one object** reads "viewed the trip list" (`log.list.<kind>` when it has its own
  sentence, else "viewed the {noun} list"; an unknown kind "viewed a list").
- **Details and reasons.** Details print their labels ("sender, subject, message text"); a detail the web has no word
  for is counted ("1 other detail"), never printed. A reason without words is left out (the CSV / JSON download
  keeps every code). Unknown action: "worked on …"; unknown object: "a record".
- **Counts.** `log.items.one` ("1 item shown"); Vietnamese "hiển thị {n} mục".
- **Studio monthly bill (S1, audit rows 18 and 24).** CIS `/v1/billing` already sends `quote.lines`, `subtotal`,
  `discount_kind`, `discount_pct`, `discount`, `pilot_free`, `monthly_total`, `annual_paid_months`, `annual_total`
  (contract tenant.entitlements.v1 1.9); the web read only the total. `quoteView()` (lib/studio/billingMoney.ts)
  turns it into rows; `QuoteCard` shows "Your monthly bill" on Billing (every product with quantity, extra seats,
  trial / agreed / price to be confirmed / yearly, subtotal, founding or combo discount with its percent, free pilot,
  monthly total, yearly price); the Dashboard's "This month" card shows the same lines (short form) under the amount
  due. The labels that misled change only when a bill is there: Billing "Plan fee, no overage" -> "Your monthly bill
  below, no overage"; Dashboard "Within plan" -> "No overage". An older CIS without lines keeps the old page.
- **D1 seed names.** `api/tests/unit/test_aa1129_seed_names.py`: a migration `INSERT` value (outside the
  `shared.schema_versions` registry row) and a name-like field (name, title, display name, agency / tenant / company
  name, label, subject, slug, …) in `e2e/`, `loadtest/`, `api/tests/`, `api/app/seed/` and `web/tests/` never holds
  an issue id (`AA-123` or an `aa-123` slug). Today there is none, so no baseline is needed. No data change on Dev.

## Changed (vs the lane brief)

- The brief asked for "the agency name / trip title or a plain noun"; the lane uses the plain noun everywhere (the
  owner's own agency is "the agency"; trip titles are client data, see above). No API change was needed.
- Removed: `shortId` (lib/accessLog.ts, no caller left), `log.list.other` (replaced by `log.listOf` / `log.listAny`).

## Tradeoffs

- About 1,100 new message strings in the CRM bundle (the access log is a client component). Accepted: one dictionary
  per app is the existing pattern, and the alternative (rule-built sentences from code parts) reads badly in Vietnamese.
- The catalogue is checked in (JSON) rather than generated at build: the web build never needs Python, and the API
  test tells the author exactly what to run.
- The seed guard is a regex over source text, not an AST per language: it may miss a name built in several steps,
  but it costs nothing and catches the pattern the audit found.

## Should know

- When the API adds an audit code: `cd api && python3 scripts/audit_codes.py --write`, then add the words to
  `web/lib/i18nAuditLog.ts` and `web/lib/i18nAuditLogVi.ts`. The two tests say so in their failure messages.
- New test ids: `billing-quote`, `quote-lines`, `quote-line`, `quote-discount`, `quote-pilot`, `quote-total`,
  `quote-annual`, `dashboard-quote`.
- Not in this lane: the rewrite counters of audit row 19 (one ledger, CIS API) and "Live: earlier version" (already a
  title on the published link; the CIS lane owns the API part).
- Locally the unit suite needs `ENVIRONMENT=test` (as in ci.yml): without it 8 deploy-gate / platform-settings tests
  fail on origin/main too.
