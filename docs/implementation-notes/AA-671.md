# AA-671 — Marketplace redesign (catalog grid, filters, detail drawer)

Portal (`portal/`, moved from AA-CIS-App by AA-979). Session S255, 28/10/2026, Claude Code lane.

## Decisions

- **Open question "merge with Browse Tours?" decided in the system: yes, one page.** Before this issue the portal
  had two tour pages next to My Tours that read as near-duplicates:
  - Browse Tours (`/portal/tours`, `PoolTab.tsx`): the Adventure Asia catalog (`GET /v1/tours/pool`), a list with a
    side panel and the rewrite action;
  - Tour overview (`/portal/tours/marketplace`, `MarketplaceTab.tsx`, named "Marketplace" until AA-760): the tours the
    tenant already picked (`GET /v1/marketplace`), with price and status, no action.
  Both answer "which tours are in play for me", only from two ends. They are now **one page, Marketplace**, at
  `/portal/tours`, with two views on the kit `Tabs`: **All tours** (the catalog; default) and **In my catalog**
  (the old Tour overview). The view is in the URL (`?view=mine`), so it can be linked and the browser back button
  works. My Tours stays its own page: it is the work page (review, edit, export, versions), not a catalogue.
- **The name "Marketplace" is back, on the right page.** AA-760 dropped it because it sat on an overview of the
  tenant's own tours, where "a place to find tours" was misleading. The merged page *is* the place to find and pick
  tours, so the issue's own name fits it now.
- **Old routes keep working.** `/portal/tours/marketplace` and the AA-759 slug `/portal/marketplace` answer 308 to
  `/portal/tours?view=mine` (next.config.ts), the query string kept. The page file `tours/marketplace/page.tsx` is gone.
- **Grid card** (both views, one card component): country and duration chips, a "New" chip for a tour published in the
  last 14 days ("recently added": the API lists newest first, there is no other sort), name, subtitle (2 lines),
  up to 3 theme tags (the tour's SEO keywords, as before), the price text, and the tour's status from the shared
  work-status model (`workStatus.tsx`, the AA-760 rule: read from the job, never inferred).
- **Detail drawer** = the kit `Drawer` (was a sticky side panel that halved the list). Summary, highlights, itinerary
  (collapsed to 8 lines, "Show full itinerary"), SEO title and meta, published date. Footer: the quota note and the
  action for the tour's state (never rewritten: Rewrite this tour; ready: Open in My Tours + Rewrite again; writing:
  Follow in My Tours; failed: Retry in My Tours).
- **Quota-aware rewrite**: the drawer footer and the bulk bar say how many rewrites are left this period and what
  happens past the quota, from the same numbers as Billing (`usageMeter()` in `lib/account.ts`, over `GET /v1/quota`
  and `GET /v1/billing`). Copy only says what CIS does (AA-640: past the quota the rewrite still runs and is billed
  as overage at `overage_rate_usd_per_tour`; no plan attached = not billed yet). Pure rule `rewriteQuotaNote()` in
  `lib/tours.ts`, unit-tested.
- **After a rewrite starts the tenant stays on the Marketplace** (it used to jump to My Tours): the card turns to
  "Writing" from the shared `["my-versions"]` query, which polls while a rewrite runs; the toast says where to follow
  it. Picking several tours in a row no longer means coming back to the catalog each time.
- **Rewrite errors are shown.** The old loop ignored the POST response (a 409 "already in progress" or a 409 for a
  tour AA stopped serving read as success). Now each POST goes through `apiSend`; the toast reports started / failed
  counts, and tours already being written are left out of a bulk rewrite.
- **Kit-only code.** The new files import the kit barrel (`@/app/_kit`) and `K` tokens only, not the legacy
  `_components/ui.tsx`: they pass the AA-994 S2b `inline` preset (no hand-styled `<button>`, no `var(--aa-*)` string,
  no hex colour, no legacy import). `fmtDuration` moved to `lib/tours.ts` (ui.tsx re-exports it) so the new code and
  the legacy pages format durations with one function.

## Changed (vs the issue text)

- Issue scope listed filters "country, duration, activity, intensity, recently added" and a "cover" image on the card.
  Shipped: search, country, duration, newest-first + the "New" chip. **Not shipped, CIS API gap**: the pool API
  (`GET /v1/tours/pool`, AA-CIS-App `api/routers/v1_tours.py`) returns no activity list, no intensity and no image,
  and filters only on name, country and duration. `raw_tours.activities` (jsonb) exists but is not projected; there is
  no intensity column at all. Business logic stays in the CIS API (root ADR 0010 §7), so these filters need a CIS
  change first (follow-up, see "Should know").
- "Add-to-catalog state" = the card / drawer status ("In My Tours", Writing, Writing failed) and the "In my catalog"
  view.

## Tradeoffs

- One page with two views vs two pages: one page means one search box, one card, one drawer and one nav entry; the
  cost is that the "In my catalog" view repeats part of My Tours (status). It keeps what My Tours does not show (the
  price and the planned posts per week) and links each card to My Tours for the work. A separate overview page would
  keep the duplicate the issue asked about.
- Query param vs a sub-route for the view: a param keeps one route and one page component; the 308 for the old
  routes carries the param.
- Page size 24 (was 20): a full last row on 2, 3 and 4 columns.
- The "In my catalog" view reads `GET /v1/marketplace` (all of the tenant's picked tours in one answer, as before);
  it is not paged on the server, which is what the endpoint offers today. A tenant has far fewer picked tours than the
  catalog has tours.

## Review fixes (independent review, S255)

- Rebased on `main` after AA-994 S2b (#108); `npx eslint --prune-suppressions` dropped the 10 suppressed violations of
  the three deleted components (192 -> 182, growth check OK, no inline kit disable).
- A refused rewrite now shows its tenant sentence (`plainError`): the AA-986 409 detail starts with the machine code
  `tour_discontinued: ` / `tour_paused: `, which the toast used to print as is.
- A tour AA paused or retired (`workClosed`, the pool rows carry the served fields) has no select box on its card, its
  `ServedBadge` in the card footer, and in the drawer the reason instead of Rewrite / Rewrite again (a supersede
  waiting for its new version, which has no notice, reads neutral). Before, the button was offered and the API
  answered 409.
- The bulk bar is sticky at the top of the scrolling `<main>` with an opaque card background: on a phone (one card per
  row) the Rewrite button used to scroll out of view as soon as a second card further down was picked.
- Review evidence (local build, mock API, sample data): `08-bulk-bar-sticky-*` and `09-drawer-paused-tour-*` in the
  root audit folder `docs/audits/2026-10-28-S255-aa671-marketplace/`; 0 console errors; the two old slugs answer 308
  with the request query kept (`/portal/tours/marketplace?x=1` -> `/portal/tours?x=1&view=mine`).

## Second review (independent reviewer, S255)

- A tour AA paused or retired whose last rewrite failed no longer offers "Retry in My Tours" in the drawer: the CIS
  retry (`POST /v1/tours/versions/{id}/retry`) refuses a not-served tour with the same 409. The drawer shows the
  reason and "Open in My Tours".
- Checked against AA-CIS-App `main`: `GET /v1/tours/pool` accepts `page`, `page_size` (24 <= 100), `search` (name),
  `country`, `duration_min` / `duration_max`, orders by `published_at DESC`, returns `countries` and the served fields
  (`_annotate_served`); the AA-986 409 detail is a plain string, so `ApiError.message` + `plainError` reads right.
