# AA-1094: "Book now" books the tour the page shows

S278 system audit M12: the CIS trip page answer had no catalogue key, so the AA-1072 widget took the AA tour key from
the link (`p=`) and could offer a tour that differs from the page text (seen in the S277 live check).

## Decisions

- CIS `GET /v1/trip/{id}` now returns `source_id`, the page's own AA catalogue key (AA-CIS-App PR of this issue).
  `lib/bookNow.ts` `widgetTour(pageSourceId, linkTour)` makes it win over `p=`; the link key counts only while CIS
  sends no key (an older CIS answer during the rollout). Before, `p=` won over the page key.

## Changed

- `web/lib/bookNow.ts`: `widgetTour`. `web/app/trip/[tourId]/page.tsx`: the widget's `tour` comes from it.
- `web/tests/bookNow.test.ts`: the precedence cases.

## Tradeoffs

- The API still accepts any served tour key (it cannot see the page): a hand-made request can book another served tour
  of the same agency, which is the visitor's own booking, not a confusion caused by the page.

## Should know

- Live check after the CIS deploy: open a served trip page with `?f=<form key>&p=<another tour key>`; the widget title
  must be the page's tour.
