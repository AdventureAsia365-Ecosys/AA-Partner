# AA-1085 — legal-hold guards read the holds of the row's own agency

Lane l24 of S277. Found by the AA-1071 lane: a foreign-key action (ON DELETE CASCADE / SET NULL) runs its query, and
the BEFORE triggers it fires, as the table owner with row security off (PostgreSQL's RI queries ignore FORCE ROW
LEVEL SECURITY for the owner). The hold guards read `crm.legal_hold` through `crm.hold_trip` / `hold_traveler` /
`hold_row`, which rely on RLS for the agency, so inside a cascade they see every agency's holds.

Migration: crm-058 (contract, MIG-4) in a migration-only PR; this code PR raises readiness to it.

## Decisions

- **New tenant-explicit functions, old ones kept.** `crm.hold_trip_of(tenant, trip)`, `crm.hold_traveler_of(tenant,
  traveler)`, `crm.hold_row_of(tenant, trip, traveler)` are the crm-010 hold rule 4a-4d with `tenant_id = p_tenant`
  on every read (`crm.legal_hold` and `crm.trip_traveler`). The one-argument functions stay unchanged: their callers
  (`crm.erase_held`, `crm.legal_hold_blocks`, the trash pre-check, the redaction job) always run under RLS with
  `app.tenant_id` set, and changing them would mean re-issuing the long `crm.erase_held` text for no gain.
- **The row's tenant, not `app.tenant_id`.** The guards pass `OLD.tenant_id`. The GUC would give the same answer on
  every path today, but the row's own column cannot drift from the row. `crm.guard_held_change` (generic, jsonb)
  refuses a table without `tenant_id` instead of matching no hold (fail closed); every hold-guarded table has a NOT
  NULL `tenant_id` (integration test).
- **Every hold guard covered**, found from the catalog (every crm trigger function that reads holds), not only the
  crm-054 one named in the issue: `guard_held_change` (crm-010, 35 tables), `guard_message` (crm-015),
  `guard_held_flight` (crm-029), `guard_ops_release` + `guard_supplier_manifest_export` (crm-034),
  `guard_held_travel_doc` (crm-054). Each body is the latest text with only the hold reads changed (plus the
  `crm.ops_release` / `crm.conversation` lookups getting the tenant predicate too).
- **Flight and travel-doc guards check cascades again.** crm-029 / crm-054 let every cascade pass (`pg_trigger_depth()
  > 1`) only because the guard could not read holds safely there. With the tenant predicate they check at any depth,
  which enforces hold rule 4d ("a row is held when its trip or traveller is") on a cascade too.
  `guard_ops_release` and `guard_supplier_manifest_export` keep their depth / owner pass: there it is about who may
  write a release, not about holds.
- **`crm.partner_commission` gets `guard_held_change('trip_id')`** (crm-056 left it off for this reason; crm-056 is
  on main). Its trip never moves (`partner_commission_fixed`), so the guard acts on a delete or a trash: a partner
  delete that would cascade onto a commission of a held trip is refused (CRM10 -> 409 `legal_hold` through
  `tenant_tx`).
- **Lint in two places.** A unit test over the migration texts (`api/tests/unit/test_aa1085_hold_guard_tenant.py`,
  latest definition of each function; no DB, so it fails at the unit stage when a new migration adds an RLS-only
  guard) and the same rule on the replayed catalog (`api/tests/integration/test_crm058_schema.py`). The unit lint
  proves itself on the pre-crm-058 texts (it must flag all six).

## Changed

- Scope beyond the issue text: `guard_message`, `guard_ops_release`, `guard_supplier_manifest_export` and
  `guard_held_flight` had the same pattern and are fixed in the same file.
- Behaviour: a cascade onto a held row of `traveler_flight`, `booking_line_voucher`, `room_assignment`,
  `visa_application` or `partner_commission` is now refused (it passed before); a hold of another agency never refuses
  anything. Every erase `crm.erase_subject` allows is unchanged: `crm.erase_held` already refuses an erase that would
  reach a held row, and the cascades of those tables come from rows with the same trip and traveller.
- `api/tests/integration/test_crm015_schema.py` re-applies crm-058 after it re-runs crm-015 (which re-creates the
  RLS-only `guard_message`); `test_crm029_schema.py` docstring names the crm-058 rule.

## Tradeoffs

- Keeping the one-argument functions leaves two spellings of the hold rule. The lint pins which one a guard may use;
  merging them (e.g. `hold_row(trip, traveler)` = `hold_row_of(current tenant, ...)`) is possible later but touches
  every non-trigger caller.
- Checking cascades costs one indexed `crm.legal_hold` probe per cascaded row (`legal_hold_active_uq` leads with
  `tenant_id`, partial on active); an agency without an active hold exits at the first probe in
  `guard_held_change`.
