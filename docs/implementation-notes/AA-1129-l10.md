# AA-1129 lane l10 — agency app follow-ups after the S285 live check

Scope: the S285 live check of the merged agency fixes (Partner #349, #350) against the S283 UI audit, agency rows 6,
10, 13, 14, 15 and proposal P4 (settings pages). One PR, web and API.

## Decisions

- **One member label rule** in `web/lib/people.ts` (`personLabel`): name ("lan.nguyen · Agent") -> place in the role
  ("Agent 2") -> role alone ("Agent"); an unknown member reads "Former member". Never an e-mail address or an id. Both
  older helpers (`lib/team.ts` and `lib/pipeline.ts` `memberLabel`) now call it, so every caller (Team page, forms'
  owner picker, menus, reports, calendar, access log) follows it. The planned kit PersonLabel can take this order.
- **Team page and owner picker**: the Team API still sends the full address (owner only); the web cuts it to the part
  before the "@" (`nameFromEmail`, the same 64-character cut as the API's members `display_name`). The full address no
  longer shows on the Team page either (task: "never show an e-mail"); the invitation list keeps its masked address.
- **Pipeline fallback**: a member object without name or place now reads the role alone ("Agent"), not "Agent · abcd".
- **Access log actor**: the server page reads `GET /members` beside the events and passes a member directory to the
  view. A member missing from the directory is "Former member"; when the members call failed, the role alone. That
  read is itself one logged list view (it names the members whose address was opened), which is correct logging.
- **Access log time (#418)**: the API page answer now carries the agency `timezone` (`tenant_settings.timezone`, default
  `Asia/Ho_Chi_Minh`, as the other modules); `whenText` formats day and time in that zone with fixed options, so the
  server render and the browser produce the same string. An older API (no field) falls back to UTC, still
  deterministic.
- **List sentences**: `list_view` lines use a full sentence per object kind (`log.list.<kind>`, e.g. "viewed the team
  members"), else "viewed a list: <object>". `log.obj.member` is now "team member"; the actor's own member object
  ("signed in to …", the bell) reads "the agency"; another member is named by the rule.
- **Travelling now**: web-only. The API's `day_no` is the day number on `on_date` (the trip's first day in the window),
  so for a future trip it is 1. `tripWhen(trip, view.today)` says "Starts in N days" ("Starts tomorrow") while the
  start date is after the view's `today` (agency timezone from the API), else "Day N".
- **Client host 404**: deleted the `/c/[...slug]` placeholder (200 with the partner brand). Unknown client-host paths
  outside `/c` and `/trip` are rewritten by `proxy.ts` to `/c/_not-found` (a private `_` segment, no route), so Next
  renders `app/not-found.tsx` with HTTP 404, host kind `client` (no brand, neutral title). The rewrite target is fixed;
  no other page can render through it.
- **Trash wording**: `trashPurgeLine(purge_after, deletion_dry_run, now)`: dry run -> "Would have been removed on" (past)
  / "Would be removed on" (future); deletion on -> "Removed for good on" (future) / "at the next daily clean-up" (past).
  `now` comes from the server render (prop) so the browser words it the same. A note above the trash says deletion
  is off while the dry run is on.
- **Paging / collapse**: the trash is a kit DataTable (10 rows a page, page size 10/25/50, search above 10 rows); the
  exports and data requests show their first 5 rows and a "Show all n" / "Show fewer" toggle (`lib/fold.ts`,
  `components/FoldToggle.tsx`); Settings > Agreements shows the New version form first, then drafts and published
  versions, and folds retired versions under "Older versions (n)".

## Changed (vs the lane brief)

- The trash label fallback was the id's first 8 characters; it is now "Untitled" (no ids in UI).
- The calendar's team feed list fell back to an id slice for an unknown member; it is now "Former member".
- P4 items not in this lane's brief (settings subtitle, hold reason label, search box under 600 px) are not done here.

## Tradeoffs

- The fold size (5) and the trash page size (10) are display choices, not policy limits: every row stays one click
  away (Show all / pager / page-size select), so they are not admin settings (the S279 thresholds rule covers caps and
  limits that refuse or drop something).
- `<details>` for older agreement versions (native, as on Travelling now) instead of a new kit component.
- The client-host rewrite costs one Next render per unknown path instead of a plain-text answer; those paths are rare
  and the response is `no-store`.
