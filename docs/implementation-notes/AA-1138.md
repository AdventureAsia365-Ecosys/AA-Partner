# AA-1138 — CRM draft replies on Claude Haiku 5.5 (acc1), Nova Lite last; the CRM cap per connection

Lane l8 of S285 (Claude Code). The tech lead approved on 19/11/2026, after a blind A/B of ten client replies (Claude
Haiku 5.5 won 7 of 10 over Amazon Nova Lite): route `crm_draft_reply` to Claude Haiku 5.5 with the platform route order
for Claude, and give the CRM a 5 USD monthly cap on the new connection, taken from the CIS share.

Two PRs (MIG-4): the migration `crm-078` alone, then this code PR (readiness `crm-078`), plus an AA-CIS-Infra PR for
the acc1 role trust, the CRM task role's assume grant and the task env.

## Decisions

- **acc1 Bedrock, not the Anthropic API.** The platform order for Claude is the Anthropic API, then acc1, then acc3
  (route-control v11). The CRM has no Anthropic API client, no vendor key and no secret for one, and root ADR 0008a
  §5 keeps the CRM on Bedrock only (the bypass guard `test_gateway_bypass.py` fails on a vendor SDK or host). Adding
  one would be a new provider, a new secret, a new data path for traveller text (scrubbed) and an ADR change. The
  minimal safe path is the one CIS already uses for its Bedrock hop: acc1's `AA1-Bedrock-Invoker` role, assumed with
  an ExternalId. So the CRM route is Claude Haiku 5.5 on acc1 first, then Nova Lite on acc2 (the CRM task role's own
  Bedrock). acc3 is not added: AWS refuses models there at account level. If the tech lead later wants the Anthropic
  API first for the CRM too, that is its own issue (ADR 0008a amendment + provider + secret).
- **The cap moves to acc1, taken from the CIS share of acc1.** The issue text named the Anthropic API share (CIS 150 ->
  145). Because the CRM's Claude hop is acc1, the CRM spends nothing on the Anthropic API connection; the 5 USD comes
  from the CIS share of acc1 instead (the acc1 connection's monthly budget in the CIS gateway registry, 100 -> 95 USD),
  and the CRM setting `crm.ai.connection_monthly_cap_usd` gets `"acc1": 5` beside `"acc2": 5`. The provider budget
  setting `cis.spend.connection_provider_budget_usd` does not change (acc1 100 = CIS 95 + CRM 5). These are live steps
  (admin Settings / AI gateway pages), not code.
- **A route entry names its connection** (`crm.llm_stage_route.connection_key`, crm-078). NULL keeps today's meaning
  (the process's own connection: the task role, or `CRM_LLM_ROLE_ARN`). The only named connection is `bedrock_acc1`;
  its role ARN and ExternalId come from the task env (`CRM_LLM_ACC1_ROLE_ARN`, `CRM_LLM_ACC1_EXTERNAL_ID`, set by
  Terraform) because the public repo carries no account ID. A key the process has no configuration for is never
  called: a refused 0 USD attempt (class `credential`), then the next entry. That keeps the window between the
  migration and the Infra apply safe (the draft still gets Nova Lite).
- **Temperature per route entry** (`sends_temperature`, crm-078). Claude Haiku 5.5 rejects a temperature (CIS
  catalogue row `haiku-5-5`, supports_temperature false). A model capability belongs with the route row, not in a
  model list in code.
- **The cap is checked per connection of the route, and a capped entry is skipped, not the whole call.** Before, the
  gateway checked only the first entry's connection and refused the call at its cap. With two connections, a capped
  acc1 must not stop drafts that Nova Lite on acc2 can still write, so `connection_cap.check_route` leaves the entry
  out and the route goes on; only when every entry is capped is the call refused (the first entry's refusal). Each
  connection is read once per call.
- **Month spend per connection from the rollup joined with the route.** `crm.llm_usage_daily` has no connection
  column, and `crm.llm_call` is tenant-isolated (the cap is platform-wide). The rows of a (stage, model) pair that a
  route entry runs on a named connection count for that connection; every other row (other models, the guardrail
  rows) counts for the process's own connection. No schema change on the rollup.
- **Output cap.** Haiku 5.5 thinks before it answers (adaptive thinking, billed as output). In the A/B 9 of 10 drafts
  fit the CRM's 800-token cap and one used 820, which the CRM would log `truncated` and move to Nova Lite. The cap is
  the admin-editable setting `crm.ai.draft_reply_max_tokens` (50..4000); the live steps raise it to 2000 (worst case
  0.001 USD per Haiku draft). No new per-model floor in code.

- **Fail closed on a named connection without a CRM cap (review S285).** An independent reviewer found that the
  first live order (Infra apply, crm-078, deploy, then the cap setting) left a window in which the CRM could call
  Claude on acc1 with no CRM cap, and the setting needs maker-checker approval, so the window could last. Two fixes,
  both kept: (1) under the dev spend rules, `connection_cap.refusal` refuses a route entry whose NAMED connection
  has no entry in `crm.ai.connection_monthly_cap_usd` (`connection_cap_missing`, class `budget`; a named key the CIS
  registry cannot name is refused the same way), so `check_route` leaves the acc1 entry out and the draft goes to
  Nova Lite; the process's own connection keeps "no entry = no cap" (crm-077 meaning, unchanged); the prod rules
  only log (pay per use, tech lead S283); (2) the live order now writes and approves the setting first.

## Changed

- `app/llm/profiles.py`: the route entry carries `connection_key` and `sends_temperature` (absent columns read as
  NULL / true).
- `app/llm/providers/bedrock.py`: `Connection`, named connection roots (`bedrock_acc1`), ExternalId on AssumeRole,
  temperature left out when the entry says so, `from_settings`; `NOT_CONFIGURED` for an unconfigured connection.
- `app/llm/connection_cap.py`: `bedrock_acc1` -> CIS `acc1`; month spend per connection (`OWN_MONTH_SQL`,
  `NAMED_MONTH_SQL`); `check_route`; `connection_cap_missing` for a named connection without a CRM cap (dev
  rules). `app/llm/app_profile.then_connection_cap` returns the profile the call goes on with; `app/llm/gateway.py` calls it before choosing the first provider (the file does not grow: the provider is
  built by `from_settings`).
- `app/settings.py`: `CRM_LLM_ACC1_ROLE_ARN` / `CRM_LLM_ACC1_EXTERNAL_ID` (the ARN needs the ExternalId; hidden from
  `repr`). `app/db.py`: readiness `crm-078`.
- `app/platform_settings/guides.json`: the connection cap example names the per-connection rule.

## Tradeoffs

- A (stage, model) pair routed on two connections counts for both (never under-counted, may stop one early). The CRM
  routes do not do that today.
- A route change during the month moves where that month's earlier rows count (the join reads the route as it is
  now). Accepted: a route change is a migration, rare, and the shares are small.
- The Bedrock price of Haiku 5.5 is the catalogue's Anthropic list price (0.10 / 0.50), marked unconfirmed for Bedrock
  in CIS 259; the CRM ledger uses the route row's price like for Nova Lite.
