## Decisions

- **No migration for the agency reports.** Every number is computed on page open from the agency's own rows (the data lane's own wording for
  R28: "computed on page open"). `crm.metric_daily` (25-month rollup) is not created: trips are kept far longer than
  25 months (auto-archive 36 months minimum keeps trips; trash only removes deleted ones), so year-on-year from the
  base rows is exact, and a rollup table would need a job, a retention rule and an erasure entry for no gain on Dev.
  It becomes worth it when reports get slow or when erasure must keep aggregates (follow-up, not built).
- **`crm.metric_event` is not extended.** Its `trip_id` is NOT NULL, so agency-level events cannot live there. Every
  spec §6 success line got a source query over the existing tables instead (`SUCCESS` in `app/reports/service.py`):
  module 1 budget share and first reply, 2 quiet leads, 3 upgrade rate and messages per booked trip, 4 text proposal
  time, 5 / 9 messages by channel, 6 margin known, 7 deposits within 48 h, 10 overdue tasks before departure, 11
  portal opened, 12 signed before departure, 15 mixed trips, 16 report downloads (audit `report_export`), 18 data
  exports. Modules 8 (ops release), 13 (commission) and 14 (AI drafts) are not built yet: they say "Coming later"
  instead of a number. Module 17 is AA's side (the insights read).
- **Win = reached Booked.** A trip counts as won when its current stage is Booked or later, or when a stage-history
  row moved it to Booked and no later Undo reversed it (crm-012 `undo_of`). A booked-then-cancelled trip stays won (the
  sale happened); the cancellation shows in the cancel reasons. Seeded trips without history still count by stage.
- **Upgrade = an option dearer than the block's suggested one** (`option.sell_amount > default.sell_amount`); "kept
  your suggestion" = the default option. The design's "Upgrade chosen 23% (goal >= 20%)".
- **Money only for owner / agent.** The service skips the money query for the assistant (crm-014 would return no rows
  and the page would show 0); the AA share tile switches to booking lines. The CSV money section is refused with
  `require(VIEW_MARGIN)` because the margin serializer filters JSON only.
- **AA insights live in crm.ops.v1 (1.5), not a new crm.insights.v1.** Same caller (CIS admin, WORKFORCE
  `cis-admin`), same route class and guard; its keys pass the L1 allow-list and the root contract policy (no trip,
  pipeline, revenue or agency id). A separate contract would need a new route class or prefix for no extra protection.
- **Insights read path.** Per agency `platform_tx()` (active only; a locked agency does not count), the opt-out read as
  crm_app BEFORE any fact, then `SET LOCAL ROLE crm_insights` (`tenancy.as_insights_reader`, a savepoint like
  `as_eraser`) to read `crm.v_insight_fact`. Synthetic agencies count everywhere but prod (Dev and stg hold synthetic
  agencies only). A cell = one value of one dimension over the requested months; travellers = party sizes summed. A
  suppressed cell leaves nothing (no bucket, no counts, no total), only the number of cells held back.
- **No per-agency audit event for the insights read**, like `/data-coverage`: it reads totals no agency can be found
  in, and one event per agency per page load would bury the owner's access log. One log line per call.
- **Home tiles** come from `GET /reports/tiles` (last 12 months, everyone) in a separate server component that renders
  nothing on an error, so Home never breaks on the reports API.

- **Review fix pass (S261).** Four findings from the independent reviewers, all confirmed against the code and fixed:
  1. *Insights counted a trip once per destination.* `crm.v_insight_fact` is one row per trip and destination, so a
     1-traveller trip to 4 places added 4 travellers to its budget band cell (3 such agencies = 12, published). Fix:
     an **expand** migration `crm-031` adds `crm.v_insight_trip_fact` (trips per agency, month and band combination,
     `trip_count`, no destination, no trip id; GROUP BY so not updatable) for every dimension but the destination;
     `insights.Fact.grain` + `aggregate()` refuse per-destination facts for those dimensions. A new view, not a
     changed one: changing `v_insight_fact` (an ordinal column) would be a contract file (manual apply, separate PR).
     The expand lint and the expand post-check (`run_migration.expand_lint` / `expand_findings`) both pass locally.
     An expand file cannot REVOKE, so `crm_app` keeps the schema's default DML grant on the view; it does nothing
     (not updatable; the test checks INSERT / UPDATE / DELETE fail).
  2. *Outstanding counted an invoiced schedule row twice.* `SCHEDULE_DUE_SQL` now leaves out a row a live invoice (not
     draft, not void) bills; the UI and CSV label the rest "not invoiced yet" (CSV `what` = `schedule_not_invoiced`).
  3. *Open-invoice outstanding differed from A-10 Receivables.* Now the same rule: `RECEIVABLE` statuses (expired
     included, imported from `app.invoices.service`), paid = payments only, `greatest(total - paid, 0)` per invoice
     before the currency sum (overdue too). Integration test reconciles with `invoices.receivables()` after a partial
     payment and a partial refund.
  4. *Insights could be differenced across overlapping month ranges.* `GET /insights` takes `quarter=YYYY-Qn` only
     (one fixed calendar quarter; `from` / `to` in the answer are its bounds; 422 `invalid_quarter`), so answers never
     overlap or nest. Added a dominance rule: no published cell has more than 70 % of its travellers from one agency
     (stricter than card R; the reviewers' optional suggestion, cheap, and it stops a cell describing mostly one
     agency). The docstring and the contract now say what is NOT guaranteed: live cells, so toggling one agency's
     opt-out between two reads of a quarter reveals that agency's share (a platform write, audited); a frozen
     per-quarter `crm.insight_aggregate` is the follow-up that removes it.

## Changed

- `metric_daily` and `insight_aggregate` tables of the design are not created (see Decisions); insights are aggregated
  per request, per calendar quarter (the design spoke of a month range).
- Module 17 dominance rule (no agency above 70 % of a published cell) on top of card R.
- The CIS admin page S-03 is not in this PR (AA-CIS-App); the CRM side serves the read it needs. Follow-up.
- "Margin by trip type (system tags)" of the wireframe uses `trip.party_type` (tags do not exist yet).
- Report catalog CRM-02 is inside Team activity (first reply, overdue tasks, unanswered > 24 h, trips per owner); the
  weekly digest mail and CRM-03 / 04 / 05 / 06 stay with their own cards.

## Tradeoffs

- Computing on open runs about 25 small queries per Reports page (more with the 3-month trend). Fine for Dev volumes
  and one agency's rows; a rollup table is the lever when it is not.
- Amounts are shown in the agency's base currency for confirmed lines (frozen FX), but outstanding payments are per
  document currency (no conversion of open invoices).
- `v_insight_fact` drops trips without a month (no start date and no travel month): they cannot be placed in time.
