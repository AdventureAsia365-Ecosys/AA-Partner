# AA-1089 — CRM small add-ons from the Odoo study (CRM part)

Two items remain of ranks 45-53 (S279 scope update): the "Booking confirmed" starter template (CIS owns the starters:
AA-CIS-App `data/aa_content/seed_v1.json`, same issue) and, here, the source AA tour and departure on the trip
header (rank 48).

## Decisions

- **No migration.** The trip already names its AA tour where it came from one: the "Book now" attempt that made it
  (`crm.public_booking_attempt`: `tour_source_id`, `departure_id`, `trip_id`, `proposal_id`) and its AA booking lines
  (`aa_tour_source_id`, `departure_id`, `service_from`). `aa_source` is computed on each trip read
  (`app/catalog/trip_source.py`), so nothing can go stale.
- **Which source wins:** the Book now attempt (status `created`) first: that is the enquiry-to-booking path the
  study names; its departure date is the start (`starts_on`) of the proposal the press sent. Else the AA line still
  standing with the earliest service date, with the same "still standing" rule as `app.catalog.retired.ITEMS_SQL`
  (not cancelled; confirmed, booked with a Booking id, or held / pending / quoted). AA options in a draft proposal
  are not a source: the trip did not come from them, and the AA tour discontinued card already covers options.
- **One source, not a list.** The header names one tour. A trip with several AA tours shows the first by the rule
  above; the trip's Bookings card lists every line.
- **Titles from the CRM's own cache** (`crm.aa_catalog_tour`, filled by the hourly `crm_catalog_sync` through
  catalog.http.v1): no CIS call on a trip read, no cross-schema read. A tour not cached yet reads "An AA tour".
- **The tour page link.** The public tour page is on the client host (`/trip/<id>`, a client-only path), so the API
  builds the absolute URL from the first `INTAKE_PAGE_ORIGINS` entry (the same origin the text proposal links use).
  The CRM knows a tour only by its catalogue key (`COALESCE(source_group_id, tour_id)` in CIS), which is not a page id
  for a versioned tour; the CIS part of this issue makes `/v1/trip/<key>` answer 301 to the key's current version
  (the web page then 308s). The link is left out while the tour is not served (retired or paused), when the key is
  not a uuid (CIS 404s it before any read) or when no client origin is configured.
- **UI:** one line under the trip title (`TripSourceLine`): neutral "AA tour" badge, the title, "Departs <date>"
  (date spelled per the agent's locale), an accent "Booked online" badge for a Book now trip, "Tour page ↗" in a new
  tab (`rel="noopener noreferrer"`; only an http(s) URL is linked). Kit `Badge` and tokens only; EN and VI words.

## Tradeoffs

- Computing on read costs one small indexed query per trip page; storing a source on `crm.trip` would need a
  contract migration and a backfill for no gain (both sources already exist and never change for a created trip).
- Linking `/trip/<catalogue key>` relies on the CIS redirect (shipped in the same issue). A `page_tour_id` in the
  catalogue contract would avoid the redirect but needs a contract change, a CRM migration and a resync.
