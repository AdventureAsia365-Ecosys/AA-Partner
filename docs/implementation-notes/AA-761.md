# AA-761 — Portal Account pages with real data (portal part)

Billing, Activity and Integrations of the tenant portal (`portal/`, moved here by AA-979 P2a), on the UI kit inside
PortalShell. The CIS read endpoints are on AA-CIS-App branch `feat/aa-761-account-endpoints` (its own
`docs/implementation-notes/AA-761.md`).

## Decisions

- **Billing** (`_components/PlaceholderTabs.tsx` `BillingTab`):
  - plan card unchanged (plan, price, quotas, rate limit, Change plan by mail);
  - new rewrite meter (`UsageMeterCard`): used / quota and the reset date from `GET /v1/quota` (the counter the
    rewrite route charges), the overage so far and the per-rewrite rate from `GET /v1/billing`; states no plan /
    unlimited / ok / near (≥ 80 %) / over, computed by `usageMeter()` in `portal/lib/account.ts`;
  - "This period" keeps API calls and the amount due so far (the rewrites tile moved into the meter);
  - **Invoices**: CIS stores no AA-issued invoices (no table; the billing provider decision is open), so the card is
    the kit empty state with a mail link for a copy of an earlier invoice. When CIS stores invoices, the list goes
    here.
- **Activity** (`_components/AccountActivity.tsx`): the tenant's own trail from CIS `GET /v1/account/activity`
  (sign-ins, Slate picks, writing, publishing, tour rewrites and downloads, account changes by AA). Kit DataTable
  with `serverPagination` (the API pages and counts), filters by type and by date (UTC days, both inclusive; a
  half-typed date is not sent, reversed dates are swapped), "Clear", and **Export CSV** of the whole filtered set
  from `GET /v1/account/activity/export` (the kit's own CSV button exports only the loaded page, so it is off;
  search is off for the same reason). It replaces the old Activity Log page, which showed the 5 newest rewrites
  from `/v1/billing`; the dashboard feed and the bell still use that list.
- **Integrations** (`account/integrations/page.tsx`): each channel's health badge next to its title (the last
  test's result: Working / Needs attention / Not tested yet / Not connected) and the existing status card with
  "Test connection", "Change credentials" and Disconnect; new **API key** section (`_components/ApiKeyCard.tsx`):
  masked `cis_` key, issue date, last used, last API call, and "Request a new key" (mail to AA; self-serve rotate
  comes with the identity work).
- **"Moves here from Publish"**: the Publish page keeps the inline connect form for a channel that is not
  connected yet (AA-456 Option 3+2, the first connect), but a connected channel now shows a one-line
  `ConnectionSummary` (target, health, "Manage" / "Check connection" → Integrations). Testing and changing a
  connection happen only on Integrations.
- **Kit**: the Billing / Settings contact dialog moved onto the kit `Modal` (it was a hand-rolled dialog, the AA-732
  lint warning). Tables, badges, empty states and the modal come from `app/_kit`; cards and headers stay the
  portal's `ui.tsx` ones, like the other portal pages.
- **Pure helpers + tests**: `portal/lib/account.ts` (meter, filters, query string, file name, health, labels) is
  dependency-free and tested by `portal/lib/account.test.ts` with `node --test --experimental-strip-types`
  (`npm test`, new step "Unit tests (node --test)" in the Portal Build job). `lib/**/*.test.ts` is excluded from
  the portal tsconfig (the test imports `./account.ts` with its extension, which Node needs and tsc refuses).

## Tradeoffs

- Offset paging (page numbers + total) instead of keyset "load older": the kit pager needs a total, and a tenant's
  trail is small.
- Times in the table are in the browser's time zone, the date filters in UTC days (the API's contract); the page
  says so under the table.
- The Facebook summary on Publish shows "Page <id>" as the status card always did (CIS keeps no Page name).

## S251 review follow-up

- The CIS API now refuses activity dates outside 2000-01-01 .. 2100-12-31 with a 400 (before, `until=9999-12-31`
  was a 500). The portal mirrors that window: `ACTIVITY_DATE_MIN/MAX` in `portal/lib/account.ts`,
  `cleanFilters()` drops a date outside it (a year still being typed, such as 0002-10-01, never reaches the API),
  and both date inputs carry min/max. Re-run: `npm test` 5 pass (the filter test has two new assertions),
  `npx tsc --noEmit -p .` clean, eslint on the touched files 0 problems.
