# AA-964 — CRM-33a AI gateway + drafts + guardrails (slice B3 of the S262 gateway plan)

Two PRs in this repo, in MIG-4 order (crm-032 is a contract file):

1. `feat/s262-aa964-crm-032-llm-call-v2`: migration only (`api/migrations/032_crm_llm_call_v2.sql`, its integration
   test, the CONTEXT.md table row). Merge, let the Migration Sync bot copy it to AA-CIS-Infra, run DB Migrate `apply`,
   merge the `bot/db-schema-reference` PR.
2. `feat/s262-aa964-crm-ai-gateway`: the code (adds `crm-032` to `REQUIRED_SCHEMA_VERSIONS`), merged only after (1) is
   applied on Dev.

## Decisions

- **crm-032 is contract, not expand.** It replaces `llm_call_role_chk`, adds CHECKs on existing tables and adds
  columns to a ledger (a hot table in Infra `owners.yaml`). ADR 0017 d3 makes each of those contract, so no
  `-- migrate: expand` header and the code ships in a second PR.
- **Column names follow CIS 319** (`attempt_no`, `request_id`, `connection_key`, `deployment_wire_id`,
  `cache_read_tokens`, `cache_write_tokens`, `units`, `unit_kind`, `pricing_mode` with the same regex,
  `prompt_hash`, `prompt_version`, `is_shadow`, `is_experiment`), so the CIS Calls tab maps both ledgers with one
  column list. `outcome` stays the CRM's name for the CIS `status` (ok / refused / error); `crm.ops.v1 /llm/calls`
  serves it as `status`.
- **`app` is NOT NULL DEFAULT 'crm' with CHECK = 'crm'.** The CRM only writes its own rows; the default keeps every
  existing row and the pre-AA-964 INSERT valid.
- **`is_shadow` / `is_experiment` are NOT NULL DEFAULT false** (CIS has them nullable because it has years of rows
  without them; the CRM table holds a few rows and nothing ever wrote a shadow call).
- **`units` + `unit_kind` added** (not in the plan's column list, but the plan says the guard row records "units"):
  the guardrail bills text units (1 unit = up to 1000 characters), not tokens. Both or neither.
- **Budget alert state in `crm.tenant_settings`** (`ai_alert_month`, `ai_alert_pct`): the 75 / 90 / 100 % alert of R5
  must fire once per month and level, so the gateway needs to remember the highest level raised this month. A
  `crm.metric_event` (the bell) cannot hold it: that table needs a `trip_id`.
- No new index: `/llm/calls` reads per agency through `llm_call_tenant_at_idx (tenant_id, at DESC)`.

## Changed (vs. the plan text)

- Added `units` / `unit_kind` and the two `tenant_settings` columns (see Decisions).
- `reasoning_tokens` and `effort` (CIS 319) are left out: Bedrock Haiku drafts report neither today; a later key
  adds them if a model needs them.

## Tradeoffs

- Re-adding the CHECKs with `DROP CONSTRAINT IF EXISTS` + `ADD CONSTRAINT` (validated at once) keeps the file
  re-runnable without DO blocks; fine because `crm.llm_call` is tiny (180-day retention, a handful of rows on Dev).

## Should know

- Apply order: crm-032 on Dev **before** the code PR deploys: the new gateway INSERT names the new columns and writes

- `python3 <Infra>/db/run_migration.py --inspect api/migrations/032_crm_llm_call_v2.sql` is clean (Infra `main`).
