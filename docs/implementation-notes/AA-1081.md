# AA-1081 — Articles page: why a tour has no article topic (Partner web part)

The CIS part (AA-CIS-App `docs/implementation-notes/AA-1081.md`) makes the T7 Slate give every adopted tour a Blog
topic when it has a free candidate, and records a typed reason per tour that has none. `GET /v1/slate` returns it as
`blog_topics` (`{tours: [{tour_id, tour_name, topics, reason}], total, with_topic}`; null before the first topic update
that computed it).

## Decisions

- **Where**: under the Blog channel panel of the topic list (`SlateTab`, so the Articles page `/portal/create/article`;
  the Social Posts page never shows the Blog tab). A note, not a modal: "N of your M tours have no article topic yet",
  one line per tour (catalog name — reason), the first 5 rows then "Show all N".
- **Copy**: one message per reason code in `BLOG_TOPICS_MESSAGES` (`writer.messages.ts`, EN + VI). Agency words only:
  no "bar", score, Debate, gate or seed (a test checks the EN and VI strings). The `seed_too_thin` line says the tour
  description is too short for a full article (about 900 words) and that its stops are offered as shorter posts.
- **Unknown codes**: `lib/studio/blogTopics.ts` keeps only the codes of the CIS contract (`NO_TOPIC_REASONS`); anything
  else reads "No article topic yet." so a new CIS code never shows a raw identifier.
- **No new request**: the note reads the same cached `GET /v1/slate` answer as the topic list (react-query key
  `tenant-slate`).

## Changed

- `web/lib/studio/blogTopics.ts` (new): codes, types, `toursWithoutTopic()`.
- `web/app/(studio)/portal/_components/BlogTopicsNote.tsx` (new): the note.
- `SlateTab.tsx`: `blog_topics` in the response type; the note under the Blog panel.
- `writer.messages.ts`: `BLOG_TOPICS_MESSAGES`.
- Tests: `web/tests/studio/blogTopics.test.ts`, `web/tests/studio/blogTopicsNote.test.ts`.

## Tradeoffs

- The note reflects the last topic update, not live picks: a tour whose only topic the agency skipped shows its reason
  after the next update. The CIS proposal runs when the list is older than a day or on "Update topics".
- Kept as a plain list in the panel rather than a per-tour filter: the Articles page has no tour filter yet (portal UI
  item 3 of the AA-741 phase 3 audit belongs to the writer panel issue).

## Should know

- Needs the CIS change deployed first (`blog_topics` in `GET /v1/slate`); before that the field is absent and the note
  shows nothing.
