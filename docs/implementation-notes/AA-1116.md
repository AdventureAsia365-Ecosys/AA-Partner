# AA-1116 — option B in AA-Partner: studio money in the agency currency, CRM member limits as settings (slice S9)

The CIS part (migrations 435-439, contract tenant.entitlements.v1 1.9) is live on Dev: `GET /v1/billing` returns
`billing_currency`, per plan `currency` + `price_monthly`, and `quote`. This slice reads them in the Content studio and
moves the CRM member limit literals into the CRM settings registry (crm-075).

## Decisions

- **Money follows the currency, not the UI language** (`web/lib/studio/billingMoney.ts`): VND whole with `₫` and dot
  thousands ("3.790.000 ₫"), USD with `$` ("$149", "$19.50" with cents). The kit `formatMoney` ("1,845.00 USD") stays
  the CRM's finance format; the studio plan card keeps the price-list look the agency signs.
- **Amount due = the CIS quote** (`quote.monthly_total`: every product, the seat minimum, an agreed price, the founding /
  combo discount, a free pilot) plus the rewrite overage. The overage is USD (the per-tour overage rate is a USD price):
  same currency adds up; a VND agency sees the VND total and "Plus $X overage, billed in USD" (no FX conversion here).
- **Older CIS** (no 438 fields): every amount falls back to the USD fields, as before.
- **Member limits as settings** (crm-075): `crm.members.default_limit` (3, option B seat minimum) and
  `crm.members.max_limit` (500), area `members`, platform scope (the seats per agency come from CIS `crm.seats`, so no
  per-agency value), maker-checker, enforced, guides EN + VI. Read at the time of use (`team.default_member_limit()`,
  `team.max_member_limit()`); the default never exceeds the ceiling. The ceiling's own bound is 500, the
  `tenant_entitlement_limit_chk` CHECK of crm-008 (a higher setting would fail the write).
- **The 008 column default 10 goes** (`ALTER COLUMN member_limit DROP DEFAULT`, in crm-075): the L1 console's two
  upserts that could create the first entitlement row now name `member_limit` (the default setting), the feed always
  did. Kept in the same file as the seed (crm-074 pattern: the file ships in the code PR).

## Changed

- `api/app/cis/entitlement_feed.py`: `MEMBER_LIMIT_MAX` / `DEFAULT_MEMBER_LIMIT` removed (settings lint baseline shrinks
  by two); `api/app/members/team.py`: `DEFAULT_PLAN` → `default_plan()`; `api/app/ops/console.py`: inserts name
  `member_limit`, the no-row entitlements answer the default setting.
- `web`: Billing tab (`PlaceholderTabs.tsx`), Dashboard (`DashboardTab.tsx`), the `perMonth` / `includesOverage` /
  `overage` messages take a formatted amount (no `$` in the copy), new `plusOverage`.
- Tests: `tests/unit/test_aa1116_member_limits.py`, `web/tests/studio/billingMoney.test.ts`; the integration inserts
  into `crm.tenant_entitlement` name `member_limit` (crm008, crm011, aa963 search).

## Tradeoffs

- The studio does not convert the USD overage into VND: CIS has a reference FX setting but invoices never use it; an
  agency reads the two amounts apart rather than a converted figure that is not what it is billed.
- `crm.members.default_limit` has no per-agency value: an agency's own seats are sold on CIS Tenant 360.
