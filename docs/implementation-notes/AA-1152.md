# AA-1152 — optional activities per day, rounded agency prices (AA-Partner part)

Slice L9 of the root `docs/audits/2026-11-19-S285-session/advisory-r2-plan.md` (Jira PR-29 T6 and B2 option C). The
TripPlanner day cards and price display, the Booking `GET /add-ons` read and the root contracts ship in their own PRs
of the same wave.

## Decisions

- **One price function** (`app/proposals/rounding.py`): `from_price` (B2B x (1 + markup), else RRP, then rules, one
  round up) for the drawer and the planner prices; `suggested_total` (round per traveller, then x party) at the end of
  the builder's `_suggestion` (after the agency's price rules), so every suggestion in the CRM is rounded once.
- **Rounding is always up** (never costs margin). The agency's choice per currency (crm-086 column), the platform
  default and the choice list are settings (crm-087), not literals: tech lead S279 "thresholds are settings".
- **crm-086 / crm-087 split**: the ALTER is a migration-only PR (MIG-4); the two setting rows ship with their readers in
  the code PR like crm-084 (a settings row needs its reader, guide and compiled default in the same PR; the readers
  serve the compiled defaults until it is applied). The code reads the columns fail soft (`UndefinedColumn` = defaults,
  a save answers 422 `planner_prices_not_ready`), so readiness does not wait for crm-086.
- **An add-on hangs on an AA tour of the trip**: `crm.option` requires `aa_tour_source_id` for an AA option (CHECK, and
  booking lines, refreshes and parity read it). Rather than widen that CHECK in this slice, the add-on takes the AA
  tour of the same day, else the proposal's first one; a proposal without an AA tour gets 409 `aa_addon_needs_tour`.
- **AA's name, never the browser's**: the add route reads the add-on list from Booking again for that day and party
  and uses Booking's title; its RRP becomes the option's "from" price so `retail.suggest` can fall back to it (an RRP
  fallback is no longer tour-only).
- **Planner prices are pushed** (`crm_tp_price_publish`), not read by TripPlanner: no AA app reads `crm` (root ADR
  0008a). Hourly sweep plus one row per owner change; TripPlanner only shows what it was given.
- **Matching an add-on to a day**: the CRM day has a free-text place, no CIS id; the drawer lists the day's add-ons and
  marks the ones whose CIS place name and the day's place contain each other ("At this day's place", sorted first).

- **Review fixes (S289):**
  - *Refresh keeps an add-on's RRP*: "Refresh AA prices" re-quotes with `aa_options.quote`, which gives a "from"
    price for a tour only. `aa_addons.refresh_rrp` now reads AA's add-on list again (one call per day and party) and
    puts the add-on's current RRP on the answer, else the stored `aa_from_price` (the refresh plan carries it) when
    Booking fails or no longer lists it. A tour's "from" price still comes from price parity only.
  - *Rounding per paying traveller*: the suggestion is rounded up per traveller who pays a share of the per-traveller
    grid (adults + children by the agency's bands; an infant starts at 0 in `pricing.grid`), then times them
    (`_retail_ctx` puts `payers` = `pricing.payers(pricing.row_counts(row, bands))` in the pricing context;
    `rounding.for_party`), in the view, `use_suggested` (sell and grid) and the AA add. The
    total is still AA's RRP x party (infants counted, AA's rule); only the rounding head count changed, so the grid's
    price per traveller is on the step (2 adults + 1 infant, VND: 530,000 each, not 525,000).
  - *Never an out-of-date planner price*: an agency no longer routed here, refused by Booking (`unknown_partner` /
    `forbidden`) or whose CRM is locked or deleted gets an empty hidden list (`show_prices` false), once per worker
    process (`PricePublish._hidden`; a publish clears the mark); `unknown_tenant` (no planner) is marked too, so the
    hourly sweep does not call TripPlanner again. TripPlanner also hides a list older than its setting
    `tripplanner.prices.agency_stale_hours` (CIS 476) for a CRM that cannot publish at all.

## Changed

- `retail.suggest`: the RRP fallback applies to any AA option with a "from" price (only tours had one before).
- Builder suggestions are now rounded to the agency step (USD 1 by default): `test_builder_service.py` 165.00 -> 166.00.

## Tradeoffs

- The tour "from" price uses the lowest per-person price of the agency tariff bands that hold 2 travellers (no date):
  the page says "from"; the quote is final.
- The "already hidden" mark lives in the worker process (no column): a restart sends one more hidden list per
  unrouted agency, which TripPlanner stores as the same empty list; a durable flag would need a crm migration.
- The hourly sweep calls Booking's tariff for every agency with a planner: bounded by the existing tariff reader limits
  in Booking; acceptable at today's agency count. A per-agency change detection can come later.
- Standalone add-ons (a proposal with no AA tour) are refused for now; widening `crm.option` is a follow-up if agencies
  need it.
