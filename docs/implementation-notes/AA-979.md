# AA-979 — CRM-P2a: the tenant portal moves into AA-Partner

AA-Partner part of AA-979 stage P2a (root ADR 0010 §6): the Content studio (`portal/`) moves from AA-CIS-App into
this repo with its history, keeps the same Vercel project (`aa-cis-portal`, host `portal.lumiguides.it.com`) and the
same tenant API-key sign-in through the BFF. P2b (CloudFront to Fargate, partner pool, re-enrol by invitation, 301
for `/trip/*`) and the deletion of the CIS copy (P2b + 7 days) come later. Session S250, agent Claude Code.

Two Partner PRs:

1. `feat/aa-979-p2a-portal-import` (P2a-1): only the imported history, `portal/**`, nothing else. Rebase merge.
2. `feat/aa-979-p2a-portal-wiring` (P2a-2, this file): CI, the Vercel deploy and smoke workflows, guards, docs.
   Squash merge, after P2a-1.

## Decisions

- **History import with git filter-repo in a scratch clone.** Cut = AA-CIS-App `d1e0eb43` (main after #980; #981,
  the last portal change, is in it). Kept paths: `portal/` plus the 7 pre-split sources of the 67 renames in the
  split commit `a70cf53d` (#832): `frontend/app/(tenant)/portal/`, `frontend/app/tenant-login/`, and
  `frontend/app/api/{auth/tenant-login,auth/tenant-logout,playground/proxy,tenant/me}/`, renamed to their
  `portal/app/...` targets so `git log --follow` crosses the split. Result: 154 commits (2 merges), then
  `git rebase --onto origin/main --root` drops the 2 merge commits (Partner requires linear history): 152 commits.
- **Gates passed before the branch was written** (all on the rebased branch):
  - `git rev-parse HEAD:portal` = `ba736844f356f5d13aa40e4fc378c460e5efbfb7` = CIS `d1e0eb43:portal` (118 files);
  - no change outside `portal/` against Partner main;
  - `git log --follow portal/app/portal/_components/Sidebar.tsx` reaches the pre-split commits (19 commits, back
    to "feat(portal): rebuild tenant portal UI");
  - gitleaks v8.30.1 with Partner `.gitleaks.toml` + `.gitleaksignore`: PR range (151 commits with a diff), the
    squash preview and the full local history, 0 findings each;
  - `.github/scripts/check_resource_ids.py`: 514 files, 0 findings.
- **The one known gitleaks hit is rewritten, not pinned.** CIS `.gitleaksignore` pins the fake `api_key` literal of
  the old `MOCK_TENANT` sample (commit `c5c35a55`, `frontend/app/(tenant)/portal/page.tsx` line 7). The import
  replaces that literal with `***REMOVED***` (`--replace-text`), because a rebase merge writes new SHAs and a pinned
  fingerprint would not match them. It was never a real key (a hard-coded UI mock).
- **Commit messages.** A commit callback rewrites every bare `#NNN` to `AdventureAsia365-Ecosys/AA-CIS-App#NNN`, so the
  links do not point at unrelated Partner PRs, and appends the trailer
  `Imported-from: AdventureAsia365-Ecosys/AA-CIS-App@<original sha>`. No message carries a Linear closing keyword
  (checked: 0 hits for close/fix/resolve/complete + key), so the merge cannot auto-close an issue.
- **Release notes.** The P2a-1 PR body carries a release-please `BEGIN_COMMIT_OVERRIDE` block
  (`chore: import the AA-CIS-App portal history`), so the ~100 imported feat/fix subjects do not land in the Partner
  CHANGELOG or bump the version.
- **Same Vercel project, new deployer.** `aa-cis-portal` keeps Root Directory `portal`, `sourceFilesOutsideRootDirectory`
  true, no Git link and Git deployments off (`portal/vercel.json`), so Vercel needs no change: what moves is the
  repo variable (project id) and the secrets (token, bypass, tenant test key). The deploy workflow is a port of the
  CIS one with Partner's pinned action versions.
- **Smoke helpers are trimmed, not copied.** CIS `tests/e2e/smoke/smoke-helpers.ts` imports the admin `lib/rbac.ts`
  and carries admin-only checks (sidebar width, dark-theme luminance on `.aa-admin-main`). `e2e/smoke-portal/smoke-helpers.ts`
  keeps only what the portal specs import (base URL, origin-scoped bypass route, page watcher, content check, page
  check), with the same code. Paths are relative to `e2e/` (`results/smoke-portal`, `.auth/`).
- **Guards ported into `api/tests/unit/test_portal_guards.py`** (portal side only of CIS test_aa885, aa886, aa760
  muted contrast and metering, aa820, aa911 and the login cross-link test). The vendored byte checks move to
  `scripts/check_vendored_copies.py` (`PORTAL_COPIES`), like the web's.
- **Package renamed** `aa-cis-portal` -> `aa-partner-portal`, version 0.3.0 (the repo version), and added to
  release-please `extra-files`.

## Tradeoffs

- Rebase merge (new SHAs, history kept) vs squash (one commit, history lost): rebase, per ADR 0010 §6. Needs a
  repo-setting toggle by the admin login (see "Should know").
- Trimmed helpers diverge from CIS; acceptable because the CIS portal smoke is deleted in P2a-3 and Partner owns the
  portal smoke from now on.

## Should know

- **P2a-1 merge is a settings change.** AA-Partner allows squash only (`allow_rebase_merge=false`) and requires
  linear history. The orchestrator, with Nghiệp's admin `gh` login (not `aa-agent`, ADR 0011), sets
  `allow_rebase_merge=true`, runs `gh pr merge <n> --rebase`, and sets it back to false at once. Fallback when GitHub
  refuses: admin fast-forward of main to the green PR head (`enforce_admins` is off). Record which one was used here.
- **The Partner deploy needs four repo values before P2a-2 is opened**: variable `VERCEL_PORTAL_PROJECT_ID`, secrets
  `VERCEL_TOKEN` (new, team scoped), `VERCEL_PORTAL_BYPASS_SECRET`, `E2E_TENANT_API_KEY`. Without them the deploy job
  fails red on purpose.
- **Only one deployer at a time.** P2a-3 (CIS: delete the portal deploy workflows, freeze `portal/`) merges only after
  the Partner production deploy is verified live.
- The `api/scripts` change triggers a no-op Partner API rollout (deploy-dev watches `api/**`); it is gated by
  `crm.job`, not by the CIS wave.
- Sign-in is unchanged: the portal BFF still calls CIS `/auth/tenant-login` with `client: "portal"`; business logic
  stays in the CIS API (ADR 0010 §7).
