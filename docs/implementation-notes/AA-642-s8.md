# AA-642 S8 — the shared AI gateway core vendored into AA-Partner (root ADR 0009 decision 13)

The canonical notes are in AA-CIS-App `docs/implementation-notes/AA-642-s8.md`; this file covers AA-Partner only.

## Decisions

- **Code only.** `api/app/aa_llm/` is a byte copy of AA-CIS-App `shared/aa_llm/` with `api/aa_llm.lock.json`. The CRM
  keeps `app/llm/gateway.py`, `crm.tenant_settings` and `crm.llm_call` (root ADR 0008a §5–6); nothing in `app/` uses
  the copy yet. Moving the CRM gateway onto the core's error classes and budget decision is a later slice.
- **Integrity test, not the live compare.** `tests/unit/test_aa_llm_copy.py` (offline, part of the required unit
  tests) checks the copy against its manifest and the lock. The existing "Vendored CIS copies" job compares other
  files with CIS `main` and stays as it is; the core is pinned to the lock commit instead, so a CIS merge never turns
  this repo red.
- **Lint.** The core is ruff-formatted with this repo's config in CIS, so no `extend-exclude` entry was needed.
  Coverage omits `app/aa_llm/*` (tested in CIS), like `identity_verifier.py`.

## Should know

- Never edit `app/aa_llm/`. A CIS change reaches this repo as the bot PR `bot/llm-core-sync`, or by hand with the
  root `tools/llm-core/llm-core-sync.sh crm`.
- The guard test also fails if a module here calls the core's `insert_sql()` or names the CIS contract views.
