# AA-1036 — R3 one agency app (slice 1: merge `portal/` into `web/`)

Root ADR 0019 d6 (one agency app, one sign-in, no tenant API keys) and d7 (one invitation; a tenant lands on Content;
add-ons open per entitlement or after a request). Clarifications TL-6 / TL-7 (S265). Takes over the AA-1007 leftovers
that fall in the moved code.

## Decisions

- **Copy, not move, in slice 1.** The studio code is copied into `web/` and `portal/` stays untouched with its CI and
  deploy, so Dev keeps serving `portal./portal*` from `aa-crm-dev-portal` until the cut-over (slice 2: the ALB rule
  `/portal*`, `/api/*`, `/tenant-login*`, `/terms`, `/privacy`, `/assets/*` -> the web target group, then the studio
  service, task definition, target group, ECR repository and log group are deleted, and `portal/` with its workflows).
- **Layout in `web/`:** `app/(studio)/portal/**` (same URLs `/portal/*`), `app/(studio)/portal-access/**`,
  `app/(studio)/legal/{partner-terms,privacy}`, `app/(studio)/_legal/`, the studio BFF at the same `/api/*` paths
  (`app/api/tenant/[...path]`, `tenant/me`, `auth/tenant-logout`, `auth/tenant-select`, `playground/proxy`,
  `healthz`, new `studio/apps`), the shell under `app/_kit/local/studio/`, helpers under `lib/studio/`, tests under
  `tests/studio/` (converted from `node --test` to vitest).
- **One session.** The studio reads this app's own sealed session (`lib/session.ts`); the byte copies of
  `session.ts` / `seal.ts` (and of `sameOrigin`, `crossSiteGuard`, `bffPath`, `proxyResponse`, `upstreamHeaders`,
  identical in `web/lib/`) are not carried over. The CIS tenant-session exchange stays a server-side call
  (`lib/studio/studioSession.ts` `exchange`), now in `proxy.ts` (`studioGate`) and `lib/studio/auth-server.ts`
  (`requireStudio`). CIS is `CIS_API_URL` (already set for the trip page); no CIS host constant (public repo).
- **No API-key session.** A studio token without `amr=partner` is never used; `/tenant-login*` answers 308 to
  `/auth/refresh?next=/portal/dashboard`; the API-key sign-in page and its BFF are not carried over;
  `PORTAL_API_KEY_SIGNIN` does not exist in the merged app.
- **Proxy order** host -> `/staff` -> `/c` -> studio (`/tenant-login`, "/" landing, `/api/*` through, legal public,
  `/portal*` needs the session and then the exchange step) -> CRM. The exchange step runs in `proxy()` after the
  synchronous `gate()` let a `/portal*` page through (the same post-step pattern as the inquiry form's CSP).
- **Legal pages:** the CRM already owns `/legal/terms` (AA-1033), so the studio's draft terms are
  `/legal/partner-terms` and its privacy notice `/legal/privacy` (public, outside the gate). `/terms` and `/privacy`
  answer 308 (`next.config.ts`, kept in step with `lib/studio/legal.ts` by a test). The old slug 308s moved too.
- **Content is home (d7) behind a switch.** `WEB_CONTENT_HOME=true` makes "/" a 307 to `/portal/dashboard`; the CRM
  home also lives at `/home` (the sidebar links it). Off by default, because until the cut-over the separate studio's
  "Open CRM" links "/", which would bounce back to the studio.
- **App switcher.** `lib/apps.ts`: Content (current / link), CRM (open when the tenant holds the add-on, else
  "Request add-on"), Trip planner (always "Request add-on": no `tp.*` entitlement reaches this app). The CRM state
  comes from `GET /crm/v1/me` for the studio's tenant (from its httpOnly `cis_tenant_id` cookie), which now answers
  `crm_entitled` (API: `app.entitlements.crm_entitled`, false only for a projected row on plan `free`). "Request
  add-on" is a `mailto:` to the AA support address with the add-on and agency in subject/body (no request endpoint
  exists yet). Studio: `GET /api/studio/apps` (always 200) feeds the sidebar "Apps" group; CRM: the "Content studio"
  group became "Apps" (studio link + Trip planner request).
- **AI pause banner:** the app-wide AI switch (`crm.llm_app_profile.ai_enabled`) is readable only on `/crm/ops/v1`;
  no `/crm/v1` route exposes it, so the banner is a follow-up (task: "if the signal already exists in the CRM API").
- **Own e-mail (AA-1007 leftover):** the id token's `email` (same client, same `sub`) is kept in the sealed session
  (`em`), kept across refreshes, and `/bff/identity` adds it to its answer; the studio says "Signed in to AA Partner as
  <email> (<Role> of <agency>)". The e-mail is never taken from an API answer.
- **Styles:** `app/(studio)/studio.css` = the studio's globals with Tailwind 4 `source(none)` (preflight only, no
  utility generated; the studio uses none), loaded only by `app/(studio)/layout.tsx`. Links between the studio and
  the CRM are plain `<a>` so the studio stylesheet never stays on a CRM page. The sidebar-rail restore script moved to
  the root layout head.
- **Sentry:** `instrumentation*.ts` moved to `web/` (whole app), inert until a DSN is mapped (slice 2).

## Changed (vs. the Linear scope)

- Slice 1 only: no Infra change, no deletion of `portal/` or the studio service, no CIS key removal (slice 3).
- `/api/healthz` in the merged app answers `{ok, service: "aa-crm-web", studio: "merged", version, sha}`; the
  `crm-portal.rows` verify row still expects `aa-partner-portal` until slice 2 switches the rows.
- The CRM home moved to `/home` (with "/" still serving it while `WEB_CONTENT_HOME` is off).

## Tradeoffs

- Kit-lint suppressions: the moved files keep their studio violations (no growth); the web suppressions grow by
  exactly the studio's entries under their new paths. The kit core's built-in `LEGACY_MODULES` knows only
  `app/portal/_components/ui`, and `isModule()` matches an exact path or a "/"-suffix, so after the move
  `aa-kit/no-legacy-kit` no longer saw the studio's imports of its legacy `ui.tsx` (first build of this slice dropped
  the 39 frozen uses instead of carrying them; caught in review). `web/eslint.config.mjs` now passes the rule
  `modules: [...LEGACY_MODULES, app/(studio)/portal/_components/ui]` (core untouched), and the 39 imports are frozen
  under their new paths (`eslint --suppress-rule aa-kit/no-legacy-kit`; counts equal the base portal file's, file by
  file); a new studio import of `ui.tsx` fails lint. Follow-up: add the moved path to `LEGACY_MODULES` in the CIS
  canonical kit and sync, then drop the local override. CI's growth check gets the base studio
  entries mapped to the new paths (`.github/scripts/studio_suppressions_base.py`), so a moved file may keep, never grow,
  its count. Reaching 0 stays an R3 follow-up (AA-1007 Done-when).
- Tailwind added to `web/` only for the studio preflight, instead of hand-copying a reset (risk of visual drift).
- `mailto:` for "Request add-on" instead of a request API: no backend exists yet; a real request flow is a follow-up.

## Should know

- Until the cut-over, the merged studio is reachable only where the ALB sends `/portal*` to the web (local, CI, or
  after slice 2). On Dev after this deploy: `/legal/partner-terms`, `/legal/privacy` and `/home` are served by the web;
  `/portal*`, `/api/*`, `/terms`, `/privacy` still by the studio service.
- Env names introduced: `WEB_CONTENT_HOME` (slice 2 sets it with the ALB switch). Sentry for the web needs
  `SENTRY_DSN` (task) and the `NEXT_PUBLIC_SENTRY_DSN` build arg (deploy workflow) in slice 2.
- `api/tests/unit/test_studio_guards.py` carries the studio guards of `test_portal_guards.py` over to the merged app.
