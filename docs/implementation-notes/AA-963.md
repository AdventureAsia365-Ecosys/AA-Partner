# AA-963 — CRM-32 global search (R35) and the library page (R9)

S282 lane l2-search (Claude Code). Design: root `docs/audits/2026-10-21-S246-crm-design-v3/design-v3.md` §2.3 (A-00
"Search (Ctrl/Cmd+K)"), §4.2 (blind indexes, "search (R35, exact only)"), §6.3 card CRM-32; the final design §3.2
"Global shell". Linear scope updated S279: global search in the one agency app over Content pieces and the CRM records
the member is entitled to; the library itself is live (message templates, AA workflows, inclusions), this card only
adds CIS Content pieces to the picker if missing.

## Decisions

- **Off by default, per agency.** The switch is the admin-editable setting `crm.search.enabled` (crm-071, bool,
  scope `platform+tenant`, default off, maker-checker): an administrator turns it on for one synthetic agency on CIS
  Platform > Settings (CRM tab) after the independent review, never for the pilot before it. It is not an entitlement
  key of `tenant.entitlements.v1` (that would need a CIS key, a crm-008 CHECK change and the feed): the search is part
  of the CRM itself, not a paid add-on; what a member sees inside it is decided by feature keys and the role matrix.
- **Three match rules, by the class of the field** (design §2.3: "blind index, exact only; accent-insensitive on
  non-PII fields"):
  1. **F1 identity fields** (the client's e-mail, phone, name: encrypted, `pii:contact` / `pii:name`) only through
     their blind indexes (`traveler.email_bidx`, `phone_bidx`, `name_token_bidx`): a full e-mail, a full international
     phone, or whole name tokens (the directory's own rule, confirmed after decrypting the display name). Never a
     prefix, a substring or a fragment.
  2. **Plaintext fields tagged `pii:` but not identity** (`trip.title`, `pii:travel`): whole words only, accent- and
     case-insensitive ("Da Lat" finds "Đà Lạt honeymoon", "Lat" alone does not). No index is added.
  3. **Fields with no personal data** (supplier and service names, template titles, workflow names, inclusion lines,
     tag names, booking references): accent- and case-insensitive substring; booking references (AA booking code,
     hold id, supplier confirmation number) and the group code exact, case-insensitive.
- **Partial F1 search is refused, not degraded**: a query with `@` that is not a whole e-mail, or one that starts with
  `+` and is not a valid phone number, answers 422 `partial_contact_search`; `*` or `%` answers 422
  `partial_search_refused`. A run of digits without `+` is never tried as a phone (it may be a confirmation number):
  it searches the references and text only.
- **Accent folding happens in SQL on both sides** (one expression, `app.search.fold.fold_sql`: NFKD, combining marks
  removed, `đ/Đ ø/Ø ł/Ł` -> `d o l`, `ß` -> `ss`, lower-cased), so the query and the column always fold the same way.
  The Python `fold()` mirrors it for the web tests and the Content pieces filter (`web/lib/search.ts` `foldText`).
- **Entitlements**: each result kind names the role-matrix action of the page its results open (`TRIP_VIEW`,
  `CLIENT_VIEW`, `PIPELINE_VIEW`, `TAG_APPLY`) and, where one applies, the CRM feature key (`whatsapp_sms` for the
  approved WhatsApp templates). A kind the member's role is denied, or whose feature key the agency does not hold, is
  not searched at all (no query runs). Content pieces show only when CIS lists the agency among the person's studios
  (the layout's existing studio check) and the studio token's tenant is the CRM agency.
- **Content pieces are searched in the web**, not the CRM API: the CRM holds no CIS content and has no CIS scope for
  it. The palette reads the person's pieces through the existing studio BFF (`/api/tenant/v1/content-writing/reviews`,
  the same list the studio's own palette uses) and filters them with the same fold.
- **Library page**: `/library` was the generic empty section. It is now the picker of the four libraries: message
  templates, workflows, "Included / Not included" lines, and the Content studio's pieces (only for a person with
  studio access).

## Changed

- **API**: `app/search/` (`query.py` term classification, `fold.py` the accent fold, `kinds.py` the ten kinds and
  the entitlement filter, `service.py` the bounded queries), `app/routers/search.py` (`GET /search/config`,
  `POST /search`), four settings keys in `app.platform_settings` (+ `compiled_defaults.json`, `guides.json`), crm-071.
- **Web**: `components/search/SearchPalette.tsx`, `lib/search.ts`, `lib/searchContent.ts`, `lib/i18nSearch.ts`, the
  shell's search box (`app/_kit/local/CrmShell.tsx`: a button when search is on, a phone icon, the palette slot), the
  layout reads `search/config`, `app/(crm)/library/page.tsx` replaces the generic empty section (nav `empty` removed,
  the two `section.library.*` strings dropped), BFF allow-list (two routes), `e2e/visual/pages.ts` lists `/library`.
- The shell's "search arrives with the first client records" hint now says search is not switched on yet.
- Kinds not in the design list but useful and free of personal data: services, message templates, automations,
  proposal lines, tags, WhatsApp templates. Sales partners are left out (their names are encrypted `pii:contact`
  without a blind index), and so are notes and messages (`pii:free_text`).

## Tradeoffs

- **No search index.** Every plaintext comparison scans one agency's rows (FORCE RLS on `tenant_id`) with a bounded
  `LIMIT`; at Dev / pilot scale (hundreds of rows per agency) that is cheap, and an index on a folded `trip.title`
  would be a plaintext index of a `pii:` field, which the card forbids. A large agency would need an index on the
  non-personal names only (a follow-up if the database metrics ever show it).
- **Whole words for trip titles** instead of substring: a title often carries a family name, so a letter-by-letter
  probe is refused the same way an identity field is; agents type a whole word ("Da Lat", "honeymoon").
- **Digits without `+` are references, not phones**: a supplier's confirmation number is more often typed than a
  local phone number, and guessing a region for a local number would be a partial phone search by another name.
- **Content pieces in the browser**: one more CIS read per page (cached per page and agency) instead of a new CIS
  contract and scope for the CRM API; CIS already authorises the studio token, and the CRM holds no CIS content.
- **The switch is a setting, not an entitlement key**: a CIS key would need a CIS migration, the crm-008 CHECK and
  the feed for a feature that is not sold; the setting is per agency, audited and maker-checker.

## Should know

- **Independent review before enabling** (card, Linear S279): turn `crm.search.enabled` on only for a synthetic
  agency until then; the pilot stays off. Review points: `app/search/query.py` (what counts as partial),
  `app/search/service.py` (`CLIENT_SQL` reads blind indexes only; one `list_view` per search), the "no plaintext
  index" proof in `tests/integration/test_aa963_search_db.py`.
- crm-071 is **contract** (config rows) and ships in this code PR like crm-068 / crm-070 (MIG-4 deviation: the
  settings lint, guide lint and seed parity bind the seed, the readers and the compiled defaults). The code works
  before the apply: the compiled default keeps search off everywhere. No readiness raise.
- The term is never logged, echoed or put in a URL; refusals carry codes only.
- The SQL fold uses `normalize(..., NFKD)` (PostgreSQL 13+, UTF-8 database) and `regexp_replace` with `\u0300-\u036f`;
  `test_e_the_sql_fold_equals_the_python_fold` pins it against the Python mirror.
